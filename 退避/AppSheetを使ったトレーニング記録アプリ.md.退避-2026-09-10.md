今回の話の目的は、**Googleスプレッドシートで管理している筋トレ記録を、AppSheetからスマホ入力しやすくすること**でした。

特に最初の目的は、

> 有酸素運動ではなく、筋トレだけを対象にして、  
> 「記録日・種目・重量・回数・セット数・補足」をAppSheetから入力できるようにする。  
> さらに、同一種目について複数パターンを一括入力できるようにする。

というものでした。

最終的には、**個別入力フォーム**と**同一種目の一括入力フォーム**の両方が動くところまで実現できました。

---

# 1. 最初に確認した前提

最初のスプレッドシートには、すでに `トレーニング記録` シートがありました。

列としては、おおむね次のような構成でした。

```
記録日
種目
主対象
副対象1
副対象2
重量
回数
セット
総回数
総負荷
有酸素運動
補足
week
```

この時点で確認したのは、

> `トレーニング記録` は新しく作るのか？  
> それとも今あるシートを使うのか？

という点です。

結論としては、**今ある `トレーニング記録` をそのまま使う**ことにしました。

理由は、すでに筋トレ記録の保存先として必要な列がそろっており、スプレッドシート側でも集計や計算ができる状態だったからです。

ただし、AppSheetでは各行を一意に識別するためのキー列が必要なので、`トレーニング記録` の一番左に **ID列** を追加しました。

---

# 2. 種目マスタの扱い

次に確認したのが、`種目マスタ` です。

種目マスタはすでに存在していて、`トレーニング記録` のプルダウンにも使っていました。

画像で確認した種目マスタの構成は、だいたい次のような形でした。

```
種目ID
種目
タイプ
主対象
副対象1
副対象2
```

例としては、

```
leg_press        レッグプレス
adduction        アダクション
abduction        アブダクション
lat_pulldown     ラットプルダウン
bicep_curl       バイセップスカール
dips             ディップス
chest_press      チェストプレス
shoulder_press   ショルダープレス
bodyweight_sq    自重スクワット
stationary_bike  バイク
treadmill        トレッドミル
```

のような内容でした。

ここで確認したのは、

> 種目マスタにもID列は必要か？

という点です。

結論として、**種目マスタにもID列を作る方がよい**という判断になりました。

ただし、今回の初期実装では、`トレーニング記録` の `種目` 列には `種目ID` ではなく、これまで通り `チェストプレス` などの種目名を保存する形にしました。

つまり、いったんはこうです。

```
種目マスタ側：
種目ID = AppSheet内部管理用
種目 = 表示名

トレーニング記録側：
種目 = 種目名を直接保存
```

この方が、既存の過去データを壊しにくいためです。

---

# 3. AppSheetへテーブルを読み込む

次に、AppSheet側で次の2つのテーブルを読み込みました。

```
トレーニング記録
種目マスタ
```

その後、まず `種目マスタ` 側の設定を行いました。

`種目マスタ` では、

```
種目ID → Key
種目 → Label
```

にしました。

これにより、AppSheet内部では `種目ID` を使って行を識別しつつ、画面上では `チェストプレス` や `アダクション` のような種目名が表示される状態にしました。

次に、`トレーニング記録` 側のID列もKeyにしました。

ユーザー側ではすでに `1` から始まる数字のIDを入れていたため、それをそのまま利用しました。

`トレーニング記録` のID列は、

```
Type：Number
Key：ON
Show?：OFF
Editable?：OFF
Required?：ON
```

にし、新規追加時の自動IDとして、

```
MAX(トレーニング記録[ID]) + 1
```

を使う方針にしました。

---

# 4. 個別入力フォームを作った

最初に作ったのは、**1行ずつ入力する通常フォーム**です。

目的は、

```
記録日
種目
重量
回数
セット
補足
```

だけをスマホで入力し、`トレーニング記録` に1行追加することでした。

## 種目のプルダウン設定

`トレーニング記録` の `種目` 列は、AppSheet側で `Enum` にしました。

設定は次の通りです。

```
Type：Enum
Base type：Text
Allow other values：OFF
Required?：ON
```

`Valid If` には、種目マスタから筋トレ種目だけを取り出す式を入れました。

```
SORT(
  SELECT(
    種目マスタ[種目],
    [主対象] <> "心肺機能"
  )
)
```

この条件により、`主対象 = 心肺機能` の `バイク` や `トレッドミル` はプルダウンから除外され、筋トレ種目だけが表示されるようになりました。

## 重量・回数・セットの設定

次に、重量・回数・セットを設定しました。

最初は以下のようにしました。

```
重量：Number
回数：Number
セット：Number
```

セットには初期値 `1` を入れました。

その後、重量については将来的に5kg刻みの選択式にできるという話をしました。

その場合は、重量列を、

```
Type：Enum
Base type：Number
```

にして、`Valid If` に、

```
LIST(0, 5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55, 60, 65, 70, 75, 80)
```

のようなリストを入れればよい、という整理をしました。

---

# 5. 総回数・総負荷の計算でバッティングが起きた

途中で、`総回数` と `総負荷` にAppSheet側の `App formula` を入れようとしました。

式としては、

```
[回数] * [セット]
```

や、

```
[重量] * [回数] * [セット]
```

です。

しかし、ここでエラーが出ました。

原因は、

> スプレッドシート側にも数式がある  
> AppSheet側にもApp formulaがある  
> 同じ列に両方あるのでバッティングしている

というものでした。

この時点で、一般的にはどちらに計算式を置くべきかも整理しました。

今回の方針は、

```
AppSheet：入力画面
Googleスプレッドシート：保存先・計算・集計
```

です。

そのため、`総回数` と `総負荷` は **スプレッドシート側の数式を正とする**ことにしました。

AppSheet側では、`総回数` と `総負荷` の `App formula` を空欄にし、スプレッドシート側の計算に任せました。

これによりエラーは解消しました。

---

# 6. スプレッドシート側の入力規則との不一致が原因で同期エラーが起きた

個別入力フォームのテストでは、ほとんどの種目は問題なく登録できました。

しかし、`自重スクワット` だけ同期エラーが出ました。

エラー内容は、

```
Value '自重スクワット' in field '種目' cannot be converted to type 'Enum'.
```

でした。

最初はAppSheet側の `Enum` 設定や `Base type` を疑いましたが、設定は正しく、

```
Type：Enum
Base type：Text
Allow other values：OFF
Required?：ON
```

になっていました。

その後、全種目をテストしたところ、**自重スクワットだけが失敗する**ことが分かりました。

さらに、スプレッドシート側の過去データを確認した結果、`トレーニング記録` の `種目` 列のプルダウンに `自重スクワット` が入っていないことが判明しました。

つまり原因は、

```
AppSheet側のプルダウン：自重スクワットあり
スプレッドシート側の入力規則：自重スクワットなし
```

という不一致でした。

これにより、AppSheet側では選べても、Googleスプレッドシートに書き込む段階で拒否されていた、ということです。

この話から、

> AppSheet側でプルダウンを作るなら、スプレッドシート側にプルダウンは必須ではない。  
> ただし、スプレッドシート側にも入力規則があるなら、AppSheet側の候補と一致していないと同期エラーの原因になる。

という整理をしました。

---

# 7. 個別入力は完成した

ここまでで、個別入力については問題なく動くようになりました。

できるようになったことは、

```
AppSheetでフォームを開く
↓
記録日、種目、重量、回数、セット、補足を入力
↓
保存
↓
トレーニング記録に1行追加
↓
総回数・総負荷などはスプレッドシート側で計算
```

です。

この段階で、通常の筋トレ記録は問題なく入力できるようになりました。

---

# 8. 次に「同一種目の一括入力」を作った

次の目的は、

> チェストプレスなど同じ種目について、  
> 重量・回数・セット・補足の複数パターンを、1回のフォーム入力でまとめて登録したい

というものでした。

たとえば、

```
チェストプレス
15kg × 12回 × 1セット：ウォームアップ
25kg × 12回 × 1セット：準備
30kg × 12回 × 3セット：メイン
```

のような内容を、1回の入力フォームでまとめて入れることです。

ただし、保存先の `トレーニング記録` のフォーマットは変えないことにしました。

つまり、最終的には `トレーニング記録` に、

```
チェストプレス 15kg 12回 1セット
チェストプレス 25kg 12回 1セット
チェストプレス 30kg 12回 3セット
```

のように複数行として追加される形です。

---

# 9. 一括入力用シートを作った

そのために、スプレッドシートに新しく一括入力用のシートを作りました。

シート名は、

```
筋トレ一括入力
```

です。

列は次のような構成にしました。

```
一括ID
記録日
種目

重量1
回数1
セット1
補足1

重量2
回数2
セット2
補足2

重量3
回数3
セット3
補足3

重量4
回数4
セット4
補足4

重量5
回数5
セット5
補足5
```

これにより、最大5パターンまで同一種目を一括入力できるようにしました。

この `筋トレ一括入力` は、最終的な保存先ではなく、**入力フォーム用の一時テーブル**です。

最終的な記録は、従来通り `トレーニング記録` に入ります。

---

# 10. AppSheetに一括入力テーブルを読み込んだ

次に、AppSheet側で `筋トレ一括入力` をテーブルとして追加しました。

`一括ID` はKeyにしました。

設定は、

```
Type：Text
Key：ON
Label：OFF
Show?：OFF
Editable?：OFF
Required?：ON
Initial value：UNIQUEID()
```

です。

`記録日` は、

```
Type：Date
Required?：ON
Initial value：TODAY()
```

にしました。

`種目` は、通常入力と同じように `Enum` にして、

```
SORT(
  SELECT(
    種目マスタ[種目],
    [主対象] <> "心肺機能"
  )
)
```

で筋トレ種目だけを表示するようにしました。

---

# 11. 一括入力フォームを作った

AppSheetの `UX > Views` で、`筋トレ一括入力` 用のFormビューを作りました。

ここで一度混乱がありました。

最初、`View type` が `Deck` になっていたため、`Form Saved` が表示されませんでした。

`Deck` は一覧表示用のビューです。

今回必要だったのは、入力用のフォームなので、

```
View type：Form
For this data：筋トレ一括入力
```

にする必要がありました。

`View type` を `Form` にしたことで、フォーム保存時にアクションを実行する `Form Saved` が使えるようになりました。

---

# 12. 一括入力内容をトレーニング記録に追加するアクションを作った

次に、`Behavior > Actions` でアクションを作りました。

まずは1行目だけを対象にしました。

アクション名は、

```
一括入力_1行目を追加
```

です。

対象テーブルは、

```
For a record of this table：筋トレ一括入力
```

です。

処理内容は、

```
Data: add a new row to another table using values from this row
```

を選びました。

追加先は、

```
トレーニング記録
```

です。

`Set these columns` では、次のように対応付けました。

```
記録日 = [記録日]
種目 = [種目]
重量 = [重量1]
回数 = [回数1]
セット = [セット1]
補足 = [補足1]
```

IDは `Set these columns` に出てきませんでしたが、これは `トレーニング記録` 側のIDがKeyで、Initial valueに任せているため問題なしと判断しました。

また、空欄の行を追加しないために、`Only if this condition is true` に次の条件を入れました。

```
AND(
  ISNOTBLANK([重量1]),
  ISNOTBLANK([回数1]),
  ISNOTBLANK([セット1])
)
```

その後、`Form Saved` にこのアクションを設定し、テストしたところ、`筋トレ一括入力` から `トレーニング記録` へ1行追加できることを確認しました。

---

# 13. 2〜5行目の追加アクションも作った

1行目の追加が成功した後、同じ要領で2行目から5行目までのアクションを作りました。

作ったアクションは、

```
一括入力_2行目を追加
一括入力_3行目を追加
一括入力_4行目を追加
一括入力_5行目を追加
```

です。

たとえば2行目なら、

```
記録日 = [記録日]
種目 = [種目]
重量 = [重量2]
回数 = [回数2]
セット = [セット2]
補足 = [補足2]
```

にしました。

条件式も2行目用に、

```
AND(
  ISNOTBLANK([重量2]),
  ISNOTBLANK([回数2]),
  ISNOTBLANK([セット2])
)
```

としました。

3〜5行目も同様に、それぞれ `[重量3]`、`[重量4]`、`[重量5]` のように変えて作成しました。

---

# 14. グループアクションを作った

次に、1〜5行目の追加アクションをまとめて実行するため、グループアクションを作りました。

アクション名は、

```
一括入力_トレーニング記録へ追加
```

です。

設定は、

```
For a record of this table：筋トレ一括入力
Do this：Grouped: execute a sequence of actions
```

にしました。

ここで確認した重要点は、

> グループアクションも `筋トレ一括入力` に対して作る

ということです。

理由は、このグループアクションは、`筋トレ一括入力` の1件のフォーム入力内容をもとに、1〜5行目追加アクションを順番に実行するためです。

グループアクションの中には、

```
一括入力_1行目を追加
一括入力_2行目を追加
一括入力_3行目を追加
一括入力_4行目を追加
一括入力_5行目を追加
```

を順番に登録しました。

その後、`筋トレ一括入力` のFormビューの `Form Saved` に、このグループアクションを設定しました。

---

# 15. 一括入力のテストに成功した

最後に、一括入力フォームでテストしました。

たとえば、

```
記録日：今日
種目：チェストプレス

重量1：15
回数1：12
セット1：1
補足1：ウォームアップ

重量2：25
回数2：12
セット2：1
補足2：準備

重量3：30
回数3：12
セット3：3
補足3：メイン
```

のように入力しました。

その結果、`トレーニング記録` に3行が追加されました。

4行目・5行目は空欄だったため、`Only if this condition is true` の条件によって追加されませんでした。

これにより、

```
同一種目の一括入力
↓
入力された行だけを判定
↓
トレーニング記録に複数行として追加
```

という仕組みが完成しました。

---

# 16. その後、UI改善の話をした

一括入力自体は動くようになりましたが、AppSheetのFormビューは基本的に縦1列の入力フォームなので、

```
重量1
回数1
セット1
補足1
重量2
回数2
セット2
補足2
...
```

のように縦に長くなってしまいます。

そこで、画像のような横並びの表形式UIが作れるか確認しました。

結論としては、

> AppSheet標準のFormビューでは、Excelのような横並び入力表をそのまま作るのは難しい

という話をしました。

代替案として、次の2つを検討しました。

```
A. ページ区切り方式
B. 親子テーブル方式
```

## ページ区切り方式

今の `筋トレ一括入力` テーブルをそのまま使い、フォーム内を、

```
基本情報
記録日
種目

1〜2行目
重量1
回数1
セット1
補足1
重量2
回数2
セット2
補足2

3〜5行目
...
```

のようにページ分けする方法です。

メリットは、今作った仕組みをほぼ壊さずに改善できることです。

## 親子テーブル方式

もう1つは、親子テーブル方式です。

構造としては、

```
親テーブル：筋トレ一括入力
・一括ID
・記録日
・種目

子テーブル：筋トレ一括入力明細
・明細ID
・一括ID
・重量
・回数
・セット
・補足
```

にする方法です。

こちらはデータベース設計としてはきれいですが、今作った5行固定の一括入力アクションとは別の作りに近くなるため、実装は少し難しくなります。

今回の段階では、**まずページ区切り方式でフォームを見やすくする**のが現実的、という判断になりました。

---

# 17. 最終的に実現できたこと

このチャット全体で実現できたことは次の通りです。

```
1. 既存のトレーニング記録シートをAppSheetの保存先として使う
2. トレーニング記録にID列を追加し、AppSheetのKeyにする
3. 種目マスタにも種目IDを用意し、Key/Labelを設定する
4. 種目マスタから筋トレ種目だけをプルダウン表示する
5. 通常の1行入力フォームを作る
6. 総回数・総負荷はスプレッドシート側の計算に任せる
7. スプレッドシート側の入力規則とAppSheet側のEnum候補の不一致を発見する
8. 個別入力を問題なく動作させる
9. 一括入力用の筋トレ一括入力シートを作る
10. 最大5パターンまで入力できる一括入力フォームを作る
11. 1〜5行目をトレーニング記録に追加するアクションを作る
12. グループアクションで複数行をまとめて追加する
13. 空欄行は追加しない条件分岐を設定する
14. 同一種目の一括入力を実現する
15. 今後のUI改善としてページ区切り方式を採用する方針にする
```

---

# 18. 今の完成形

現時点の完成形はこうです。

## 通常入力

```
筋トレ入力フォーム
↓
記録日・種目・重量・回数・セット・補足を入力
↓
トレーニング記録に1行追加
```

## 一括入力

```
筋トレ一括入力フォーム
↓
記録日・種目を1回だけ入力
↓
重量1〜5、回数1〜5、セット1〜5、補足1〜5を入力
↓
保存
↓
グループアクション実行
↓
入力されている行だけ、トレーニング記録に複数行追加
```

つまり、同じ種目について、

```
15kg × 12回 × 1セット
25kg × 12回 × 1セット
30kg × 12回 × 3セット
```

のような内容を、1回のフォーム保存で複数行として登録できるようになりました。

# 19. 次にやる予定

次は、AppSheetのフォームが縦に長くて見にくい問題を解消するために、**ページ区切り方式**でUIを改善する予定です。

具体的には、`筋トレ一括入力` テーブルに `Show` 型の仮想列を追加し、

```
基本情報
1〜2行目
```
