# AI整理済みObsidianノートを公開可能な知識へ育てる方針

## 1. 出発点

過去に、ObsidianのInboxに大量に存在していたメモをAIで整理し、Researchフォルダへ移動した。

その結果、

- 多くのノートに`ai-generated`タグが付いている
- 文章としては整理されている
- ただし知識カードとしては未熟
- AIが最初から最後まで生成・整理しただけのノートも多い
- 自分自身の考察がまだ十分に入っていない

という状態になっている。

問題は、これらを単純に「公開記事へ清書する」のではなく、

> Obsidian  
> ＋ Zettelkasten  
> ＋ Digital Garden  
> ＋ ナラティブな公開

という自分の運用思想に合う形でどう成熟させるか、という点にある。

---

## 2. 基本方針：ノート単体ではなく「関係性のあるクラスタ」で育てる

未熟なResearchノートを、

```
ノートA
ノートB
ノートC
```

とファイル順・作成順に1件ずつ仕上げていく方法は採らない。

代わりに、

> 関係性のあるノート群を1つのテーマ／クラスタとして扱い、そのつながりを辿りながら連続的に成熟させる。

ことを基本方針とする。

### 理由

この方式には複数のメリットがある。

- Zettelkasten本来の「カード間の関係」を育てられる
- 関連カードを連続して扱うため思考が途切れにくい
- 「次に何を処理するか」が自然に見える
- テーマ全体が成長していく感覚がある
- 個々のノートの完成作業よりモチベーションを維持しやすい
- 最終的に公開サイト上でもナラティブを作りやすい

基本処理単位は、

```
1ノート
```

ではなく、

```
1テーマ
1クラスタ
1つの知識ネットワーク
```

とする。

---

## 3. Researchノートは「知識原料庫」として扱う

AI整理済みResearchノートは、失敗作や未完成記事として考えない。

位置付けとしては、

> 今後Permanent Noteや公開コンテンツを生成するための知識原料庫

とする。

すべてのResearchノートを公開品質まで磨く必要はない。

各ノートは大きく、

1. 単独で育てる
2. 他ノートと統合して育てる
3. Researchのまま保持する

に分かれる。

特に、

> 自分には役立つが、他人に公開するほどではない

というノートをResearchのまま残すことも正常な運用とする。

---

## 4. AI生成ノートとLiterature Noteの関係

AIが最初から最後まで整理・生成したノートについては、それ自体を自分のPermanent Noteとは見なさない。

そのまま参照資料として残すのであれば、

> Literature Note / 資料ノート

に近いものとして扱う。

この段階では`ai-generated`タグを残してよい。

概念としては、

```
flowchart LR
    A[AI生成・AI整理ノート] --> B[Literature Note]
    B --> C[自分が読む]
    C --> D[自分の反応・疑問・解釈]
    D --> E[AIとの追加対話]
    E --> F[自分なりの結論・主張]
    F --> G[Permanent Note]
```

となる。

---

## 5. Permanent Noteへの昇格

AI整理ノートを読んだ結果、

- 自分が疑問を持った
- 自分なりの意見を書いた
- 実体験を追加した
- 別ノートとの関係に気付いた
- AIにさらに問い返した
- AIの回答に対して再び考えた
- 最終的に自分なりの判断を形成した

という流れが生まれた場合、そのノートは単なるAI生成資料ではなくなっていく。

その時点でPermanent Noteへ昇格させる。

重要なのは、

> AI文章が残っているかどうか

ではない。

判断基準は、

> 「このノートの知的主体が誰になったか」

とする。

### Permanent化の判断基準

|観点|昇格の目安|
|---|---|
|問い|自分自身の問いになっている|
|主張|自分が採用する考え・判断がある|
|AIの役割|主体ではなく壁打ち・整理・補助になっている|
|経験|自分の経験・検証・観察が入っている|
|リンク|他カードとの関係を自分で意味付けしている|
|読み返す価値|「AIが言ったこと」ではなく「自分がどう考えたか」が残っている|

---

## 6. `ai-generated`タグの意味を明確にする

`ai-generated`は、

> AIを一度でも使ったノート

という意味ではなく、

> ノート全体の主要な知的主体がAIである

ことを示すタグとして扱う。

したがって、

### AI主体のLiterature Note

```
tags:
  - ai-generated
```

を保持。

一方、

### 自分の思考へ成熟したPermanent Note

では`ai-generated`を外してよい。

これは、

> AIを使わなくなった

という意味ではない。

より正確には、

> ノート全体の知的主体がAIから自分へ移った

ことを示す。

---

## 7. ノート内部で「誰の思考か」を明示する

この運用を成立させるうえで重要になったのが、

> ノート内部の文章が誰によるものなのかを明示する仕組み

である。

参考として強く影響を受けているのが、サイボウズ・ラボの西尾泰和氏のCosense（旧Scrapbox）。

特に、顔アイコンを使って、

- 自分の発言
- AIの発言
- 他者の発言

などを視覚的に区別できる点を評価している。

これにより、

```
🙂 自分
この整理を見てこう思った。

🤖 AI
その考え方なら、こう整理できる。

🙂 自分
ただし自分の場合はここが違う。
```

という思考の流れそのものをカード内に残せる。

---

## 8. この話者表示が持つ意味

顔アイコンは単なる装飾ではない。

役割としては、

> 発話主体・思考主体のメタデータ

である。

ノートの内部で、

```
誰が考えたのか
誰が発言したのか
どこから自分自身の考察へ変わったのか
```

を追跡できる。

これにより、Permanent Noteから`ai-generated`タグを外しても、

> AI由来部分まで消えてしまう

ことはない。

情報の管理粒度を分けられる。

```
ノート単位
└─ ai-generated
   └─ ノート全体の主要主体

本文ブロック単位
├─ 自分
├─ AI
└─ その他
   └─ 個々の発話・思考主体
```

---

## 9. Obsidianでの実装案

最有力案は、

> Custom Callout + CSS + Templaterショートカット

である。

Markdown内部では意味構造のみ保持する。

例：

```
> [!talk-me]
> このノートを読んで、自分はこう考えた。

> [!talk-ai]
> その場合、この観点も考えられる。
```

Obsidian側ではCSSによって、

- Callout背景を消す
- 枠線を消す
- Calloutタイトルを消す
- 左側に顔アイコンを表示
- 右側に本文を配置

といった表示にする。

結果として、見た目はCosenseに近い、

```
🙂 本文

🤖 本文
```

という軽量な会話表示を目指す。

---

## 10. Quartzとの両立

Markdown内に画像や複雑なHTMLを直接埋め込むのではなく、

```
[!talk-me]
[!talk-ai]
```

のような意味情報を残す。

表示については、

```
flowchart LR
    A[Markdown] --> B[Obsidian CSS]
    A --> C[Quartz CSS]
    B --> D[Obsidian上の表示]
    C --> E[公開サイト上の表示]
```

とする。

つまり、

> Markdownの意味構造は共通  
> 表示だけObsidianとQuartzそれぞれで調整

という設計にする。

長期的な保守性が高い。

---

## 11. 入力はショートカット化する

毎回、

```
> [!talk-me]
>
```

と入力するのは避ける。

Templater等を使い、

```
Ctrl + Alt + M
→ 自分

Ctrl + Alt + A
→ AI
```

のようなショートカットで即座に挿入できる仕組みを用意する。

理想的には、

```
ショートカット
↓
話者ブロック挿入
↓
本文位置へカーソル移動
↓
そのまま入力
```

とする。

---

## 12. 当初は話者を細分化しすぎない

将来的には、

- 自分
- ChatGPT
- Claude
- Gemini
- その他人物

などへ分けることも可能。

ただし初期実装では、

```
自分
AI
```

程度に留める案が有力。

理由は、

- モデル名は頻繁に変わる
- サービス名まで分けると運用負荷が増える
- 本質的なのは「人間かAIか」
- 必要になれば後から拡張できる

ため。

---

## 13. 外部資料と話者表示は分ける

第三者の資料・Web・書籍まで、すべて顔アイコン方式にはしない。

区別すべきものは、

```
🙂 自分
→ 思考主体

🤖 AI
→ 思考主体

Web / 書籍 / 論文
→ 出典・典拠
```

である。

つまり、

> 誰が考えたか

と、

> どこから得た情報か

を混同しない。

外部資料は通常の引用・出典・Literature Noteへのリンク等で管理する。

---

## 14. 「AIとの対話」という中間層

従来のZettelkastenでは、

```
Source
↓
Literature Note
↓
Permanent Note
```

という流れが一般的。

現在のAI環境では、その間に、

> Thinking / Dialogue

という層が実質的に存在する。

```
flowchart LR
    A[Source] --> B[Literature Note]
    B --> C[自分の思考]
    C --> D[AIとの対話]
    D --> E[再考]
    E --> F[Permanent Note]
```

この思考・対話過程自体を消さずに残す。

これがCosense的な公開との相性も良い。

---

## 15. ナラティブな公開

公開する際は、Permanent Noteを独立した完成記事として並べるだけではない。

カード同士が、

```
AはBの前提
BはCの具体例
CはAに対する反論
DはA〜Cから生まれた自分の考察
```

のようにつながっていること自体を見せる。

理想的には、

```
flowchart LR
    A[情報を知る] --> B[疑問を持つ]
    B --> C[AIと対話する]
    C --> D[自分で考える]
    D --> E[別ノートへつながる]
    E --> F[考えが更新される]
```

という知識形成のナラティブが公開サイト上でも辿れる状態にする。

---

## 16. MOCについて

途中で使用した`MOC`は、

> Map of Content

の略。

関連するノートをまとめた、

> 目次  
> 案内ページ  
> テーマの入口

に相当する。

例：

```
# AI × Obsidian 知識管理

- [[InboxをAIで整理する]]
- [[AI-generatedタグの扱い]]
- [[Literature NoteとPermanent Note]]
- [[AIとの対話をカードへ残す]]
- [[Quartzで公開する]]
```

ただし、この運用では`MOC`という用語そのものにこだわる必要はない。

自分にとっては、

> テーマページ  
> 案内ページ  
> ナラティブの入口

程度の理解でよい。

---

## 17. 西尾泰和氏から受けている影響

公開知識管理の方向性として、サイボウズ・ラボの西尾泰和氏のCosenseを重要な参照対象とする。

特に影響を受けているのは、

- 完成した記事だけを公開しない
- 思考の断片も公開する
- カード間リンクを重視する
- 後から知識同士がつながる
- 思考過程そのものに価値を持たせる
- 人間とAIなど、発話者を視覚的に区別する
- 完成品というより「育ち続ける知識」を公開する

という方向性。

自身のObsidian + Zettelkasten + Quartzも、一般的なブログより、

> 公開された個人知識ベース  
> ＋ 思考履歴  
> ＋ Digital Garden

に近いものを目指す。

# 現時点での全体モデル

```
flowchart TD
    I[Inbox<br>断片・メモ]
    R[Research<br>AI整理済み]
    L[Literature Note<br>資料・AI生成物]
    T[Thinking / Dialogue<br>自分とAIの思考過程]
    P[Permanent Note<br>自分の知識]
    N[関連Permanent Note群]
    G[テーマページ / ナラティブ]
    Q[Quartz公開]

    I --> R
    R --> L
    L --> T
    T --> P
    P --> N
    N --> G
    G --> Q
```

ただし実際には完全な一方向ではない。

公開後も、

```
Permanent Note
↓
新しい経験
↓
新しい疑問
↓
AIとの再対話
↓
Permanent Note更新
```

という循環を前提にする。

# Decisions

現時点で決まった方針は以下。

1. AI整理済みResearchノートを1枚ずつ機械的に完成させない。
2. 関係性のあるノートをテーマ／クラスタ単位で処理する。
3. Researchフォルダは公開記事置き場ではなく知識原料庫として扱う。
4. AIが主体のノートはLiterature Note的に保持する。
5. AI主体のノートには`ai-generated`タグを残す。
6. 自分自身の思考・判断が中心になったノートはPermanent Noteへ昇格する。
7. Permanent Noteへの昇格時、条件を満たせば`ai-generated`タグを外す。
8. `ai-generated`は「AIを使ったか」ではなく「ノート全体の知的主体」を示す。
9. ノート内部では人間とAIの思考主体を明示する。
10. Cosenseの顔アイコン式表示を参考にする。
11. ObsidianではCustom Callout + CSS + Templaterを第一候補とする。
12. Quartz側でも同じMarkdownをCSSで表示する。
13. 話者入力はショートカット化する。
14. 初期段階では「自分」「AI」程度の少数話者から始める。
15. 第三者資料・Web情報は話者ではなく出典として管理する。
16. AIとの対話過程自体を知識形成の一部として残す。
17. 公開時にはカード単体ではなく、カード間のナラティブも重視する。
18. テーマ単位の案内ページを用意する。ただしMOCという名称に固執しない。
19. 西尾泰和氏のCosenseを、今後の公開知識管理における重要な参照軸とする。

## このスレッドで到達した核心

この一連の話で最も重要なのは、

> **AIが作った文章を公開することではなく、AIが作った知識素材を自分が読み、反応し、問い直し、AIとも対話しながら、自分自身のPermanent Noteへ変えていく過程そのものを知識資産として残す**

という方向性が明確になったこと。

さらに、その思考形成過程を、

- カード間リンク
- 自分とAIの話者表示
- Literature Note
- Permanent Note
- テーマ単位のナラティブ

として公開する。

これにより、Obsidian + Zettelkasten + Quartzは単なるブログ基盤ではなく、

> **「自分の思考がどのように形成され、更新され、他の知識と結びついたか」を公開するDigital Garden**

として育てていくことができる。
