# 継続的な画像共有ではファイル転送より共有場所を固定する

大容量の画像を外部担当者へ渡す方法として、ギガファイル便のようなファイル転送サービスと、Googleドライブの共有リンクがある。

単発の受け渡しだけなら、どちらでも大きな問題はない。むしろ「一度ダウンロードしてもらえば終了」という用途では、ギガファイル便の方が操作が単純で使いやすい場合もある。

ただし、打ち合わせ後に修正や差し替えが続く案件では、単なる「ファイル送信」ではなく、**同じ共有場所を継続利用する方が管理しやすい**。

今回のイプロス広告案件では、

- 来週に軽い打ち合わせを行う
- その後、タイトルを調整する
- サムネイルを調整する
- A/Bテスト用のデザインを作る
- A案・B案を比較する
- 必要に応じて再修正する
- 画像の追加や差し替えが発生する

という流れが想定されている。

この条件では、Googleドライブを共有場所として固定する方が適している。

|比較項目|Googleドライブ|ギガファイル便|
|---|---|---|
|単発の大容量送付|○|◎|
|継続的な案件|◎|△|
|画像プレビュー|◎|△|
|後からファイル追加|◎|再送が必要|
|差し替え対応|◎|再アップロード|
|同じURLの継続利用|◎|△|
|過去版の整理|◎|△|
|A/B案の整理|◎|△|
|相手側の操作の簡単さ|○|◎|
|権限管理|◎|△|

## ファイルを「送る」運用の問題

ギガファイル便を修正のたびに使用すると、次のような流れになる。

```
初稿
↓
URL①

修正版
↓
URL②

A/Bテスト案
↓
URL③

再修正版
↓
URL④
```

この方式では、連絡履歴の中に複数のURLが残る。

その結果、

- どれが最新版なのか分かりにくくなる
- 古いURLを相手が開く可能性がある
- 修正のたびにアップロードが必要になる
- ファイル管理と連絡が分離する
- A案・B案・旧版の関係が見えにくくなる

という問題が起こりやすい。

単発の送付では問題にならないが、修正回数が増えるほど管理コストが増える。

## 共有場所を固定する

Googleドライブでは、一度共有フォルダを作れば、その後も同じURLを利用できる。

```
共有フォルダ
↓
現在の画像を格納
↓
担当者へURL共有
↓
打ち合わせ
↓
修正版を追加
↓
A/Bテスト案を追加
↓
再修正版を追加
```

担当者は毎回新しいURLを探す必要がなく、常に同じ場所を確認すればよい。

この場合、

```
メール・連絡
＝ 何を変更したか伝える

Googleドライブ
＝ 実際のファイルを置く
```

という役割分担になる。

ファイルそのものをメールごとに送り直すのではなく、**共有場所の更新を通知する**という運用になる。

## フォルダ構成

最初から細かく分けすぎる必要はない。

ファイル数が少ないうちは、例えば次の程度でよい。

```
イプロス広告
├─ 現行
├─ ABテスト
└─ 旧版
```

作業量が増えてきた場合は、次のように拡張できる。

```
イプロス広告
├─ 01_現行素材
├─ 02_打ち合わせ用
├─ 03_ABテスト
│  ├─ A案
│  └─ B案
└─ 99_旧版
```

重要なのは、最初から管理構造を作り込みすぎることではなく、**現在使用するデータと過去データを混在させないこと**。

## バージョン管理

A/Bテストやデザイン修正では、ファイル名でも版を判別できるようにする。

例えば、

```
thumbnail_A_v01.jpg
thumbnail_B_v01.jpg
```

修正版なら、

```
thumbnail_A_v02.jpg
thumbnail_B_v02.jpg
```

とする。

次のようなファイル名は避ける。

```
最終.jpg
最終2.jpg
最終修正版.jpg
本当の最終.jpg
```

「最終」という名前は、修正が発生すると意味を失う。

連番の方が変更履歴を判断しやすい。

## 共有権限

外部担当者には、最初から編集権限を与える必要はない。

基本は、

> リンクを知っている全員：閲覧者

とする。

これなら担当者は、

- 画像を見る
- プレビューする
- ダウンロードする

ことができる一方、こちらのファイルを変更・削除することはできない。

相手側からファイルをアップロードしてもらう必要が出た場合だけ、別途方法を検討する。

## ギガファイル便の位置付け

ギガファイル便を使わないという意味ではない。

次のような用途では依然として便利。

- 一度だけ大容量ファイルを渡す
- 完成データをまとめて送る
- 相手側でGoogleドライブへアクセスできない
- 社内セキュリティの都合でGoogleドライブが使えない
- 一時的にZIPファイルを渡したい

したがって、

```
flowchart LR
    A[継続的な修正・共有] --> B[Googleドライブ]
    C[一度だけの大容量送付] --> D[ギガファイル便]
    B --> E{相手側で利用可能か}
    E -->|利用可能| F[同じ共有リンクを継続利用]
    E -->|利用不可| D
```

という使い分けになる。

## 今回の判断

今回のイプロス広告案件では、打ち合わせ後にもタイトル・サムネイル・A/Bテスト向けのデザイン調整が続く予定である。

そのため、単なる大容量ファイルの受け渡しとして考えるのではなく、**継続案件用の共有場所を用意する**方が適している。

基本方針は次の通り。

- Googleドライブを共有場所として固定する
- 同じ共有リンクを今後も利用する
- 担当者には原則として閲覧権限のみ付与する
- 現行・A/Bテスト・旧版を分けて管理する
- 修正版にはバージョン番号を付ける
- ギガファイル便は単発送付またはGoogleドライブが使えない場合の代替手段とする

重要なのは、**ファイルの受け渡し方法そのものより、修正が続く案件では「どこを見れば最新版があるか」を固定すること**である。

この内容なら、単なるイプロス固有のメモよりも、今後ほかの外部業者・制作会社とのデータ共有にも再利用しやすいPermanent寄りのノートとして扱えます。
