# プリントパック入稿時にグレーが濃くなる問題

会社の複合機でPDFを印刷した場合は色合いに問題がない一方、同じPDFをプリントパックへ入稿して印刷すると、ライトグレーやグレーが想定より濃くなり、黒に近い色味になることがある。

今回のPDFは、元の最新AIデータが残っておらず、以前の完成PDFを外注先へ渡し、それを元に修正してもらったものだった。

制作工程はおおむね次の通り。

```
flowchart LR
    A[古いAIデータしか残っていない] --> B[最新の完成PDFを外注先へ渡す]
    B --> C[外注先がPDFを元に修正]
    C --> D[修正版PDFを納品]
    D --> E[プリントパックへ入稿]
    E --> F[グレーが濃く印刷された]
```

この工程では、単純な「プリントパックの色が濃い」という問題だけでなく、**PDFを再編集・再書き出しした段階でカラー情報が変化していないか**を最初に確認する必要がある。

## 最も疑うべき原因

特に優先度が高いのは次の4点。

|原因|何が起こるか|
|---|---|
|PDF再編集時のカラー変換|既存部分を含めCMYK値や色空間が変化する|
|K単色グレーが4色グレーへ変化|ライトグレーが重く、黒っぽくなる|
|RGB→CMYK変換|画面上のグレーと印刷時のグレーに差が出る|
|複合機側の自動補正|PDFに問題があっても社内印刷では自然に見える|

### PDFを再編集したこと自体が重要

PDFは基本的には最終出力用の形式であり、元のIllustratorデータを編集する場合とは事情が違う。

PDF内部には、

- CMYK
- RGB
- グレースケール
- DeviceGray
- ICCプロファイル付きカラー
- 特色
- オーバープリント
- 透明効果
- 描画モード
- Output Intent

など複数の情報が含まれている。

そのPDFをIllustratorなどで開き、編集して再度PDFとして書き出すと、

```
flowchart LR
    A[元PDF] --> B[Illustrator等で読み込み]
    B --> C[カラー情報を再解釈]
    C --> D[修正]
    D --> E[PDF再書き出し]
    E --> F[カラー情報が変化する可能性]
```

という処理が発生し得る。

そのため、**修正していない既存のグレーまで濃くなっている場合は、PDF全体のカラー情報が再変換された可能性が高い。**

## K単色グレーと4色グレー

同じように見えるグレーでも、印刷データ上の作り方によって結果が異なる。

K単色なら例えば、

```
C 0
M 0
Y 0
K 20
```

のようになる。

一方、4色グレーでは、

```
C 20
M 15
Y 15
K 15
```

のようにCMYKを重ねて作る。

4色グレーは印刷時に、

- 想定より濃くなる
- 黒っぽく見える
- わずかに色味が付く
- 印刷機の濃度差の影響を受けやすい

といった問題が出やすい。

今回のような「ライトグレーがブラック寄りになる」という症状では、**元々K単色だったグレーが再編集時に4色グレーへ変換された可能性**を確認すべき。

## RGBからCMYKへの変換

画面上では単純なニュートラルグレーでも、RGBデータがCMYKへ変換されるとK単色になるとは限らない。

例えば、

```
RGB
R 200
G 200
B 200
```

が、

```
CMYK
C 15
M 12
Y 12
K 15
```

のように複数色へ分解される場合がある。

そのため、完成PDF内部にRGBオブジェクトが残っていないかも確認する必要がある。

## 複合機で正常でもPDFが正常とは限らない

会社の複合機と商業印刷では出力処理が大きく異なる。

複合機では、

- RGB変換
- 自動色補正
- 明度補正
- コントラスト補正
- 黒生成
- トナー濃度制御
- 文書向け補正

などが行われることがある。

```
flowchart LR
    A[PDF] --> B[プリンタドライバ]
    B --> C[自動色補正]
    C --> D[複合機用の色変換]
    D --> E[トナー出力]
```

そのため、PDF側に問題があっても複合機では自然に見える可能性がある。

つまり、

> 複合機では問題なく印刷できた

ことは、

> PDFデータにも問題がない

ことを意味しない。

むしろ、商業印刷で初めてデータ上の問題が表面化する場合がある。

## その他に考えられる原因

### ドットゲイン

商業印刷では、網点が紙上で広がることで中間調がデータ上より濃く見える。

例えば、

```
データ
K 20%
```

でも、実際の印刷物では視覚的にそれ以上の濃度に感じることがある。

ライトグレーや中間グレーは特に影響を受けやすい。

複合機とは印刷方式が異なるため、複合機では問題が再現しないこともある。

### 用紙の違い

同じCMYK値でも、用紙によって見え方は変わる。

代表例は、

- コート紙
- マットコート紙
- 上質紙
- 光沢紙

など。

用紙によって、

- インキの沈み方
- 光の反射
- 黒の締まり方
- 彩度
- コントラスト

が異なる。

特にマット系の紙では、グレーが重く沈んで見えることがある。

以前同じカタログを正常に印刷できていた場合は、

- 用紙種類
- 紙厚
- プリントパックの商品
- 印刷方式

が前回と今回で同じか確認する。

### オーバープリント

グレーのオブジェクトにオーバープリントが設定されている場合、下地の色と重なって印刷される。

```
上のグレー
+
下の色
=
重なった色
```

そのため、想定より濃くなることがある。

画面や一般的な複合機では目立たず、印刷用RIPで処理されたときに問題が表面化する場合もある。

### 透明・乗算などの描画モード

グレーが単純なCMYKオブジェクトではなく、

- 透明度
- 乗算
- オーバーレイ
- 透明グループ
- その他の効果

を使っている場合も注意が必要。

例えばK20%のグレーでも「乗算」になっていれば下地と合成され、想定以上に濃くなる。

PDF再編集時に透明効果が統合されたり、描画設定が変わった可能性もある。

### ICCプロファイルとOutput Intent

CMYK値だけでなく、どの印刷条件を前提としたPDFなのかも重要。

PDF/Xなどでは、Output Intentによって印刷条件を指定できる。

例えば、

```
修正前
Japan Color系
```

から、

```
修正後
別のCMYKプロファイル
```

へ変化していれば、RIP側での色処理も変わる可能性がある。

そのため、Illustrator側の設定だけでなく、**完成PDFそのもののICCプロファイルとOutput Intentを確認する必要がある。**

## PDF上で同じ見た目でも内部データは異なる

画面上では同じライトグレーに見えても、内部的には次のような違いがあり得る。

```
DeviceGray
20%
```

```
CMYK
C0 M0 Y0 K20
```

```
RGB
R204 G204 B204
```

```
CMYK 4色
C15 M10 Y10 K15
```

モニターでは似て見えても、印刷時の処理が異なるため、結果にも差が出る。

## 原因を切り分ける方法

まず、修正前PDFと修正後PDFの同じグレー部分を比較する。

例えば、

```
修正前
C 0
M 0
Y 0
K 15
```

だったものが、

```
修正後
C 15
M 12
Y 12
K 20
```

になっていれば、PDF再編集時のカラー変換が原因としてかなり有力になる。

確認する順序は次の通り。

1. 修正前PDFと修正後PDFの同じ箇所のCMYK値を比較する。
2. K単色グレーが4色グレーへ変わっていないか確認する。
3. RGBオブジェクトが残っていないか確認する。
4. DeviceGrayや特色が使われていないか確認する。
5. オーバープリントの有無を確認する。
6. 透明・乗算などの設定を確認する。
7. ICCプロファイルとOutput Intentを比較する。
8. 前回正常に印刷できたものがあるなら、用紙・紙厚・印刷方式を比較する。
9. それでも差が説明できなければ、プリントパック側の印刷条件やロット差を確認する。

```
flowchart TD
    A[グレーが濃く印刷された] --> B[修正前PDFと修正後PDFを比較]
    B --> C{CMYK値が変わっているか}
    C -->|はい| D[PDF再編集・カラー変換を疑う]
    C -->|いいえ| E[色空間・ICC・Output Intent確認]
    E --> F[オーバープリント・透明・乗算確認]
    F --> G[前回との用紙・印刷条件比較]
    G --> H[プリントパック側の印刷工程を確認]
```

## 症状から見た原因候補

|症状|主に疑うもの|
|---|---|
|修正した箇所だけ濃い|新しく設定した色の値が違う|
|修正ページ全体が濃い|PDF再編集・再書き出し時のカラー変換|
|修正していない既存グレーも濃い|PDF全体のカラー情報が変化した可能性|
|グレーだけ特に濃い|K単色→4色グレー、ドットゲイン|
|写真も含めて全体の色が違う|ICC、Output Intent、RGB→CMYK|
|下地によって濃さが違う|オーバープリント、乗算|
|前回正常で今回は濃い|PDF生成条件、用紙、印刷条件の違い|
|複合機だけ正常|複合機側の自動補正|

## 外注先へ確認する内容

外注先には単に「色が濃くなった」と伝えるのではなく、次の点を確認してもらうと原因を特定しやすい。

- 修正前PDFと納品PDFで、同じグレー部分のCMYK値は同一か
- K単色グレーが4色グレーへ変換されていないか
- RGBデータが残っていないか
- PDFを何のソフトで編集したか
- IllustratorでPDFを直接開いて編集したのか
- PDF書き出し時にカラー変換を行ったか
- ICCプロファイルが変更されていないか
- Output Intentが変更されていないか
- オーバープリントが設定されていないか
- 透明や乗算などの効果が残っていないか

最優先なのは、**修正前PDFと修正後PDFの同じ位置について、実際のCMYK値と色空間を比較すること**。

今回の制作工程では、まず外注先によるPDF再編集・再書き出しによってカラー情報が変化していないかを確認し、その後にプリントパック側の印刷条件や用紙の影響を調べる順序が合理的である。
