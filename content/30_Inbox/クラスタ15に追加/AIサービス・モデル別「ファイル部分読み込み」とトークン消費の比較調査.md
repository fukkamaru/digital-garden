# AIサービス・モデル別「ファイル部分読み込み」とトークン消費の比較調査

AIがローカルファイルや接続先のファイルを扱う際に、

> 「ファイル全文をモデルへ入力してから必要箇所を探すのか」
> 
> それとも
> 
> 「検索・範囲取得・インデックス等を使い、必要部分だけをモデルへ入力するのか」

という違いについて詳しく調査してください。

単なる「長いファイルを読めるか」という比較ではなく、**モデルへ実際に投入されるコンテキスト量と、その前段にあるファイル取得・検索機構まで分解して比較すること**が目的です。

2026年9月時点の最新情報をWeb検索で確認してください。

## 調査したい中心的な疑問

例えば100ページのMarkdown、PDF、テキストファイルがあり、

> 「第3章だけ読んで内容を説明してください」

と指示した場合、

### パターンA

```
100ページ全文
↓
モデルへ入力
↓
モデルが第3章を探す
↓
回答
```

となるのか、

### パターンB

```
検索・見出し検出・範囲取得
↓
第3章だけ抽出
↓
第3章だけモデルへ入力
↓
回答
```

となるのかを知りたいです。

後者なら、モデルの入力トークンを大幅に削減できる可能性があります。

ただし、単にAIへ「必要部分だけ読んで」と指示しただけで後者になるとは限らないため、**実際の実装・ツール能力・エージェント挙動を確認してください。**

## 最重要：比較単位を混同しないこと

「AIサービス」と「モデル」と「ファイル取得機構」を分けて分析してください。

例えば、

```
AIサービス / ホスト
        ↓
エージェント制御
        ↓
ファイル検索・取得ツール
        ↓
モデル
```

という複数層があります。

したがって、

> 「GPTは部分読みできる」  
> 「Claudeは全文を読む」

のように、モデル単体の能力として安易に断定しないでください。

以下を分離してください。

- モデルそのものの能力
- ChatGPT / Claude / Gemini等のサービス側実装
- Agent / Work / Code環境などのエージェント制御
- ファイル検索機構
- semantic search / RAG
- grep等の文字列検索
- 行範囲・ページ範囲取得
- MCP
- 独自API
- ローカルファイル操作ツール
- クラウドストレージ接続
- コンテキストキャッシュ等

ただし、

とは仮定しないでください。

ツール利用方針とモデル能力を分けて評価してください。

## APIとMCPの関係

今回、この点も詳しく整理してください。

部分読み自体は、

```
search()
read_range()
read_page()
grep()
```

のような独自APIでも実現できます。

そのため、

> MCPだから部分読みできる

という説明は不正確だと考えています。

以下を整理してください。

- APIだけでも何が実現できるか
- MCPが追加する価値は何か
- MCPは部分読み・RAG技術そのものなのか
- MCP Serverがどのような検索・読み込み機能を公開するかによって挙動がどう変わるか
- MCP Host / Client / Server / Modelの役割
- MCP利用時でも全文取得になるケースはあるか
- 独自APIとMCPの実質的な違い

## トークン消費について

特に重要です。

以下の3つを分離してください。

1. ストレージ上のファイルサイズ
2. 検索・インデックス・ツール側が処理したデータ量
3. モデルのコンテキストへ実際に投入されたトークン量

例えば100ページのファイルから第3章10ページだけ抽出した場合、

> ファイル検索システムは100ページを処理しているが、モデルへ入るのは10ページだけ

という構造があり得ます。

この場合、

- モデルの入力トークン
- サービスの利用制限
- API課金
- Agent / Workの利用量

がそれぞれどう扱われるか、公開情報の範囲で確認してください。

特に、

> 「部分取得すれば必ず利用制限も10分の1になる」

とは仮定しないでください。

サービス独自の利用量計算がある場合は分離してください。

## 最終的に知りたいこと

調査結果から、以下を明確にしてください。

### 1. どのAI環境が部分読み込みに強いか

単なるコンテキスト長ではなく、

> **大きなファイルから必要箇所だけを効率よく取得してモデルへ渡す能力**

で比較してください。

### 2. モデル差とサービス差のどちらが大きいか

例えば、

> 同じGPTでもChatGPT WorkとAPI Agentでは挙動が違う

などがあるのかを整理してください。

### 3. ユーザー側で保証できる方法

「AIが賢く部分読みしてくれること」を期待するのではなく、

- ファイル分割
- Index
- RAG
- MCP
- 独自検索API
- grep
- ファイル単位のコンテキスト境界

など、**構造的に全文投入を防ぐ方法**を比較してください。

### 4. AI向けローカルファイル設計への示唆

最終的には、

> 巨大な1ファイルを維持してAIに部分読みさせる

のと、

> 最初から小さな複数ファイルへ分割する

のでは、2026年時点のAIエージェント環境ではどちらが堅牢なのか判断したいです。
