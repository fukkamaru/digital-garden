Googleスプレッドシートにある既存の`トレーニング記録`シートへ、AppSheetから筋トレ内容を入力できるようにする。

最初の目的は、

```text
記録日
種目
重量
回数
セット
補足
```

を入力できるようにすること。





ただし、1セットごとに1行入力するのではなく、

```text
同じ重量・同じ回数で行ったセット群を1行で記録する
```

という運用にした。

例：

```text
チェストプレス
30kg × 12回 × 3セット
```

を、3行ではなく1行で入力する。

---

# 1. 既存の「トレーニング記録」シートを使う方針

最初に確認したのは、

> トレーニング記録は今あるやつで良いのか？新しく作るのか？

という点。

結論は、

```text
既存の「トレーニング記録」シートを使う
```

で進めた。

理由は、すでに以下のような列構成があり、筋トレ記録の保存先として使える形だったため。

```text
記録日
種目
主対象
副対象
重量
回数
セット
総回数
総負荷
有酸素運動
補足
week
```

ただし、AppSheetでは各行を一意に識別するためのKey列が必要なので、`トレーニング記録` の一番左に `ID` 列を追加した。

既存データには、`1` からの連番IDを事前に入れた。

# 2. 種目マスタの扱い

種目マスタは元々存在しており、既存のトレーニング記録でも使っていた。

当初は、

> 種目マスタにもID列は必要か？

という話になった。

結論として、長期的に使うなら種目マスタにもID列を入れた方がよい、ということで、種目マスタにも `種目ID` 列を追加した。

種目マスタの構成は画像から、以下のような形だった。

```text
種目ID
種目
タイプ
主対象
副対象1
副対象2
```

例：

```text
leg_press       レッグプレス        マシン  太もも      お尻        もも裏
adduction       アダクション        マシン  内もも      股関節まわり
abduction       アブダクション      マシン  お尻        外もも      股関節まわり
lat_pulldown    ラットプルダウン    マシン  背中        腕          肩まわり
bicep_curl      バイセップスカール  マシン  腕          前腕
dips            ディップス          マシン  胸          二の腕
chest_press     チェストプレス      マシン  胸          二の腕      肩前部
shoulder_press  ショルダープレス    マシン  肩          二の腕      胸上部
bodyweight_sq   自重スクワット      自重    太もも      お尻        もも裏
stationary_bike バイク              マシン  心肺機能    太もも      お尻
treadmill       トレッドミル        マシン  心肺機能    脚          お尻
```

AppSheet側では、種目マスタの設定を以下のようにした。

```text
種目ID：Key ON
種目：Label ON
```

ただし、今回の `トレーニング記録` 側では、まだ `種目ID` を保存するRef方式にはせず、既存データとの互換性を優先して、`種目` 名をそのまま保存する形にした。

つまり、`トレーニング記録[種目]` には、

```text
チェストプレス
アダクション
自重スクワット
```

のような種目名が入る。

# 4. トレーニング記録のID設定

`トレーニング記録` の `ID` 列をKeyに設定した。

設定内容は以下。

```text
Type：Number
Key：ON
Label：OFF
Show?：OFF
Editable?：OFF
Required?：ON
Initial value：MAX(トレーニング記録[ID]) + 1
```

これにより、新しくAppSheetから登録した行には、

```text
既存の最大ID + 1
```

が自動で入るようにした。

# 5. 種目をプルダウン化した

`トレーニング記録` の `種目` 列を、AppSheet側でプルダウン入力にした。

設定は以下。

```text
Type：Enum
Base type：Text
Allow other values：OFF
Required?：ON
```

`Valid If` には、種目マスタから筋トレ種目だけを出す式を入れた。

最終的には、有酸素運動を `主対象 = 心肺機能` で判定し、以下の式にした。

```appsheet
SORT(
  SELECT(
    種目マスタ[種目],
    [主対象] <> "心肺機能"
  )
)
```

これにより、以下は表示される。

```text
レッグプレス
アダクション
アブダクション
ラットプルダウン
バイセップスカール
ディップス
チェストプレス
ショルダープレス
自重スクワット
```

以下は除外される。

```text
バイク
トレッドミル
```

途中で、`[有効] = TRUE` を使った式を入れたためエラーが出た。

理由は、種目マスタに `有効` 列が存在しなかったため。

そのため、上記の `[主対象] <> "心肺機能"` に修正した。

# 10. 総回数・総負荷の計算式でエラーが出た

最初、AppSheet側の `App formula` に以下のような式を入れた。

```appsheet
[回数] * [セット]
```

```appsheet
[重量] * [回数] * [セット]
```

しかし、エラーが出た。

主な原因は2つ。

## 原因1：列名の違い

AppSheet側では `セット数` ではなく `セット` と認識されていた。

そのため、`[セット数]` は使えず、使うなら `[セット]` にする必要があった。

## 原因2：スプレッドシート側にも数式が入っていた

エラー内容は、

```text
Sheet Formula as well as an App Formula. This is not allowed.
```

つまり、

```text
スプレッドシート側にも数式がある
AppSheet側にもApp formulaがある
両方は不可
```

という意味だった。

今回の運用では、スプレッドシート側に既に数式があり、スプレッドシートを計算・集計の中心として使う方針だったため、AppSheet側の `App formula` は空欄にした。

結論として、役割分担は以下になった。

```text
AppSheet：入力フォーム
Googleスプレッドシート：保存先・計算・集計
```

したがって、`総回数`、`総負荷`、`week` などの計算はスプレッドシート側に任せる。

# 12. 同期エラー：自重スクワットだけ保存できなかった

同期エラーの内容は以下だった。

```text
Value '自重スクワット' in field '種目' cannot be converted to type 'Enum'.
```

最初は、AppSheet側の `種目` 列の設定を疑った。

しかし、以下は問題なかった。

```text
Type：Enum
Base type：Text
Allow other values：OFF
Required?：ON
```

その後、複数種目でテストした結果、

```text
チェストプレス：OK
アダクション：OK
自重スクワット：NG
```

となり、自重スクワットだけが失敗することが分かった。

最終的に、原因はAppSheetではなく、**スプレッドシート側の種目列のプルダウンに自重スクワットが入っていなかった**ことだった。

つまり、

```text
AppSheet側：自重スクワットを許可
Googleスプレッドシート側：自重スクワットを許可していない
```

という不一致が原因だった。

このとき、スプレッドシート側にもデータ入力規則がある場合、AppSheetからの書き込みもその制約に引っかかることを確認した。

補足として、以下も整理した。

```text
スプレッドシート側にプルダウンがない場合：
AppSheet側だけでEnumやValid Ifを設定すればOK

スプレッドシート側にもプルダウンがある場合：
AppSheet側とスプレッドシート側の候補を一致させる必要がある
```

今後は、スプレッドシート側のプルダウンも `種目マスタ` を参照させるのが安全、という話になった。

# 13. Enumとは何かを整理した

途中で、

> Enumとはそもそも何か？  
> AppSheetで扱える型を教えてほしい

という話になった。

整理した内容は以下。

## Enum

`Enum` は、候補から1つ選ぶ型。

例：

```text
種目：チェストプレス / アダクション / レッグプレス から1つ選ぶ
重量：0 / 5 / 10 / 15 / 20 から1つ選ぶ
```

`Enum` は選択式にするための型で、`Base type` に中身の型を指定する。

例：

```text
種目：Type = Enum, Base type = Text
重量：Type = Enum, Base type = Number
```

## EnumList

候補から複数選ぶ型。

例：

```text
効いた部位：胸、肩、二の腕
```

## Ref

別テーブルの1行を参照する型。

例：

```text
トレーニング記録[種目ID] → 種目マスタ[種目ID]
```

長期的にきれいな設計にするなら、種目は `Enum` ではなく `Ref` にする方法もある。

ただし、今回は既存データとの互換性を優先して `Enum` にした。

## 主な型

整理した型は以下。

```text
Text：短い文字
LongText：長文
Number：整数
Decimal：小数
Date：日付
DateTime：日付＋時刻
Time：時刻
Yes/No：TRUE/FALSE
Enum：候補から1つ選択
EnumList：候補から複数選択
Ref：別テーブル参照
Image：画像
File：ファイル
URL：URL
Email：メール
Phone：電話番号
Price：金額
Percent：パーセント
LatLong：緯度経度
Address：住所
Show：フォーム上の見出し・説明
```

# 23. 一括入力からトレーニング記録へ1行追加するアクションを作成

次に、一括入力フォームに入力した内容を、既存の `トレーニング記録` に追加するアクションを作った。

まずは1行目だけ作った。

AppSheetで、

```text
Behavior > Actions > New Action
```

から作成。

設定は以下。

```text
Action name：一括入力_1行目を追加
For a record of this table：筋トレ一括入力
Do this：Data: add a new row to another table using values from this row
```

`Do this` の候補から、以下を選んだ。

```text
Data: add a new row to another table using values from this row
```

追加先は `トレーニング記録`。

ただし、画面上で `Table to add to` という名前が見つからず、追加先テーブルの指定欄が別名になっている可能性を確認した。

その後、`Set these columns` で、追加先の列と値を設定した。

設定内容は以下。

```text
記録日 = [記録日]
種目   = [種目]
重量   = [重量1]
回数   = [回数1]
セット = [セット1]
補足   = [補足1]
```

`ID` は表示されなかった。

理由は、`トレーニング記録` 側の `ID` がKeyかつ非表示・編集不可で、Initial valueが設定されているため。

そのため、IDはアクション側では指定せず、`トレーニング記録` 側のInitial valueに任せることにした。

また、画像上で `有酸素運動 = [重量1]` のような不要な設定が見えたため、これは削除するようにした。

# 24. 空欄行を追加しない条件を入れた

1行目追加アクションには、空欄のとき実行しない条件を入れた。

`Only if this condition is true` に以下を設定。

```appsheet
AND(
  ISNOTBLANK([重量1]),
  ISNOTBLANK([回数1]),
  ISNOTBLANK([セット1])
)
```

これにより、重量1・回数1・セット1が空欄の場合は、`トレーニング記録` に行が追加されない。

# 27. グループアクションを作成

次に、1〜5行目の追加アクションをまとめて実行するグループアクションを作った。

ここで、

> New Actionを作るのは筋トレ一括入力に対してですか？

という確認があり、答えはYESだった。

理由は、グループアクションは `筋トレ一括入力` の1件のデータをもとに、1〜5行目の追加アクションを順番に実行するため。

作成したグループアクションは以下。

```text
Action name：一括入力_トレーニング記録へ追加
For a record of this table：筋トレ一括入力
Do this：Grouped: execute a sequence of actions
```

実行するアクションとして、以下を順番に設定した。

```text
一括入力_1行目を追加
一括入力_2行目を追加
一括入力_3行目を追加
一括入力_4行目を追加
一括入力_5行目を追加
```

各個別アクションに `Only if this condition is true` が入っているため、空欄行は追加されない。

# 31. 見た目改善の候補として、ページ区切りと親子テーブルを比較した

入力UIを見やすくする案として、以下の2つを比較した。

```text
A. ページ区切り方式
B. 親子テーブル方式
```

## A. ページ区切り方式

今の `筋トレ一括入力` テーブルをそのまま使い、フォーム内をページで分ける。

例：

```text
ページ1：基本情報
・記録日
・種目

ページ2：1〜2行目
・重量1
・回数1
・セット1
・補足1
・重量2
・回数2
・セット2
・補足2

ページ3：3〜5行目
・重量3
・回数3
・セット3
・補足3
...
```

メリット：

```text
今の一括入力テーブルを使える
今作ったアクションもほぼそのまま使える
日付と種目は最初の1回だけ入力
最後に保存すれば複数行が追加される
開発が比較的簡単
```

デメリット：

```text
画像のような横並び表形式にはならない
```

## B. 親子テーブル方式

親テーブルと子テーブルに分ける。

親：

```text
筋トレ一括入力
・一括ID
・記録日
・種目
```

子：

```text
筋トレ一括入力明細
・明細ID
・一括ID
・重量
・回数
・セット
・補足
```

メリット：

```text
重量1、重量2、重量3…という列を増やさなくてよい
5行制限がなくなる
1種目に何行でも明細を追加できる
データベース設計としてはきれい
```

デメリット：

```text
設定が難しくなる
Ref、IsPartOf、親子関係を使う必要がある
今作った5行分アクションは作り直し寄りになる
```

# 32. 次はページ区切り方式で進めることにした

最終的に、次の方針になった。

```text
今の一括入力機能は成功している
大きく作り替えず、まずはフォームの見た目だけ改善したい
そのため、ページ区切り方式で進める
```

ページ区切り方式なら、開発難易度が低く、今の仕組みを壊さずに済む。

次にやる予定だったのは、`筋トレ一括入力` テーブルに `Show` 型の仮想列を追加してページ区切りを作ること。

最初に追加する予定だった仮想列は以下。

```text
Column name：ページ_基本情報
Type：Show
Category：Page_Header
Content：基本情報
```

これにより、フォーム内で、

```text
基本情報
記録日
種目
```

のようなページ区切りを作る想定だった。
