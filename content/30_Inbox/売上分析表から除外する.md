ここまでの会話は、単に「除外企業一覧をどう作るか」という話から始まり、最終的には **Power Queryによる売上分析を制御するExcelマスタの設計方針と、Power Queryの命名規則**まで整理してきました。

## 1. そもそもの目的

Power Queryで売上分析を作成する際、元の売上データをそのまま全部分析するのではなく、

- 特定の得意先を除外する
    
- 特定の商品・アイテムを除外する
    
- 特定の営業担当者だけを対象にする
    
- 特定の営業担当者を除外する
    
- 組織単位で対象を決める
    
- 取締役向け分析など、分析目的によって対象範囲を変える
    

といった処理が必要になります。

これらの条件をPower QueryのMコードへ直接書き込むのではなく、**Excel上のマスタとして外部管理し、Power Queryから読み込む**方向で検討しました。

---

# 2. 最初に検討した「対象外得意先マスタ」

最初のテーマは、売上分析から特定企業を除外するための一覧表でした。

当初は次のような構成でした。

|得意先コード|得意先名称|対象外フラグ|
|---|---|--:|
|000001|A社|1|
|000002|B社|0|

Power Query側では、

> `対象外フラグ = 1` の得意先を売上分析から除外する

という使い方を想定していました。

ただし問題として、

**「0と1のどちらが除外なのか、一覧を見ただけでは分からない」**

という点が出てきました。

---

# 3. 「対象外フラグ」という設計の見直し

最初は「除外ステータス」という名称も候補にしましたが、これにも問題があります。

たとえば、

|除外ステータス|
|---|
|有効|
|除外|

とすると、

> 「有効」とは得意先が分析対象として有効なのか？  
> それとも「除外設定が有効」なのか？

という別の曖昧さが発生します。

そこで、**否定形の「除外」を基準にするより、「分析対象かどうか」を基準にした方が理解しやすい**という方向になりました。

たとえば、

|得意先コード|得意先名称|分析対象|
|---|---|---|
|000001|A社|対象|
|000002|B社|対象外|

という設計です。

これなら、

- `対象` → 売上分析に含める
    
- `対象外` → 売上分析から除外
    

と、人間がExcelを直接見ても意味を理解できます。

将来的な保守を考えても、0/1だけを記録するより分かりやすい設計です。

---

# 4. 分析ごとにマスタを分けるか、一つにまとめるか

次に、

- 特定営業マン向け売上分析
    
- 組織別売上分析
    
- 取締役向け売上分析
    

など、複数の売上分析が存在する場合に、

**マスタファイルそのものを分析ごとに分けるべきか**

を検討しました。

たとえば、

```text
SalesmanAnalysisMaster.xlsx
OrganizationAnalysisMaster.xlsx
DirectorAnalysisMaster.xlsx
```

のように分割する方法です。

しかし、この方法では同じ得意先や商品について複数ファイルで管理する可能性があり、

- 更新漏れ
    
- マスタ間の不整合
    
- 重複管理
    
- どのファイルが正しいのか分からなくなる
    

といった問題が起こりやすくなります。

そのため、基本方針としては、

> **マスタファイルは集約する**

という方向を推奨しました。

---

# 5. 「1ファイル・複数シート」という構成

そこで出てきたのが、

**一つのExcelファイルに集約し、用途ごとにシートを分ける**

という方式です。

これは今回の用途との相性がかなり良いです。

概念的には、

```text
SalesAnalysisMaster.xlsx
│
├─ 対象外得意先
├─ 対象外商品
├─ 営業担当者
├─ 組織
├─ 取締役
├─ 個別分析条件
└─ その他の分析条件
```

のようにします。

つまり、

> ファイル単位では「売上分析を制御するマスタ」

として一元管理し、その中をシート単位で役割分担する

という考え方です。

---

# 6. マスタファイル名

いくつか候補を挙げました。

- `SalesAnalysisMaster.xlsx`
    
- `ExclusionInclusionMaster.xlsx`
    
- `AnalysisControlMaster.xlsx`
    

この中では、現在実際に使用しているコードからも、

**`SalesAnalysisMaster.xlsx`**

が最も自然です。

理由は、このファイルが単なる「除外リスト」ではなく、

- 除外
    
- 対象指定
    
- 営業担当者指定
    
- 得意先指定
    
- 組織指定
    
- 分析条件
    

など、**売上分析全般のマスタへ発展する可能性があるため**です。

`ExcludedCompanies.xlsx` のような名前にすると、将来「対象営業担当者一覧」などを追加したときにファイル名と実態が合わなくなります。

---

# 7. 「対象」と「除外」を別シートにする案

途中では、

```text
ExcludedCompanies
ExcludedSalesmen
IncludedCompanies
IncludedSalesmen
```

のように、対象・除外をそれぞれ別シートにする案も出しました。

ただし、現在の用途を考えると必ずしも「対象」と「除外」という概念だけでシートを分ける必要はありません。

むしろ、

**「何についてのマスタなのか」でシートを分け、その中で分析対象を管理する**

方が拡張しやすいです。

たとえば、

```text
SalesAnalysisMaster.xlsx

├─ Customers
├─ Products
├─ SalesReps
├─ Organizations
└─ Directors
```

として、各テーブルに必要な管理項目を持たせる方法です。

一方で「水岡担当分だけを抽出する得意先一覧」のように、明確に用途が限定されたリストについては専用シートにしても構いません。

---

# 8. 現在実際に使用しているマスタ

会話の後半では、実際に次のファイルをPower Queryから読み込むコードが出てきました。

```text
C:\Users\SAMPLE_REDACTED\data_files\master\SalesAnalysisMaster.xlsx
```

つまり現在の構成では、

**ファイル名**

```text
SalesAnalysisMaster.xlsx
```

を採用しています。

そして、このファイル内に

```text
mizuoka
```

というシートが存在しています。

このシートには、

|得意先コード|得意先名|担当者名|
|---|---|---|
|...|...|...|

というデータが入っています。

したがってこれは、

> 水岡担当者に関連する得意先を特定するためのマスタ

という役割を持っていると考えられます。

---

# 9. 最初のPower Queryコード

元々のコードは次の構成でした。

```powerquery
let
    ソース = Excel.Workbook(File.Contents("C:\Users\SAMPLE_REDACTED\data_files\master\SalesAnalysisMaster.xlsx"), null, true),
    担当者マスタ_Sheet = ソース{[Item="mizuoka",Kind="Sheet"]}[Data],
    昇格されたヘッダー数 = Table.PromoteHeaders(担当者マスタ_Sheet, [PromoteAllScalars=true]),
    変更された型 = Table.TransformColumnTypes(昇格されたヘッダー数,{{"得意先コード", type text}, {"得意先名", type text}, {"担当者名", type text}})
in
    変更された型
```

これについて、可読性を上げるためリファクタリングすることになりました。

---

# 10. Power Queryのステップ名を英語化

最初のリファクタリングでは、

```powerquery
Source
SalesmanMasterSheet
PromotedHeaders
ChangedType
```

のようにステップ名を英語化しました。

これはPower Queryのステップ名を、

**「そのステップで何を行っているのか」が分かる名前にする**

ためです。

---

# 11. `_` を利用した命名

その後、ステップ名へ `_` を使用する方針になりました。

一例として、

```powerquery
_Source
_SalesmanMasterSheet
_PromotedHeaders
_ChangedType
```

という形式を提示しました。

ただし、さらにユーザーから、

> 単に `_` を付けるのではなく、「除外」「ソート」「並べ替え」のように処理内容そのものをステップ名に入れたい

という要望がありました。

そこで、最終的には、

```powerquery
_ソース
_シート選択_担当者マスタ
_ヘッダー昇格
_型変換_カラム
```

という形式に変更しました。

---

# 12. 現時点のPower Queryコード

ここまでのルールを反映したコードがこちらです。

```powerquery
let
    // ソースファイルの読み込み
    _ソース = Excel.Workbook(
        File.Contents("C:\Users\SAMPLE_REDACTED\data_files\master\SalesAnalysisMaster.xlsx"),
        null,
        true
    ),

    // 担当者マスタのシートを選択
    _シート選択_担当者マスタ =
        _ソース{[Item="mizuoka", Kind="Sheet"]}[Data],

    // 1行目をヘッダーとして昇格
    _ヘッダー昇格 =
        Table.PromoteHeaders(
            _シート選択_担当者マスタ,
            [PromoteAllScalars=true]
        ),

    // 各カラムのデータ型を設定
    _型変換_カラム =
        Table.TransformColumnTypes(
            _ヘッダー昇格,
            {
                {"得意先コード", type text},
                {"得意先名", type text},
                {"担当者名", type text}
            }
        )
in
    _型変換_カラム
```

---

# 13. ステップ命名について決まってきた考え方

今回のやり取りから、Power Queryのステップ名については次の考え方になっています。

単純な、

```text
変更された型
フィルターされた行
並べ替えられた行
削除された列
```

というPower Queryの自動生成名ではなく、

**「何をしたか」＋必要なら「何に対してしたか」**

を明示します。

たとえば、

```text
_シート選択_担当者マスタ
_ヘッダー昇格
_型変換_カラム
_除外_対象外得意先
_除外_対象外商品
_抽出_営業担当者
_ソート_売上金額降順
_並べ替え_カラム
_削除_不要カラム
_追加_分析期間
_置換_得意先名称
```

といった命名です。

この方式なら、詳細エディターを開いたときにも処理の流れを追いやすくなります。

---

# 14. 今回のマスタ設計を整理すると

現時点では、全体を次のように捉えるのが分かりやすいです。

```text
data_files
└─ master
   └─ SalesAnalysisMaster.xlsx
      │
      ├─ 得意先関係
      │   ├─ 対象外得意先
      │   └─ 特定分析用得意先
      │
      ├─ 商品関係
      │   └─ 対象外商品
      │
      ├─ 営業担当者関係
      │   ├─ mizuoka
      │   └─ その他担当者
      │
      ├─ 組織関係
      │
      └─ その他分析条件
```

実際のシート構成は今後の分析方法に応じて決めればよく、重要なのは、

**「売上分析ごとにExcelファイルを乱立させる」のではなく、「SalesAnalysisMaster.xlsxを売上分析条件の中央管理場所にする」**

という考え方です。

---

## 15. 今後改善するなら重要なポイント

ここまでの設計から、次に手を入れる価値が高いのは**「シートを直接Power Queryから読む方式」から「Excelテーブルを読む方式」への変更**です。

現在は、

```powerquery
[Item="mizuoka", Kind="Sheet"]
```

としているので、シート全体を読み込んでからヘッダーを昇格しています。

マスタとして本格運用するなら、Excel側で各一覧をテーブル化して、

```text
シート名：mizuoka
テーブル名：MstSalesRepCustomers
```

などとしたうえで、

```powerquery
[Item="MstSalesRepCustomers", Kind="Table"]
```

として読み込む方が安定します。

これなら余計なセルを読み込みにくく、行が追加されてもテーブル範囲が自動拡張されます。また、テーブルには最初から列名が存在するので、`Table.PromoteHeaders` 自体も不要にできます。

つまり今後は、

**SalesAnalysisMaster.xlsx → 用途別シート → シート内のExcelテーブル → Power Query**

という構造にすると、かなり管理しやすい売上分析基盤になりそうです。
