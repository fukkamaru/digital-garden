# 読書ストラクチャーをNDCカードと横スクロールで運用する

Quartzで公開しているデジタルガーデンに、積読回避を目的とした読書ノートを掲載するようになった。

読書ノートは、もともとKindle本の管理に使っていたNDCに合わせて分類する。

単に読了記録を残すのではなく、

> とにかく本を開いて読む状態を作り、それを日常化する

ことを優先する。

そのため、1冊あたりの読書量は意図的にかなり減らし、多くの本を短時間で回す。必要なら音読し、その内容をAIに要約させるほど読書単位を小さくする。

---

## 読書ストラクチャーの初期構成

当初は、サイトホームで使用していたカード型の箇条書きCSSを、そのまま読書ストラクチャーにも流用した。

ホームでは、

```scss
article #home-navigation {
  display: none;
}

article #home-navigation + ul {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 1rem;

  padding-left: 0;
  list-style: none;
}

article #home-navigation + ul > li {
  padding: 1rem 1.2rem;

  border: 1px solid var(--lightgray);
  border-radius: 8px;

  list-style: none;
}

article #home-navigation + ul > li > ul {
  margin-top: 0.75rem;
}

@media (max-width: 700px) {
  article #home-navigation + ul {
    grid-template-columns: 1fr;
  }
}
```

としていた。

このデザインを読書ストラクチャーにも流用すると、

```text
┌ 019：図書館・図書館学 ───────────┐
│ ・正しい本の読み方               │
│ ・忘れる読書                     │
│ ・100冊で耕す                    │
└───────────────────────────────┘

┌ 100：哲学 ─────────────────────┐
│ ・スマホ時代の哲学               │
└───────────────────────────────┘
```

のようになり、通常の長い箇条書きより視認性はかなりよかった。

カードは、

- NDC分類
- その中に属する読書ノート

というまとまりを視覚的に表現できる。

そのため、ホーム用デザインの単なる流用ではなく、

> カード = 関連項目を一つの構造単位として見せるUI

としてQuartz全体で再利用できる形になった。

---

## 問題：読書ノートが増えるほど縦長になる

2列カード自体は見やすいが、読書ノートを追加していくと個別NDC分類も増えていく。

例えば、

```text
019
100
141
147
159
290
397
487
489
501
549
596
694
721
726
748
783
798
810
816
902
933
...
```

というカードが増え続ける。

つまり、

> NDC分類が増える  
> → カードが増える  
> → ページが下方向へ伸びる

という構造になる。

読書数を増やすこと自体が目的なのに、増えれば増えるほどストラクチャーノートが扱いにくくなる。

そこで、NDCの100番台単位を利用して表示構造そのものを変更することにした。

---

## 採用した構造

NDCを、

```text
000–099
100–199
200–299
300–399
400–499
500–599
600–699
700–799
800–899
900–999
未分類
```

に分ける。

表示上は、

- 縦軸：NDCの100番台
- 横軸：その100番台に属する個別NDC
- カード内部：読書ノート

とする。

例えば、

```text
000–099
[019 図書館・図書館学]

100–199
[100 哲学] [141 心理学] [147 超心理学] [159 倫理学] →

200–299
[290 地理] →

300–399
[397 国防・軍事] →

700–799
[721 日本画] [726 マンガ] [748 写真] [783 スポーツ] [798 娯楽] →
```

という配置になる。

カードが本文幅を超えた場合だけ、そのNDCグループ内を横スクロールする。

---

## なぜ100番台を縦、個別NDCを横にしたか

逆に、

```text
000–099 | 100–199 | 200–299 | 300–399 | ...
   ↓         ↓         ↓
 019       100       290
           141
           147
           159
```

と、100番台そのものを横方向に配置する案も考えられる。

しかしこの場合、特定のジャンルに読書が集中すると、その列だけ下方向へ伸びる。

例えば100番台が増えれば、

```text
100–199
100
104
121
130
140
141
146
147
150
159
...
```

となる。

今回解決したいのは縦方向への成長なので、この構造では根本的な解決にならない。

一方、

```text
100–199
[100] [104] [121] [130] [140] [141] [146] [147] [150] [159] →
```

とすれば、分類が増える方向を横へ逃がせる。

ページ全体の高さを決めるのが、

> 個別NDC分類の数

ではなく、

> NDC100番台のグループ数

になる。

そのため、こちらを採用した。

## Markdown構造

読書ストラクチャー専用の見出しキーとして、

```markdown
## reading-navigation
```

を使用する。

Markdownは次の構造になる。

```markdown
## reading-navigation

- 000-099
  - 019：図書館. 図書館学
    - [[正しい本の読み方]]
    - [[忘れる読書]]

- 100-199
  - 100：哲学
    - [[スマホ時代の哲学]]
  - 141：心理学
    - [[観察力の鍛え方]]
  - 147：
    - [[パワーストーンの教科書]]
  - 159：倫理学. 道徳
    - [[移動する人は成功する]]

- 200-299
  - 290：
    - [[楽園＆秘境]]
    - [[世界の聖地]]
```

階層としては、

```text
NDC100番台
└─ 個別NDCカード
   └─ 読書ノート
```

になる。

---

## `#home-navigation` から分離する

もともとはホーム用の、

```scss
#home-navigation
```

をそのまま流用していた。

しかし、ホームと読書ストラクチャーではレイアウト上の役割が異なる。

| 用途 | キー | レイアウト |
|---|---|---|
| サイトホーム | `#home-navigation` | 2列グリッド |
| 読書ストラクチャー | `#reading-navigation` | NDCグループごとの横スクロール |

そのため、読書用には、

```scss
#reading-navigation
```

を新設する。

これにより、今後ホーム側だけ、あるいは読書側だけを変更しても相互に影響しない。

---

## 読書ストラクチャー用SCSS

```scss
/* =========================================================
   Reading Structure
   ========================================================= */

article #reading-navigation {
  display: none;
}


/* ---------------------------------------------------------
   NDC 100区分
   000–099 / 100–199 / ...
   --------------------------------------------------------- */

article #reading-navigation + ul {
  padding-left: 0;
  list-style: none;
}

article #reading-navigation + ul > li {
  margin-bottom: 1.5rem;
  list-style: none;
}


/* ---------------------------------------------------------
   各NDC範囲のカード列
   --------------------------------------------------------- */

article #reading-navigation + ul > li > ul {
  display: flex;
  gap: 1rem;

  margin-top: 0.75rem;
  padding: 0 0 0.75rem;

  overflow-x: auto;
  overflow-y: hidden;

  list-style: none;

  -webkit-overflow-scrolling: touch;
}


/* ---------------------------------------------------------
   個別NDCカード
   019 / 100 / 141 / 147 / ...
   --------------------------------------------------------- */

article #reading-navigation + ul > li > ul > li {
  flex: 0 0 20rem;

  padding: 1rem 1.2rem;

  border: 1px solid var(--lightgray);
  border-radius: 8px;

  list-style: none;
}


/* ---------------------------------------------------------
   カード内の読書ノート一覧
   --------------------------------------------------------- */

article #reading-navigation + ul > li > ul > li > ul {
  margin-top: 0.75rem;
}


/* ---------------------------------------------------------
   Mobile
   --------------------------------------------------------- */

@media (max-width: 700px) {
  article #reading-navigation + ul > li > ul > li {
    flex-basis: min(18rem, 85vw);
  }
}
```

実装済み。

## カード幅は固定仕様にしない

現在は、

```scss
flex: 0 0 20rem;
```

としている。

ただし、20remを正解と決める必要はない。

運用しながら、

```scss
18rem
20rem
22rem
```

などを試す。

概ね、

- 狭い → 一度に多くのカードが見える
- 広い → 長い書名が読みやすい

というトレードオフになる。

必要なら将来的に、

```scss
flex: 0 0 clamp(18rem, 30vw, 22rem);
```

のような可変幅も検討できる。

現時点では、固定値の方が挙動を把握しやすいため、実データを見ながら随時調整する。

# 読書量をNDCグループ単位でゲーム化する

読書ストラクチャーをNDC別に表示したことで、単なる分類だけでなく、読書量そのものを可視化できるようになった。

ある時点での100番台ごとの読書ノート数は、

```text
000  ████████   8
100  ████       4
200  ██         2
300  █          1
400  ██         2
500  ███        3
600  █          1
700  █████████  9
800  ██         2
900  ███████    7
```

となっていた。

かなり歪な形になっている。

しかし、この歪さを欠点ではなく、読書のモチベーションに利用する。

---

## 読書の目的

現段階では、

> 一冊を深く読む

ことよりも、

> とにかく本を読む行為そのものを大量に発生させる

ことを優先する。

そのため、

- 一冊あたりの読書時間を短くする
- 一冊を読み切る必要はない
- 短時間で多冊数を回す
- 音読してAIに要約させてもよい
- 気になった本だけ後から再読・精読する

という運用にする。

これは通常の「読了冊数競争」ではなく、

> 本への接触回数を増やすための習慣形成

として考える。

---

## 少ないグループを底上げする

例えば15冊読む場合、現在の分布なら、

| NDC | 現在 | 追加例 | 結果 |
|---|---:|---:|---:|
| 000 | 8 | 0 | 8 |
| 100 | 4 | 0 | 4 |
| 200 | 2 | +2 | 4 |
| 300 | 1 | +3 | 4 |
| 400 | 2 | +2 | 4 |
| 500 | 3 | +1 | 4 |
| 600 | 1 | +3 | 4 |
| 700 | 9 | 0 | 9 |
| 800 | 2 | +2 | 4 |
| 900 | 7 | 0 | 7 |

とすれば、13冊で少ないグループをすべて4冊まで引き上げられる。

残り2冊は自由枠にする。

結果は、

```text
000  ████████   8
100  ████       4
200  ████       4
300  ████       4
400  ████       4
500  ████       4
600  ████       4
700  █████████  9
800  ████       4
900  ███████    7
```

となる。

グラフがかなり整う。

---

# 「整える → 歪ませる」を繰り返す

常に均等なグラフを目指す必要はない。

むしろ、

```text
歪な状態
   ↓
凹んだグループを読む
   ↓
グラフを整える
   ↓
好きな本を大量に読む
   ↓
意図的にグラフを歪ませる
   ↓
また整える
   ↓
また歪ませる
```

という循環にする方が、飽きにくい。

---

## 整地ターン

少ないNDCグループを重点的に読む。

目的は、

> 全体の最低ラインを一段上げる

こと。

例えば、

```text
全グループ1冊以上
↓
全グループ4冊以上
↓
全グループ5冊以上
↓
全グループ6冊以上
↓
...
```

と床を少しずつ上げる。

均等なグラフを完成させること自体が目的ではない。

「へこんでいる部分を埋める」という短期目標として利用する。

---

## 開拓ターン

グラフがある程度整ったら、冊数を気にせず読みたい本を読む。

例えば、

```text
700 +7
400 +5
900 +3
```

のような偏った配分でもよい。

むしろ、意図的に偏らせる。

すると新しい凹凸が生まれる。

```text
読む
↓
グラフが歪む
↓
今度は別のNDCが相対的にへこむ
↓
また整えたくなる
```

となり、次の読書動機が自動的に生成される。

---

## 偏りを失敗扱いしない

通常なら、

> 700番台ばかり読んでしまった

ことを偏りとして問題視しがち。

しかし、この運用では、

> 700番台が伸びた  
> → 次の整地ターンの課題が生まれた

と考える。

逆に、グラフが整ったら、

> また自由に崩してよい

とする。

つまり、

> 偏ることも、均すことも、両方が進捗

になる。

---

## グラフを完成させない

完全に均等なグラフを最終目標にすると、

```text
完成
↓
次に何をするか分からない
```

となる。

そこで、完成形そのものを設定しない。

```text
整える
↓
崩す
↓
整える
↓
崩す
```

を繰り返す。

読書ストラクチャーは、単なる読書記録ではなく、

> 次にどの本を読むかを決めるゲーム盤

として扱う。

---

## NDC分類そのものが飽き防止になる

例えば、

```text
300 社会科学
↓
600 産業
↓
800 言語
↓
400 自然科学
```

のようにジャンルを飛びながら読むと、内容そのものも大きく変わる。

そのため、

> 同じ読書という行為を続けながら、読む対象から受ける刺激は変化させる

ことができる。

これは、多冊数を回す読書法と相性がよい。

---

# 未分類・電子書籍の扱い

ストラクチャーには、

```text
xyz
├─ 999：不明
└─ 999：電子書籍のみ
```

という項目もある。

ただし、

- NDC不明 → 分類状態
- 電子書籍のみ → 媒体

なので、本来は別軸。

NDC読書グラフについては、000–999の10グループだけを対象にする。

`xyz`はゲーム上の冊数比較から除外する。

必要なら今後、

```text
未分類
```

という受け皿として整理する。

---

# 現在の運用方針

読書ストラクチャーは、次の三つの役割を兼ねる。

```text
読書ストラクチャー
│
├─ 読書ノートへのナビゲーション
│
├─ NDC別の読書分布の可視化
│
└─ 次に読む分野を決めるゲーム盤
```

読書行動そのものは、

```text
短時間で読む
↓
読書ノートを作る
↓
NDCへ登録する
↓
グラフが変わる
↓
次に読むジャンルが決まる
```

というフィードバックループにする。

---

## 決定事項

- 読書ノートはNDCで分類する。
- NDC100番台を縦方向のグループとして扱う。
- 個別NDCカードは横方向に配置する。
- 横幅を超えたグループだけ横スクロールさせる。
- 読書ストラクチャー専用に `#reading-navigation` を使用する。
- ホーム用 `#home-navigation` とはCSSを分離する。
- カード幅は暫定 `20rem` とし、随時調整する。
- 読書ストラクチャーの横スクロール化は実装済み。
- 読書初期段階では、一冊あたりの読書量を意図的に減らし、多冊数を回す。
- NDCごとの冊数を可視化し、次に読むジャンル決定に利用する。
- 全グループを恒久的に均等化することは目的としない。
- 「整地ターン」と「開拓ターン」を交互に行う。
- グラフの歪みそのものを次の読書動機として利用する。
- `xyz`などの未分類領域はNDCグラフの集計対象外とする。

## 今後の調整候補

- カード幅
- カード間の余白
- NDCグループ間の縦余白
- 横スクロールバーのデザイン
- モバイル時の表示
- 読書冊数を自動集計してグラフ化する方法
- 読書ノートの「接触」「再読」「精読」などの状態区分
- 未分類・電子書籍のみの分類方法

読書量が増えてから必要になった部分だけ細分化し、現時点では構造を複雑にしすぎない。
