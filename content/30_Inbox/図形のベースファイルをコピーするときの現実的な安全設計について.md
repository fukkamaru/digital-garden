# 1. 元々やりたいこと

## 前提

### ファイルA

図形が大量に配置されている。

```
□ □ □□ □ □□ □ □
```

重要なのは

- 配置位置
- サイズ
- レイアウト

である。

---

### ファイルB

デザイン済み図形が1個ある。

```
★
```

この図形には

- 塗りつぶし
- 線
- グラデーション
- 影
- テキスト
- SVG
- 装飾

などが設定されている。

---

## やりたいこと

Aにある全図形を

```
□ → ★
```

へ置換したい。

ただし

```
位置サイズレイアウト
```

は維持したい。

つまり

```
見た目だけB配置はA
```

という処理。

# 2. VBA（マクロ）での実現方法

## 方法① プロパティ転写

B図形の情報を取得して、

A図形へ適用する方法。

イメージ

```
B ↓色取得線取得影取得文字取得 ↓Aへ設定
```

---

### メリット

- コピー不要
- 削除不要
- 位置変更不要

---

### デメリット

コピー対象が非常に多い。

例えば

- Fill
- Line
- Shadow
- Glow
- Reflection
- Transparency
- Gradient
- Text

など。

さらに

- SVG
- SmartArt
- グループ図形

などになると難しくなる。

---

## 方法② 図形そのものを置換

こちらが当初イメージしていた方法。

流れ

```
Aの位置取得 ↓A削除 ↓B複製 ↓同位置へ移動
```

---

### メリット

Bが持つデザインを100%利用できる。

プロパティ転写不要。

---

### デメリット

コピー処理が必要になる。

# 3. VBA実行中のユーザー操作問題

ここが本題。

## 最初の疑問

マクロ実行中に

- ブラウザを見る
- Excelを触る
- Wordを触る

## 結論

「場合による」

---

### 危険なコード

```
Selection.CopySelection.Paste
```

や

```

```

---

理由

マクロは

```
現在選択中現在アクティブ
```

を前提としている。

---

ユーザーが

```
別ウィンドウをクリック
```

すると

```
SelectionActiveWindow
```

が変化する。

結果

```
エラーコピー失敗貼付失敗
```

が発生し得る。

---

## 本質的な問題

途中から話が整理されて、

実際には

> ブラウザを触る

ではなく

> ユーザーがPCを普通に使いながら裏で処理できるのか

が知りたかった。

# 4. Office操作型の限界

ここで重要な話になった。

---

## VBA

VBAは

```
Excelを開くWordを開く
```

前提。

---

つまり

```
画面上のOffice
```

を操作している。

---

実態としては

```
人間の代わりにOfficeを触るロボット
```

に近い。

---

そのため

完全なバックグラウンド処理とは言い難い。

---

## Pythonでも同じ

例えば

- pywin32
- COM

を使う場合

内部的には

```
Excel.ApplicationWord.Application
```

を操作している。

---

つまり

```
VBA↓Python COM
```

になっただけ。

本質は同じ。

---

だから

```
Pythonだから裏で安全
```

ではない。

# 5. Duplicateという改善策

コピー＆ペーストより良い方法。

---

通常

```
Shape.CopyShape.Paste
```

を使う。

---

しかしExcelには

```
Shape.Duplicate
```

がある。

---

イメージ

```
コピー↓貼付
```

ではなく

```
複製↓移動
```

である。

---

メリット

- クリップボード不要
- 高速
- 安定

---

今回の用途なら

```
B取得 ↓A位置保存 ↓BをDuplicate ↓位置移動 ↓A削除
```

が最も現実的。

---

# 6. Officeファイル直接編集方式

ここから興味本位の話。

---

## Officeファイルの正体

実は

```
.xlsx.docx.pptx
```

は

ZIPファイルである。

---

例えば

```
sample.xlsx
```

↓

```
sample.zip
```

へ変更すると中が見える。

---

中身

```
XML画像リレーション情報
```

の集合体。

---

# 7. Officeを開かず編集する方式

この方式では

```
Excel起動しないWord起動しない
```

---

代わりに

```
ZIP展開 ↓XML編集 ↓再圧縮
```

を行う。

---

メリット

完全バックグラウンド。

ユーザーが

- ブラウザ
- メール
- Teams
- Excel

を触っていても影響を受けにくい。

---

# 8. VBAでも可能か

---

VBAでも

- ZIP操作
- XML操作

はできる。

---

ただし非常に面倒。

実務ではほぼやらない。

# 9. Pythonならどうか

Pythonは得意。

代表例

- python-docx

---

そのため

文字列や表の差し替えなら非常に向いている。

# 10. 図形置換だけは別格に難しい

今回のケース。

---

セル値置換なら簡単。

```
A1↓書換
```

だけ。

---

しかし図形は違う。

図形1個でも

```
位置サイズ回転テキストスタイルグラデーション影描画情報
```

など多数のXMLで構成される。

---

そのため

```
B図形↓A図形へ置換
```

をOfficeを開かずにやるのはかなり難しい。

---

# 最終結論

今回の要件

> Bのデザイン済み図形でAの大量図形を置換し、位置は維持したい

に対しては、

### 現実的な方法

```
Excel/Wordを開く↓B図形を取得↓Duplicate↓A位置へ移動↓A削除
```

が最も簡単で保守しやすい。

---

### 理論上可能な方法

```
Officeファイルを直接編集↓DrawingML(XML)を書換↓図形置換
```

も可能。

ただし難易度はかなり高い。

---

したがって実務的には、

**「Office操作型でDuplicateを使い、Select・Activate・Clipboard依存を減らす」**

のが、安定性・開発工数・保守性のバランスが最も良い、というところまで話が整理されました。
