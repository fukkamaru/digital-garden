# サムネイル制作で生じた用語と成果物の認識ずれ

Cluster 04では、制作の方向性そのものは次第に定まった一方、AIへ何を作らせるのかを表す言葉が定まらず、会話と成果物の認識がずれる場面があった。このノートは、その事実を記録するものであり、現在の用語を定義するノートではない。

## 当時の呼び方と後から現れた言葉

当時の記録には「デザインフレーム」「設計図」「設計書」といった呼び方が出てくる。これらは、構図だけを求めるのか、HTMLで完成表示するものを求めるのか、HTMLと素材を次のAIへ渡すための説明を求めるのかを、常に一意には示していなかった。

「ワイヤーフレーム」「デザインカンプ」といった語は、主にAIの説明または後日の整理で現れた。したがって、過去の記録を現在の用語だけで読み替えると、ユーザーが当時からその区別を理解して指示していたように見えてしまう。

## 記録から読める影響

| 認識を合わせる必要があったこと | 記録上の展開 |
| --- | --- |
| HTMLを何のために作るのか | HTMLと素材をAIへ渡し、完成画像を生成させる初期方式を試した。 |
| AIがどこまで仕様を守るのか | 素材・文字・座標・余白がAIにより再解釈され得ることが問題になった。 |
| 完成画像をどこで組み立てるのか | ローカルHTML/CSSで実素材を読み込み、表示を固定する方向を検討した。 |
| 画像を後からどう編集するのか | DevToolsによる書き出し、Canva・Figma・SVGの試行へ進んだ。 |

これは、用語だけが原因だったと結論づけるものではない。AIの出力特性、素材の扱い、書き出し方法、制作工程の負荷も重なっていた。用語のずれは、その複数の課題の一つとして扱う。
