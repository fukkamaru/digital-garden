# AI生成方式からローカルHTML/CSS方式へ切り替えた判断

## このノートの位置づけ

これは、HTMLと素材をAIへ渡して完成画像を生成させる方式から、HTMLをローカルで開いて実素材を所定位置へ配置する方式へ切り替えた判断記録である。AIからの説明と制作上の比較を受けて出した当時の結論であり、製品機能や一般則を証明する資料ではない。

本文で使う「デザインフレーム」は当時の呼称として残す。現在の用語では、構図の骨組みはワイヤーフレーム、実素材を読み込んで完成表示するものはHTML/CSSレイアウトテンプレートと区別する。詳細は[[wireframe-layout-template-terminology]]を参照する。

サムネイル製作をHTML形式の設計書から作る場合、デザインフレームとして機能する設計書に素材を差し込むのと、AIに設計書と素材のどちらも渡して作ってもらう2つの選択肢がある。

その違いは下表のとおり。

| 項目          | デザインフレーム → 画像差し込み | 設計書+素材 → AIが完成画像生成 |
| ----------- | ----------------- | ------------------ |
| 設計再現性       | ◎ ほぼ固定            | △ AIが解釈する          |
| 文字の正確さ      | ◎ HTMLテキスト        | △ 誤字・崩れの可能性        |
| 座標・余白       | ◎ px単位で固定         | △ 微妙にズレる           |
| ブランド統一      | ◎ 統一しやすい          | △ 毎回変動             |
| 同シリーズ量産     | ◎                 | △                  |
| 修正          | ◎ CSSや素材差替え       | △ 再生成ガチャになりやすい     |
| 写真の自然な合成    | ○                 | ◎                  |
| デザインの偶発的な発見 | △                 | ◎                  |
| 再現可能性       | ◎                 | △                  |
| 自動化         | ◎                 | ○                  |

この2択なら、サムネイルの製作工程としては「デザインフレームに素材を差し込む方式」の方が優れている。理由は、サムネイルの「デザインを考える工程」と「完成画像を組み立てる工程」を分離できるから。

特に、最大の違いは、AI生成では毎回「設計→解釈→再構築」が発生すること。

たとえば設計書に、

> 見出し X=180 / Y=240 / 幅=1600px  
> 施工写真は右60%  
> 黄色帯は左下  
> フォントサイズ220px

と書いても、生成AIはこれを「制約」ではなく、かなりの部分を「指示」として解釈するため、似たような別の画像を作り出してしまう。
