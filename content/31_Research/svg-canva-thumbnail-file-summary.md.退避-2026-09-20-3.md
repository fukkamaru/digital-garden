# 縞鋼板サムネイルのSVGを観察した記録

## 観察したファイル

対象は「縞鋼板の防滑性向上に『塗る』すべり止め材.svg」。完成サムネイルを一枚画像として扱うのではなく、文字・図形・写真・色・配置がどこまで残っているかを確認した。

## 確認できた構造

| 要素 | 確認できたこと |
| --- | --- |
| キャンバス | 3840×2160px |
| 写真 | 主施工写真とテクスチャ写真がPNGとしてSVG内へ埋め込まれていた。 |
| テキスト | コピーは`<text>`要素として残っていた。 |
| 図形・効果 | グラデーション、帯、影などがSVGの要素として残っていた。 |
| 構造 | Figma由来と思われるグループ名・階層が一部残っていた。 |

このため、このSVGはPNGよりも制作時の情報を多く含む一方、Figmaの編集データそのものではない、と理解した。

## CanvaとSVGについて当時確認したこと

CanvaへSVGを入れられることと、Figmaのレイヤー構造が完全に同じ形で編集できることは別だった。テキスト、埋め込み画像、グラデーション、フィルターなどを含むSVGでは、どの要素まで編集可能な状態で読み込まれるかを、実際のファイルで確かめる必要があった。

## このノートの結論

- SVGは、完成画像と構成情報の中間にある受け渡し候補として検討した。
- 今回観察したSVGには、文字・座標・色・写真・図形に関する情報が残っていた。
- SVGを渡せば他ソフトやAIで同じように編集できる、とまでは確認していない。
