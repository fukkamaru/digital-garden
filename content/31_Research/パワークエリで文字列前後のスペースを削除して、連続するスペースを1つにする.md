# Power Queryで文字列の前後・連続スペースを整理する

## 目的

Power QueryのM言語で、文字列を次の形へ統一する。

1. 文字列の前後にある空白を削除する
2. 半角スペースを全角スペースへ変換する
3. 連続する全角スペースを1つにまとめる

## 実運用で使用していた関数

~~~powerquery
(old_name as nullable text) as nullable text =>
if old_name = null then
    null
else
    let
        trimmedName = Text.Trim(old_name),
        normalizedSpaces = Text.Replace(trimmedName, " ", "　"),
        parts = List.Select(
            Text.Split(normalizedSpaces, "　"),
            each _ <> ""
        ),
        result = Text.Combine(parts, "　")
    in
        result
~~~

## 処理内容

| 処理 | 使用する関数 | 内容 |
| --- | --- | --- |
| 前後の空白を削除 | Text.Trim | 文字列の先頭と末尾を整える |
| 半角から全角へ変換 | Text.Replace | 半角スペースを全角スペースへ置換する |
| 全角スペースで分割 | Text.Split | 文字列をリストへ分ける |
| 空要素を除外 | List.Select | 連続スペースによってできた空文字を除く |
| 1つの全角スペースで結合 | Text.Combine | リストを文字列へ戻す |

## 入出力例

| 入力 | 出力 |
| --- | --- |
| 「　京藤　康恵　」 | 「京藤　康恵」 |
| 「京藤　　康恵」 | 「京藤　康恵」 |
| 「京藤 康恵」 | 「京藤　康恵」 |

## 元コードからの修正点

元のコメントでは「正規表現で置換」と説明していたが、この処理は正規表現を使用していない。文字列をスペースで分割し、空要素を除外してから再結合している。

また、Text.SplitAnyへ区切り文字を1種類だけ渡す場合は、Text.Splitで意図を表現できる。

## 注意点

- nullを受け取る可能性がある列に対応するため、nullable textとnull判定を追加した
- タブや改行なども統一したい場合は別処理が必要
- 半角スペースを残したい場合は、置換文字と結合文字を半角へ変更する
- 列全体へ適用する前に、想定外の空白文字がないかサンプルで確認する

## 空白種別を明示する場合の推奨例

上の関数は、半角・全角スペースを全角スペース1つにそろえる実運用の記法として残す。タブや改行も「空白」として同じ扱いにする要件がある場合は、対象文字を明示した関数にする。

```m
(value as nullable text) as nullable text =>
if value = null then
    null
else
    let
        whitespaceCharacters = {" ", "　", "#(tab)", "#(lf)", "#(cr)"},
        trimmed = Text.Trim(value, whitespaceCharacters),
        unified = List.Accumulate(
            whitespaceCharacters,
            trimmed,
            (state, current) => Text.Replace(state, current, "　")
        ),
        parts = List.Select(Text.Split(unified, "　"), each _ <> ""),
        result = Text.Combine(parts, "　")
    in
        result
```

この例では、対象にする文字を`whitespaceCharacters`へ限定している。何を正規化したのかを後から説明でき、タブや改行を残すべき列へ誤って適用することを防ぐためである。

運用は、次の順序にする。

1. `Raw`の元列を変更せずに保持する。
2. 対象列・対象とする空白文字・出力する空白文字を決める。
3. テスト入力と期待値を確認してから、`Standard`の新しい列へ関数を適用する。
4. 期待値と異なる行は例外一覧へ分け、置換前の値とともに確認する。

この順序なら、整形規則を後で変えても元データと比較できる。データ層の使い分けは[[kyoto-patty-029-sample-business|Kyoto Patty 029の架空事業設定とデータ設計]]を参照する。
