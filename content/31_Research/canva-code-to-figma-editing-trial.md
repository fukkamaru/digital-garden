# Canva CodeからFigmaへ移った編集試行

## 試した目的

ローカルHTMLで表示したサムネイルを、コードではなくGUIで編集できる状態にしたかった。必要だったのは、文字・写真・図形を別々に扱い、位置・サイズ・色・フォントを調整できることだった。

## Canva Codeで確認したこと

| 試したこと | 結果 |
| --- | --- |
| 3840×2160のHTMLを読み込む | 固定キャンバスとしては扱えず、表示領域が変化した。 |
| 先に3840×2160のデザインを作ってからHTMLを置く | HTMLを選ぶとCode用の扱いになり、目的の固定配置にはならなかった。 |
| 単純なHTMLの編集 | 文字の変更・色・フォント等は一部操作できた。 |
| 実際のサムネイルHTMLの編集 | 自由な要素移動、図形追加、レイヤー操作などは期待どおりにできなかった。 |

この試行では、Canva CodeはHTMLを通常のデザインレイヤーへ変換して自由編集する用途には合わない、と判断した。

## Figmaで確認したこと

Figmaでは、サムネイルを編集可能な形で扱える可能性を確認した。人が仕上げるための編集マスターとして `.fig` を残し、他のAIやソフトへ構成情報を渡す候補としてSVGを書き出す案を考えた。

| 役割 | 当時考えたデータ |
| --- | --- |
| 人が編集を続ける元データ | `.fig` |
| 他のAI・ソフトへ渡す候補 | SVG |
| 目視確認・最終配布 | PNG / JPEG |

この役割分担は当時の試行から生まれた案であり、現在の機能や互換性を保証しない。実際のSVGに残った情報は[HTMLサムネイル制作：SVG観察記録](html-thumbnail-svg-observation.md)に分けている。

## この試行で残った課題

- HTMLからFigmaへ移した後、HTMLとFigmaのどちらを編集の正本にするか。
- SVGへ書き出したとき、文字・写真・効果・レイヤー名がどこまで残るか。
- Canvaや別のAIへ渡したとき、SVGがどこまで編集可能な状態で扱われるか。
