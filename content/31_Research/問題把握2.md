### まず「何が起きているか」を確定する

最初に見えていた症状は、

> Windowsにログインしたら、いつもの環境ではなくTEMPプロファイルになった

でした。

この段階ではまだ「SSDが悪い」とは考えません。

直接観測できている事実は、

**ユーザープロファイルが正常にロードされていない**

だけです。

したがって最初の問いは、

> なぜWindowsは元のユーザープロファイルを読み込めなかったのか？

になります。

ここから調査を始めます。

---

## 原則1：まず「症状に最も近い層」を調べる

Windows PCをかなり単純化すると、下のような階層になっています。

```
ユーザーから見える症状
        ↓
アプリケーション / ユーザープロファイル
        ↓
Windowsサービス
        ↓
ファイルシステム（NTFS）
        ↓
ストレージドライバ / I/O
        ↓
SSD / HDD
        ↓
物理ハードウェア
```

今回なら、

```
TEMPプロファイル
```

という症状なので、一段下の

```
User Profile Service
```

を見る。

だから最初にイベントビューアーのUser Profile Serviceを調べます。

ここで例えば、

- プロファイルファイルが存在しない
- レジストリのProfileListがおかしい
- アクセス権がおかしい
- NTUSER.DATが読めない

などが出てくれば、その方向を掘ります。

---

# 原則2：「結果」ではなく「原因」を探す

ここが今回非常に重要です。

仮に、

> ユーザープロファイルが破損しています

と分かったとしても、そこで調査を終了してはいけません。

次に、

> **なぜ壊れたのか？**

を考えます。

例えば原因候補は、

```
Windows Update
強制終了
電源断
セキュリティソフト
レジストリ破損
ファイルシステム異常
SSD異常
```

などです。

つまり、

```
TEMPプロファイル
    ↓
プロファイル破損
```

までは、

**症状 → 中間原因**

にすぎません。

---

# 原則3：イベントログでは「同じ時刻の別エラー」を探す

ここから今回の調査が進みました。

プロファイル障害だけを見るのではなく、

**障害が発生した8月19日前後に、ほかの重大なイベントが発生していないか**

をSystemログまで調べる。

すると、

```
Disk
Event ID 7

\Device\Harddisk0\DR0 に不良ブロックがあります
```

が大量に見つかった。

ここで優先順位が変わります。

なぜなら、

```
SSD異常
 ↓
ファイルを正常に読み書きできない
 ↓
プロファイル関連ファイルが破損・読込不能
 ↓
User Profile Serviceがロードできない
 ↓
TEMPプロファイル
```

という**一本の因果関係が成立する**からです。

逆方向、

```
ユーザープロファイル破損
 ↓
SSDに不良ブロックが発生
```

は通常成立しません。

したがって、

**SSD側の問題のほうが上流原因である可能性が高い**

と判断します。

---

# ここで使っている重要な判断基準

要するに、

> **どちらがもう一方を説明できるか？**

です。

今回なら、

|仮説|説明力|
|---|---|
|ProfileListレジストリがおかしい|TEMPプロファイルは説明できる|
|Windows Updateがおかしい|TEMPプロファイルは説明できる可能性あり|
|SSDでI/O障害|TEMPプロファイル＋Event ID 7の両方を説明できる|

3番目が一番多くの現象を説明できます。

したがって調査優先度が上がります。

これはトラブルシューティングでかなり重要な考え方です。

---

# 原則4：「重大度」と「波及範囲」が大きいものを優先する

もう一つの判断基準があります。

例えば同時に、

```
User Profile Service Error
Disk Error
Bluetooth Error
Windows Update Warning
```

が出ていたとします。

全部を同じ重みでは扱いません。

今回なら、

**Disk Errorを優先します。**

なぜならディスクは、

```
Windows
ユーザープロファイル
レジストリ
メール
Excelファイル
共有フォルダ設定
アプリ
```

など、ほぼすべてのデータの土台だからです。

つまり障害範囲が非常に広い。

これを私は、

**影響範囲**

として見ています。

---

# 原則5：「繰り返しているか」を見る

Event ID 7が1回だけなら、判断はもう少し慎重になります。

ところが今回、

> 100件以上  
> 8月19日だけでなく20日も継続

という情報が出ました。

これによって判断がかなり変わります。

例えば、

```
1回だけ
↓
瞬間的エラーかもしれない
```

ですが、

```
100回以上
＋
翌日も継続
↓
持続的な異常
```

です。

したがって、

**偶発的なWindowsエラー**

という仮説の優先順位が落ちます。

---

# 原則6：「症状発生時刻との相関」を見る

今回あなたが確認した、

> 18日はUser Profile Serviceが正常  
> 19日に問題発生  
> 19日からDisk Event ID 7が多数発生

という情報は、かなり重要です。

時系列にすると、

```
8/18
Profile正常
Disk問題は目立たない

     ↓

8/19
Disk Event ID 7多数
Profile障害発生

     ↓

8/20
Disk Event ID 7継続
Profile障害継続
```

こうなる。

これは、

**時間的相関**

があります。

もちろんこれだけで「SSDが100%原因」と証明したわけではありません。

しかし原因候補としての優先度は大幅に上がります。

---

# 原則7：「変更する前に観察する」

だから今回、

いきなり

```
ProfileListを修正
```

とはしませんでした。

先に、

```
イベントログ確認
↓
正常だった日時を確認
↓
Systemログ確認
↓
Disk Event ID 7発見
```

と進めています。

これには理由があります。

レジストリを書き換えてしまうと、**元の状態を変えてしまう**からです。

トラブルシューティングでは基本的に、

```
観察
↓
仮説
↓
追加確認
↓
対処
```

の順です。

---

# 原則8：「修復」と「原因対策」を分ける

これも今回のCHKDSKの話につながります。

例えば、

```
CHKDSK /r
```

でNTFS側の問題が解消したとします。

それでも、

**SSDが劣化しているなら原因そのものは残っています。**

同様に、

```
新しいユーザーを作成
```

すれば業務は再開できる。

しかし、

```
SSD異常
```

が残っているなら根治ではありません。

したがって対策を、

```
① 業務復旧
② データ保全
③ 原因修復
```

に分けます。

今回なら、

```
① 新規ユーザーで業務復旧

② 必要データをバックアップ

③ SSDまたはPC交換
```

という考え方になります。

---

# これを一般化すると、チェック順はこう作れます

PCトラブルが起きたら、私は大体この順序で考えます。

```
① 症状を正確に定義
        ↓
② 直近のログを見る
        ↓
③ 同時刻の関連エラーを探す
        ↓
④ 原因候補を列挙
        ↓
⑤ より下位レイヤの異常がないか確認
        ↓
⑥ 発生時刻・頻度・再現性を確認
        ↓
⑦ 一番多くの症状を説明できる仮説を優先
        ↓
⑧ データ保全
        ↓
⑨ 非破壊的な確認
        ↓
⑩ 修復・交換
```

今回これに当てはめると、

```
① TEMPプロファイル
        ↓
② User Profile Service確認
        ↓
③ 8/19前後のイベント確認
        ↓
④ Profile破損原因を検討
        ↓
⑤ SystemログでDisk Event ID 7発見
        ↓
⑥ 100件以上・翌日も継続
        ↓
⑦ SSD障害仮説が最も説明力が高い
        ↓
⑧ バックアップ優先
        ↓
⑨ SMART・メーカー診断・CHKDSK等
        ↓
⑩ SSD/PC交換
```

となります。

### 一番覚えておくと役立つ判断基準

全部覚える必要はありません。PCトラブルなら、まず次の4問を順番に考えるだけでもかなり違います。

1. **今見えているのは「原因」なのか「症状」なのか？**
2. **同じ時刻に、もっと下位のレイヤでエラーが出ていないか？**
3. **その原因候補は、観測された複数の症状をまとめて説明できるか？**
4. **修復操作をする前に、データ保全と証拠採取を済ませたか？**

今回でいえば、最初の「ユーザープロファイル破損」を**原因だと決め打ちしなかったこと**が最大のポイントです。

`TEMPプロファイル` → `User Profile Service` → `ファイル/レジストリ` → `NTFS` → `Disk I/O` → `SSD`

と、**一段ずつ下に降りていった結果、Disk Event ID 7にぶつかった**、という構造です。

この考え方を身につけると、今回だけでなく「アプリが落ちる」「Excelファイルが壊れる」「Windowsがフリーズする」「共有フォルダが不安定」といった別の問題にもそのまま応用できます。
