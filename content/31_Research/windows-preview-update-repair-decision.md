# Windows Updateでプレビュー更新が失敗したときの修復判断

Windows Updateでプレビュー更新`KB5089573`のインストールが`0x800f081f`で失敗し、現在のWindowsを再インストールしてコンポーネントとシステムファイルを修復する画面が表示された記録。このノートでは、画面で確認できる事実、選べる修復方式、実行前に止まるべき条件を分ける。

## 画面から確認できる事実

|項目|表示内容|
|---|---|
|失敗した更新|2026-05 プレビュー更新プログラム `KB5089573`（OS ビルド `26200.8524`）|
|エラー|`0x800f081f`|
|提案された機能|「現在のバージョンの Windows を再インストールして、システム ファイルとコンポーネントを修復する」|
|保持対象|アプリ、ドキュメント、設定|
|実行条件|電源に接続し、ネットワークに接続したままにする|
|再起動|修復完了後に再起動。15分後に自動再起動する選択肢がある|

`KB5089573`はWindows 11 24H2/25H2向けの2026年5月プレビュー累積更新で、Microsoftの公開情報でもOSビルド`26200.8524`と`26100.8524`が示されている。[KB5089573（Microsoft Support）](https://support.microsoft.com/servicing/os/windows-11/2026/05/may-26-2026-kb5089573-os-builds-26200-8524-and-26100-8524-preview)

## エラーコードが示すこと

`0x800f081f`は、Windows Updateの文脈では`CBS_E_SOURCE_MISSING`、すなわち更新や修復に必要なパッケージ・ファイルの取得元を見つけられなかったことを表す。コンポーネントストアの整合性が関係する場合があるが、このコードだけで、原因となったファイルやストレージの故障を特定することはできない。[Windows Update の一般的なエラー（Microsoft Learn）](https://learn.microsoft.com/troubleshoot/windows-client/installing-updates-features-roles/common-windows-update-errors)

この記録には、エラー後にDISM、SFC、再インストールを実行した結果は残っていない。したがって、以下の修復は「実行済み」ではなく、選択肢・手順として扱う。

## 画面の「今すぐ再インストール」の位置付け

この機能は「PCを初期化する」操作ではない。Windows Updateから現在のWindowsと同じバージョンを再インストールして、システムファイルとコンポーネントを修復する方式である。Microsoftは、アプリ、個人ファイル、設定を保持する方式と説明している。[現在のバージョンのWindowsを再インストールして問題を修復する（Microsoft Support）](https://support.microsoft.com/windows/deployment/install-upgrade/fix-issues-by-reinstalling-the-current-version-of-windows)

|方式|アプリ・個人ファイル・設定|このノートでの位置付け|
|---|---|---|
|Windows Updateからの現在のバージョン再インストール|保持する|画面が提案した修復方式|
|システムの復元|個人ファイルは保持するが、復元ポイント以降のシステム変更は戻す|別の復旧手段。修復再インストールと同一ではない|
|「このPCをリセット」|選択肢によりアプリ・設定・個人ファイルの扱いが変わる|今回の画面の操作とは別。混同しない|
|インストールメディアからの再インストール|選択肢により保持範囲が変わる|今回の画面の操作とは別|

修復再インストールが保持対象を示していても、電源断・ネットワーク遮断・既存のストレージ障害などによる失敗を完全に排除するものではない。重要データは実行前に別媒体または同期済みの保存先へ保全する。

## 実行を検討できる条件

次を満たすなら、画面の修復再インストールを検討できる。

```text
Windowsへ通常どおりログオンできる
重要な作業データを保全済み
AC電源と安定したネットワークを継続して使える
BIOSで内蔵ストレージが安定して認識されている
Disk系エラーやファイル読み取り失敗が継続していない
会社PCなら、社内IT・保守ルールで許可されている
```

実行する場合に画面上で行うことは、次の範囲である。

1. 作業中のファイルを保存し、重要データのバックアップを確認する。
2. AC電源とネットワークを接続したままにする。
3. 「今すぐ再インストール」を選択する。
4. 自動再起動を15分後に行うかを選び、`OK`を押す。
5. ダウンロード・修復後に再起動し、Windows Updateを再確認する。

## 中止して先に保全・保守を優先する条件

このノートの端末と、CF-LVやLIFEBOOKの障害事例が同一端末だったという記録はない。以下は、それらの事例を混同せずに適用する安全条件である。

```text
BIOSから内蔵ストレージが消える
Disk Event ID 7やCRCエラーが発生している
重要ファイルの読み取りに失敗する
起動や再起動を繰り返せない
```

これらがある場合は、更新修復や大量の書き込みを先に行わない。データ保全と保守相談を優先する。関連する判断は、[Windowsユーザープロファイル障害・SSD不良ブロック調査まとめ](windows-profile-ssd-read-errors.md)および[LIFEBOOK AシリーズでBIOSからSSDが消えた事例](LIFEBOOK AシリーズでBIOSからSSDが消えた事例.md)にある。

## コマンドで確認・修復する場合

Microsoftは`0x800f081f`に対し、管理者のコマンドプロンプトでコンポーネントストアを修復してから、システムファイルを確認する手順を案内している。

```bat
DISM.exe /Online /Cleanup-Image /RestoreHealth
Sfc.exe /Scannow
```

この二つはこのノートで実行済みとは記録されていない。会社PCでは、実行前に保守ルールと端末のストレージ状態を確認する。特にBIOS未認識・I/Oエラー・データ読み取り失敗がある端末には、この手順を障害原因の切り分けより先に適用しない。
