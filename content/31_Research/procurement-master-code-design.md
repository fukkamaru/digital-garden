# 仕入品マスターと仕入れコードの設計

このノートは、Excelで管理する仕入表を出発点に、仕入品を長期に識別するコード体系とマスターデータの構成を検討した記録である。実在の会社の既存コード、品目数、運用慣行を含むため、非公開で維持する。ここに記録した設計案は、現行システムや実データを確認せずに適用するものではない。

## 問題：変わる分類を識別子へ埋め込むか

当初案は、`A00001`のように先頭文字をカテゴリー、残りを連番とする6桁コードだった。原料、容器、袋、副資材などをコードから読める利点がある一方、カテゴリーを誤登録・再分類した場合にコード自体を変えなければならない。発注履歴や他システムで使われるコードを後から変更すると、照合、教育、口頭連絡にまで影響する。

このため、品目を一意に識別する値と、変わり得る属性を分ける考え方を検討した。

| 項目 | 役割 | 変更の扱い |
| --- | --- | --- |
| 仕入品ID | データベース上で品目を一意に識別する内部ID。 | 原則変更しない。 |
| 現場コード | 発注・口頭連絡・旧資料で使われてきたコード。 | 互換性を考慮して維持する。 |
| カテゴリーID | 原料、容器などの分類。 | 分類見直し時はこの項目を変更する。 |
| 親コード・サブコード | 既存の重複や派生品を区別する補助情報。 | 必要な品目だけ使う。 |

つまり、コードをIdentity、カテゴリーをAttributeとして扱う。新しい内部IDを意味を持たない6桁連番にし、既存コードを現場コードとして併存させる案が、長期の安定性と現場の慣行を両立しやすい。

## 既存コードとの互換性

現場で「Bの230番」のような呼び方が定着しているなら、既存コードは単なるキーではなく共通語でもある。一気に理想的な体系へ置き換えるより、既存の意味を残しながら内部構造を整える方が安全な場合がある。

同じ現場コードが複数品目に使われている場合は、親コードを残して枝番を付ける案を検討した。例えば、`B00230-00`を本体、`B00230-01`を蓋のように扱う。2桁なら最大100、3桁なら最大1000程度の派生を区別できる。親コード、サブコード、完全現場コードは、Excelでも別列にして管理する。

カテゴリーを表す接頭辞と、コード体系そのものを区別する接頭辞も別に考える。カテゴリー変更の影響を受ける`A00001`型の接頭辞は慎重に扱う。一方、仕入品・販売品・顧客など、別のID体系を区別する`PUR`、`SAL`、`CUS`型の接頭辞は、コードを人が直接扱う業務では有用になり得る。

## 仕入品マスターのたたき台

| 項目 | 役割 |
| --- | --- |
| 仕入品ID | 内部の一意キー |
| 現場コード | 既存の発注・会話で使うコード |
| 親コード／サブコード | 重複・派生品の管理 |
| 商品名 | 品目名 |
| カテゴリーID | 分類マスターへの参照 |
| 発注先ID | 発注先マスターへの参照 |
| 使用／廃止 | 現在の有効状態 |
| 単位・容量・規格・荷姿・発注単位 | 仕入条件 |
| 旧コード・備考 | 移行経緯や例外 |

桁数は、現在の件数、将来の増加、廃番コードを再利用するか、運用年数を基準に決める。検討時には、約1万品目を長期に扱う想定から、6桁の内部IDが余裕を持つ案として挙げられた。採用前には、既存システムの桁数制限、採番方法、移行対象を確認する。

## テストデータ生成の履歴

後半では、仕入表を検証するためのテスト用マスターデータ作成も行った。これはコード体系の設計判断とは別の作業履歴である。

- 最初に2,462件の商品名生成を試みたが、実在性のない連番名では不十分だと分かり、実務に近い名称の組み合わせへ方針を変えた。
- 化学原料551件、食品551件、容器・ケース1,230件、袋・シート663件、副資材225件を生成した。CSVはExcelで扱うためUTF-8 with BOM（utf-8-sig）を想定した。
- 容器・ケースでは、最初の組み合わせ数が1,000件で不足し、寸法、缶種、容量などの条件を増やして生成方法を見直した。
- 発注先207件のCSVはツール側のエラーにより完成していない。この未完了は、コード設計の結論ではなく、テストデータ作成の保留である。

## 次に決めること

1. 内部ID、現場コード、カテゴリーIDを実際の仕入マスターで分離できるか確認する。
2. 重複している既存コードについて、枝番化が現場運用・関連システム・過去資料へ与える影響を確認する。
3. 発注先、単位、荷姿、旧コードなどをどのマスターで管理するか決める。
4. テストデータが必要な場合だけ、実在の会社・商品・取引先を含まないサンプルとして別途完成させる。
