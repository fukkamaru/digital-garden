ここまでのやり取りを踏まえて、**今回構築した「iPhone / iPad → Windows → 外付けHDD」のSMB共有運用**について、設定方法だけでなく、実際に使って分かった注意点まで含めて整理します。

## 目的と現在の構成

今回の目的は、iCloudなどのクラウド同期を使わずに、複数のiPhoneやiPadからWindows PCへ写真・動画を送り、最終的に外付けHDDへ保存することです。

環境としては、

```
撮影端末
├─ iPhone ①
├─ iPhone ②
└─ iPad
      ↓
   自宅LAN
      ↓
   SMB共有
      ↓
Windows PC
      ↓
4TB 外付けHDD
```

という構成です。

iPhoneが2台あり、それぞれApple Accountが異なるため、iCloudによる同期では「反映待ち」「どこまで転送したか分からない」といった問題がありました。

そこで、**クラウド同期ではなく、自分が必要なときだけWindowsへ明示的に送るSMB方式**を採用しました。

---

# 1. HDD側の基本構成

4TB HDD直下にはBUFFALO関連のシステムファイルなどが存在するため、HDD全体を素材置き場にはせず、自分用のトップフォルダとして、

```
E:\
└─ MediaArchive
```

を作成。

その中を、

```
MediaArchive
├─ 00_Inbox
└─ 01_Source
```

という構成から始めています。

役割は明確に分けます。

**`00_Inbox`**  
→ iPhone・iPadから受信するための一時置き場

**`01_Source`**  
→ Windowsで確認・整理を終えた写真・動画の正式な保存場所

したがって、

```
iPhone
  ↓
00_Inbox
  ↓ 確認・整理
01_Source
```

という流れになります。

`00_Inbox` が空なら、

> 現在、未整理の転送ファイルはない

と判断できるのも、この構成の利点です。

---

# 2. SMB共有するのは `00_Inbox` だけ

重要なのは、HDD全体や `MediaArchive` 全体を共有する必要はないことです。

共有するのは、

```
E:\MediaArchive\00_Inbox
```

だけで十分です。

Windowsのエクスプローラーで `00_Inbox` を右クリックして、

```
プロパティ
→ 共有
→ 詳細な共有
```

へ進みます。

そこで、

```
「このフォルダーを共有する」
```

をON。

共有名はたとえば、

```
Media_Inbox
```

とします。

ネットワーク上では、

```
\\WindowsPC\Media_Inbox
```

というような共有になります。

---

# 3. 書き込み権限を与える

iPhoneから写真・動画を送るには、Windows側の共有フォルダへ**書き込み権限**が必要です。

「詳細な共有」の「アクセス許可」で、利用するユーザーに、

```
読み取り
変更
```

を許可します。

単に「読み取り」しか許可されていない場合、

```
iPhone → Windows
```

へのファイル保存ができません。

テスト段階ならEveryoneに変更権限を与える方法もありますが、長期間運用するなら、Windowsの自分のユーザーアカウントを使って認証させる方が適切です。

---

# 4. Windows側のネットワーク設定

Windows PCが接続している自宅LANについて、ネットワークプロファイルを、

```
パブリック
```

ではなく、

```
プライベート
```

として扱います。

Windows 11なら概ね、

```
設定
→ ネットワークとインターネット
→ Wi-Fi または Ethernet
→ 接続中のネットワーク
→ ネットワークプロファイル
→ プライベート
```

です。

これは、

> 自宅LANではファイル共有を許可するが、公共Wi-Fiなどでは共有しない

という区別のためです。

さらに、

```
設定
→ ネットワークとインターネット
→ ネットワークの詳細設定
→ 共有の詳細設定
```

から、プライベートネットワークについて、

```
ネットワーク探索：ON
ファイルとプリンターの共有：ON
```

にします。

---

# 5. Windows PCのIPアドレスを確認

iPhone/iPadからWindowsへ接続するために、Windows PCのローカルIPアドレスを調べます。

コマンドプロンプトまたはターミナルで、

```
ipconfig
```

を実行。

Wi-Fiを使っているなら該当アダプターの、

```
IPv4 Address
```

を確認します。

たとえば、

```
192.168.1.123
```

だったとします。

するとiPhoneからの接続先は、

```
smb://192.168.1.123
```

となります。

PC名から接続することもできますが、今回のような初期設定・トラブル確認ではIPアドレス指定の方が分かりやすいです。

---

# 6. iPhone標準「ファイル」アプリからSMBへ接続

iPhone/iPadにはSMBクライアント機能が標準搭載されています。

「ファイル」アプリを開いて、

```
ファイル
→ ブラウズ
→ 「…」
→ サーバへ接続
```

と進みます。

サーバ欄へ、

```
smb://192.168.1.123
```

のように入力。

Windows側のユーザーで接続する場合は、

```
登録ユーザ
```

を選択して、

```
Windowsのユーザー名
Windowsのパスワード
```

を入力します。

正常に接続できれば、

```
Media_Inbox
```

がiPhone/iPadから見えるようになります。

今回については、このSMB接続自体はすでに成功しています。

---

# 7. DocumentsアプリからもSMB接続できた

iPhone/iPadの「ファイル」アプリ以外に、**DocumentsアプリからSMB共有を登録する方法も実際にテストし、接続・ファイル転送ができることを確認済み**です。

つまり、

```
iPhone / iPad
↓
Documents
↓
SMB
↓
Windows
↓
00_Inbox
```

も利用できます。

一般ファイルを扱う場合はこちらも便利です。

ただし、今回ひとつ分かったことがあります。

Documents側で「移動」を実行しても、SMBのような異なるストレージ間では実質的に**コピーとして処理され、元端末側にファイルが残ることがある**という点です。

そのため、

> 「SMBへ移動したからiPhone側から自動的に消える」

とは考えない方が安全です。

---

# 8. 写真アプリの写真・動画は「ファイル」アプリから直接見えない

ここが途中で混乱した重要ポイントです。

iPhoneの、

```
写真アプリ
```

と、

```
ファイルアプリ
```

は別の保存領域を扱っています。

そのため、ファイルアプリからSMBへ接続したとしても、

> ファイルアプリを開いて、iPhoneの写真ライブラリから写真を選ぶ

という操作はできません。

写真ライブラリにある写真・動画をSMBへ送る場合は、**「写真」アプリを起点にします。**

---

# 9. 写真アプリ → SMBへの送り方

写真アプリで、

```
写真
→ 転送したい写真・動画を選択
→ 共有ボタン
→ 「ファイルに保存」
```

と進みます。

保存先として、

```
Windows SMB
↓
Media_Inbox
```

を指定します。

つまり実際の経路は、

```
iPhone 写真ライブラリ
        ↓
「ファイルに保存」
        ↓
     SMB接続
        ↓
Windows / 4TB HDD
        ↓
MediaArchive
        ↓
00_Inbox
```

となります。

iCloudは介しません。

Apple Accountも関係ないため、Apple Accountが異なる2台のiPhoneでも同じWindows PCへ送れます。

---

# 10. 「移動」ではなく「コピー」と考える

これは今回の運用でかなり重要です。

写真アプリから、

```
共有
→ ファイルに保存
→ SMB
```

としても、写真ライブラリの元データは削除されません。

つまり、

```
iPhone
↓
SMB
↓
HDD
```

の処理は、基本的に**コピー**です。

したがって容量を空けるには、転送後、

```
① SMB転送完了
② Windows側で存在確認
③ 必要なら破損確認
④ 01_Sourceへ整理
⑤ iPhoneから削除
```

という操作が必要です。

これは一手間増えますが、逆にいうと、

> 転送に失敗したのに元ファイルまで消えてしまった

という事故を防げます。

旅行素材のような再撮影できないデータについては、安全側の動作です。

---

# 11. その日に撮った写真・動画をまとめて転送する

今回のような旅行素材では、

> 2026年8月8日に撮影したものを全部Windowsへ送りたい

という使い方が中心になります。

写真アプリで対象の日付を表示して、

```
選択
```

を押し、指を滑らせれば大量の写真・動画を連続選択できます。

また、写真アプリの検索などを利用して日付で絞り込む方法もあります。

その日の素材をまとめて、

```
選択
↓
共有
↓
ファイルに保存
↓
Media_Inbox
```

と送ります。

転送後に同じ日付の写真・動画を選択して削除すれば、

> どれを転送したのか分からない

という問題をある程度防げます。

---

# 12. 複数iPhoneから同時に送ることも可能

SMBは複数クライアントから接続できるため、

```
iPhone A ─┐
          ├→ Windows SMB → HDD
iPhone B ─┘
```

という同時転送自体は可能です。

ただし今回のように、

- 写真・動画合わせて200件
- 数百MBのMOVが含まれる
- Wi-Fi経由
- 外付けHDDへ直接書き込み

という状況では、1台ずつ処理した方が無難です。

同時転送するとWi-Fi帯域を奪い合いますし、大容量動画では転送時間も増えます。

---

# 13. 端末ごとに受信フォルダを分ける案

もう一つ途中で判明した問題が、**どのiPhoneから来た素材なのか**です。

写真・動画ファイルには、

```
IMG_4290.HEIC
IMG_0968.MOV
```

などの名前がありますが、ユーザー自身がiPhoneにつけた、

```
旅行用iPhone
メインiPhone
```

といった端末名は通常ファイルから判別できません。

さらに別々のiPhoneでは、

```
IMG_1234.HEIC
```

のような同名ファイルが発生する可能性があります。

そのため、2台以上で撮影する場合は、

```
00_Inbox
├─ iPhone_Main
└─ iPhone_Sub
```

あるいは、

```
00_Inbox
└─ 2026-08-11_和歌山
   ├─ iPhone_Main
   └─ iPhone_Sub
```

として、**転送時点で端末別に分ける**のが安全です。

SMB共有自体は `00_Inbox` にしておけば、その配下のフォルダへiPhoneから保存できます。

---

# 14. 今回実際に発生したSMB転送エラー

大量転送中、

> 「操作を完了できませんでした。RPC構造体が不正です」

というエラーも発生しました。

このときは、

- 約200ファイルを転送中
- 写真と動画をまとめて処理
- 大容量MOVも含む
- Wi-Fi → SMB → 外付けHDD

という状態でした。

このエラーが出たからといって、HDD全体が故障したという意味ではありません。

SMB転送中に、

- Wi-Fi通信
- SMBセッション
- 大量ファイル処理
- 特定ファイル
- iPhone側の処理

などのどこかで問題が発生した可能性があります。

そのため、大量転送では、

```
写真：ある程度まとめて転送
動画：10～20本程度など小分け
```

のようにする方が安全です。

特に数GBクラスの動画を大量に送る場合には、USB転送との併用も候補になります。

---

# 15. 転送後は「存在する」だけで正常とは限らない

もう一つ今回考えたのがファイル破損です。

たとえば、

```
IMG_1234.MOV
サイズ 2GB
サムネイルも表示される
冒頭30秒も再生できる
```

としても、

> 5分地点以降が破損している

可能性は理論上あります。

そのため、将来的にはFFmpegなどを利用して、

```
00_Inbox
↓
動画を最後まで自動デコード検査
↓
正常
↓
01_Source
```

という検品工程を加える案も出ています。

つまり、SMB転送が成功したことと、動画ファイル全体が正常であることは別問題として扱います。

# 現時点でのおすすめ運用

ここまで実際に試した結果を踏まえると、現在の運用は次の形がかなり分かりやすいです。

```
【撮影】

iPhone Main
iPhone Sub
iPad

        ↓

【SMB転送】

4TB HDD
└─ MediaArchive
   └─ 00_Inbox
      ├─ iPhone_Main
      ├─ iPhone_Sub
      └─ iPad

        ↓

【Windowsで確認】

・ファイル数
・ファイルサイズ
・写真の表示
・動画の再生
・必要ならFFmpegによる破損検査

        ↓

【正式保存】

MediaArchive
└─ 01_Source
   └─ 2026
      └─ 2026-08-11_和歌山
         ├─ Photo
         └─ Video

        ↓

【保存確認後】

iPhone / iPadから元データ削除
```

ポイントは、**SMBをアーカイブそのものとしてではなく「iPhone/iPadからWindows環境へ持ち込むための搬入口」として使うこと**です。

そして、

```
00_Inbox = まだ処理していない
01_Source = 処理・確認済み
```

という状態管理をフォルダ構成そのものに持たせます。

今回の一連のテストを見る限り、まずは**追加アプリなしのSMB運用を基本にして、大量動画で不安定さが目立つようならPhotoSyncやUSB転送を補助的に追加する**、という順番でよさそうです。
