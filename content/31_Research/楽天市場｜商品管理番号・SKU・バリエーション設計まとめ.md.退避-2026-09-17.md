## 1. ID体系の基本整理

楽天市場の商品登録では、主に以下のIDを使う。

|項目|役割|変更可否|今回の考え方|
|---|---|---|---|
|商品管理番号|商品ページ単位の識別子。URLの一部になる|変更不可|製品名ベースの固定文字列を使う|
|商品番号|店舗側での商品管理用|―|社内管理用途として別途利用可能|
|SKU管理番号|同一商品内のSKUを一意に識別する|変更不可|色・容量などバリエーション単位で設定|
|システム連携用SKU|外部システムとの連携用|―|必要になった場合に外部連携用IDとして使用|

重要なのは、**「商品管理番号」と「SKU管理番号」は役割が異なる**という点。

- 商品管理番号 = 商品ページ・製品ファミリーのID
- SKU管理番号 = その商品内にある個別バリエーションのID

## 2. 商品管理番号に社内商品コードを使わない理由

当初、商品管理番号を既存の商品コードにする案を検討した。

しかし、色違いや容量違いがある製品では、SKUごとに商品コードが異なる可能性がある。

例：

```text
100001 = シルバーグレー 4L
100002 = シルバーグレー 14L
100003 = ライトブルー 4L
100004 = ライトブルー 14L
```

楽天市場では、これらを1つの商品ページのバリエーションとしてまとめる場合、**商品管理番号は全SKUで共通**になる。

そのため、どれか1つの社内商品コードを商品管理番号として採用すると、

```text
商品管理番号：100001
├─ 100001 シルバーグレー 4L
├─ 100002 シルバーグレー 14L
├─ 100003 ライトブルー 4L
└─ 100004 ライトブルー 14L
```

のようになり、`100001`だけが商品全体を代表してしまう。

これでは、商品管理番号と社内商品コードの意味がずれる。

したがって、

```text
社内商品コード
→ SKU単位の識別

楽天の商品管理番号
→ 商品ページ・製品ファミリー単位の識別
```

と分離する方針が適切。

## 3. 商品管理番号は製品名ベースの文字列にする

商品管理番号には英数字・ハイフン・アンダースコアを使用できるため、数字コードではなく、**製品名をベースにした固定文字列**を使う方針を検討。

対象製品：

```text
サロモン断熱マイナス
```

英語名では「断熱」に `insulation` を使用している。

そのため、商品管理番号の候補として、

```text
salmon-insulation-mainus
```

を採用する方向。

この形には以下の利点がある。

- 製品名との対応が分かりやすい
- 色違い・容量違いの影響を受けない
- SKU追加時も商品管理番号を変更する必要がない
- 公式・既存の英語名称との整合性を保てる
- URLを見ても商品を識別しやすい

したがって現時点では、

```text
商品管理番号：
salmon-insulation-mainus
```

が有力。

## 4. 楽天市場のURL構造

当初のメモでは、

```text
店舗名 / 商品管理番号 / SKU管理番号
```

という3階層構造として考えていた。

ただし、正確にはSKU管理番号はURLパスそのものではなく、SKU選択時にクエリパラメータとして付く。

商品ページ：

```text
https://item.rakuten.co.jp/店舗URL/salmon-insulation-mainus/
```

特定SKUを選択した場合のイメージ：

```text
https://item.rakuten.co.jp/店舗URL/salmon-insulation-mainus/?variantId=silver gray
```

つまり概念的には、

```text
店舗
└─ 商品管理番号
   └─ SKU管理番号
```

という関係だが、URLそのものは、

```text
商品管理番号
+
variantId=SKU管理番号
```

という構成になる。

## 5. SKU管理番号は店舗全体で一意でなくてもよい

途中で、「他の商品でも `silver gray` が使われるとSKU管理番号が重複して問題になるのではないか」という懸念が出た。

この点については、**SKU管理番号は同一商品内で重複しなければよい**。

つまり、

```text
商品管理番号：
salmon-insulation-mainus

SKU：
silver gray
light blue
ivory
```

と、

```text
商品管理番号：
another-product

SKU：
silver gray
light blue
ivory
```

が存在しても、商品管理番号が異なるため区別できる。

したがって、

```text
salmon-insulation-mainus-silver gray
```

のように、毎回商品名までSKU管理番号に含める必要はない。

※外部の在庫管理システム・基幹システムなどで店舗全体のSKU一意性を要求される場合は別途検討する。その用途については「システム連携用SKU」を活用できる。

## 6. サロモン断熱マイナスの色バリエーション

サロモン断熱マイナスには以下の3色がある。

- シルバーグレー

## 7. 色番号やカラーコードをSKU管理番号に含めるべきか

サロモン断熱マイナスの各色については、日本塗料工業会の色を参考にした独自の色データを定めている。

そのため、

```text
silver gray-XXXX
light blue-YYYY
ivory-ZZZZ
```

のように、色番号やカラーコードをSKU管理番号へ組み込むべきかを検討した。

### 結論

現状では、**SKU管理番号に色番号やカラーコードを無理に入れる必要はない**。

現在の3色が固定色で、

```text
silver gray
light blue
ivory
```

だけで一意に識別できるなら、それで十分。

色番号はSKU管理番号とは別の「色マスタ情報」として管理する方が整理しやすい。

例：

```text
silver gray
└─ 社内色番号：XXXX

light blue
└─ 社内色番号：YYYY

ivory
└─ 社内色番号：ZZZZ
```

## 8. HEXなどのカラーコードをSKUに含めない方がよい理由

たとえば、

```text
silver gray-8a8b87
```

のようにHEXカラーコードをSKUに含めることは推奨しない。

理由：

- 人間が見ても判別しにくい
- Web表示用の色と実際の塗料色は完全には一致しない
- 表示用カラーを微調整するとSKUの意味まで変わってしまう
- SKU管理番号は変更不可なので、表示情報を持たせすぎると後から扱いにくい
- 色コードは画像制作・Web表示用データとして別管理した方がよい

したがって、

```text
SKU管理番号
silver gray

社内色番号
XXXX

表示用HEX
#XXXXXX
```

のように情報を分離する方がよい。

## 9. 日本塗料工業会の色番号を使う場合の注意

今回の色が「日本塗料工業会の色票そのもの」ではなく、**日本塗料工業会の色を参考にして自社で定めた色**である場合は、日塗工番号をそのままSKU管理番号に入れることには注意が必要。

日塗工番号を前面に出すと、

```text
この製品色 = その日塗工色そのもの
```

と受け取られる可能性がある。

そのため、日塗工色があくまで参考値であるなら、

- SKU管理番号
- 自社色番号
- 参考日塗工番号
- Web表示用カラーコード

は分けて管理した方が安全。

## 11. 現時点で決まったこと

- 商品管理番号にはSKU単位の商品コードを使わない
- 商品管理番号は商品ページ・製品ファミリーを表す固定文字列にする
- サロモン断熱マイナスの商品管理番号は `salmon-insulation-mainus` が有力
- 色は「シルバーグレー／ライトブルー／アイボリー」の3色
- バリエーション表示名は日本語の色名でよい
- SKU管理番号は `silver gray / light blue / ivory` のような簡潔な色名で成立する
- SKU管理番号は別商品間で同じ値を使うことができる
- 色番号やHEXカラーコードはSKU管理番号に無理に入れない
- 正確な色情報は別途色マスタとして持つ方がよい

## 12. 次に検討する項目

次に詰めるべきなのは、色以外のSKU軸。

特に、

```text
容量
荷姿
セット内容
シーラーとの組み合わせ
```

などが存在する場合、

```text
カラー × 容量
```

などの複合バリエーションになる。

その場合でも商品管理番号は、

```text
salmon-insulation-mainus
```

のまま固定し、SKU管理番号側だけを、

```text
silver gray-14l
silver gray-4l
light blue-14l
light blue-4l
ivory-14l
ivory-4l
```

のように拡張する設計が基本になる。
