# チャネルにおけるFBAとFBAE

## 要点

FBAEは、製品の説明を「特徴（Feature）」「優位性・仕組み（Advantage）」「顧客にとっての価値（Benefit）」「根拠（Evidence）」として整理するための枠組みである。どの販売チャネルでも同じ量の情報を載せるのではなく、そのチャネルで購入者・検討者が次に判断したいことに合わせて、要約と詳細資料を分ける。

## FBAEの役割

| 要素 | 問い | 例 |
| --- | --- | --- |
| Feature | 何を備えているか | 1材で複数の作業に対応する |
| Advantage | その特徴は何を可能にするか | 材料や工程の切替を減らせる |
| Benefit | 利用者にどんな価値があるか | 作業時間や管理負担を減らせる |
| Evidence | その説明を何で確かめられるか | 試験条件、仕様書、施工手順、導入事例 |

Featureだけでは製品仕様の列挙で終わり、Benefitだけでは根拠のない訴求になりやすい。BtoB製品では、利益を示した後に、条件を明らかにした根拠へ進める構造が特に重要になる。

## チャネル別に変わる説明の深さ

| チャネルの性質 | 読み手が最初に確認すること | 情報設計の中心 |
| --- | --- | --- |
| モールの商品詳細ページ | 何の商品か、比較対象とどう違うか | 商品名・主要仕様・選択肢・要点を先に示し、必要に応じて画像や詳細コンテンツへ進める |
| 自社の製品ページ | 課題に合うか、採用してよいか | 製品コンセプトからFBAE、FAQ、技術資料、事例へ段階的につなぐ |
| BtoB情報検索サイト | 検討対象になるか、資料を読む価値があるか | 課題・用途・差別化ポイントを短く示し、カタログや問い合わせへつなぐ |
| 個人間売買・オークション | 出品物の実際の状態と取引条件は何か | 特徴の訴求より、傷・動作・付属品・発送条件を正確に示す |

イプロスは、BtoBの製品・技術・サービスを閲覧し、資料をダウンロードできる情報検索サイトである。したがって、製品ページは自社サイトの説明をそのまま転載するよりも、課題・用途・差別化ポイントを先に示し、必要な詳細資料へ進める入口として設計するのが分かりやすい。掲載条件や利用できる機能は契約内容により異なるため、実際に掲載する前に公式の案内を確認する。

## 情報を積み上げる順序

1. 製品コンセプト：誰のどの課題に、何で応える製品かを一文で示す。
2. Feature / Advantage / Benefit：特徴から利用価値までの因果を説明する。
3. Evidence：試験、仕様書、施工条件、比較条件、事例など、主張を確認できる材料を示す。
4. 次の行動：カタログ、技術資料、問い合わせ、購入など、チャネルに応じた行動を明確にする。

根拠が未確認の場合は、効果・時間短縮・費用削減を断定しない。特に試験結果や導入事例は、対象条件、比較方法、適用範囲を併記する。

## Amazonを具体例として見る

Amazonの商品詳細ページで利用できるA+コンテンツは、商品情報を画像・動画・比較表などで補強する手段の一つである。A+の機能や利用条件は固定ではないため、具体的な設計は[Amazonの商品ページにおける「A+なし」「A+あり」「プレミアムA+あり」の違い](amazon-a-plus-content-states.md)とAmazon公式資料で確認する。

FBAEは特定モールの入力ルールではなく、製品情報を整理するための枠組みである。チャネルの画面や掲載仕様に合わせて、どの要素を短く示し、どの要素を資料や詳細ページに置くかを決める。
