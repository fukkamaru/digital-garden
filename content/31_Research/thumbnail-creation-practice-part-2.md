## ここまでの整理

今回のチャットでは、**縞鋼板向けの黄色い塗布型すべり止め材について、既存のHTML設計書と実素材をそのまま基準にしてYouTubeサムネイルを生成する**ことを目的として進めた。

重要なのは、「HTMLを参考にそれらしいデザインを作る」のではなく、**HTML自体を完成デザインの設計指示として読み取り、勝手な再構成・文言変更・装飾追加をせずに再現する**という点だった。

## 1. ユーザーから提供された素材

今回、サムネイル生成用として以下が与えられた。

|種別|ファイル|役割|
|---|---|---|
|メイン画像|`main_construction_yellow.png`|縞鋼板に黄色い防滑材をローラー施工している場面|
|テクスチャ画像|`texture_material_yellow.png`|黄色い防滑材の粘度・骨材感・垂れを見せる素材|
|メイン設計書|`thumbnail_a_yellow_offwhite_revised(1).html`|今回従うべき黄色材料・オフホワイト版HTML|
|旧／別案HTML|`thumbnail_a(2).html`|黒系デザインの旧バージョン|

今回明示的に指定されたのは、

> `@thumbnail_a_yellow_offwhite_revised(1).html`

であり、**黄色材料＋オフホワイト背景版が制作基準**だった。

HTML自身も、これは単なるブラウザ表示用HTMLではなく、**3840×2160のYouTubeサムネイルを生成するための設計書であり、DOM・CSS・座標・テキスト・data属性を生成指示として解釈する**ものと定義している。

## 2. HTMLで指定されていた完成デザイン

### 基本仕様

出力仕様は以下。

- サイズ：**3840 × 2160 px**
- アスペクト比：**16:9**
- デザイン方向：`clean industrial editorial`
- 基本背景：オフホワイト `#F7F7F5`
- 基本文字色：チャコールブラック `#111315`
- 強調色：ディープブルー `#005B96`
- 枠・区切り：ニュートラルグレー `#A4A9AD`

HTMLでは、黄色はあくまで**防滑材そのものの色として最も強く見せる**よう指定されており、文字や枠、装飾には黄色を使用しない方針になっている。

つまり色の役割は、

```text
黄色
└─ 防滑材そのもの

青
└─ 「塗る」の文字だけ

黒
└─ メインコピー・サブコピー

オフホワイト
└─ 左側の文字領域

グレー
└─ 区切り線・テクスチャ画像の枠
```

という明確な分業になっている。

### レイアウト

大きな構造は、

```text
┌────────────────────────────────────────┐
│                                        │
│  縞鋼板の防滑性向上なら      メイン施工写真 │
│                                        │
│  「塗る」すべり止め材                    │
│                                        │
│  ─ ローラーで簡単施工                    │
│                                        │
│  ┌─────────────┐                       │
│  │ 材料テクスチャ │                       │
│  └─────────────┘                       │
│                                        │
└────────────────────────────────────────┘
       オフホワイト → 徐々に写真へフェード
```

という**左テキスト／右施工写真**構成。

右側のメイン画像は、

- x = 1240
- y = 0
- width = 2600
- height = 2160

で配置し、画面右側を大きく占有する指定。ローラー、手袋、縞鋼板、黄色の塗布面、未施工の銀色縞鋼板の境界を重要要素として残すよう指示されている。

左側には別の四角い白パネルを置くのではなく、オフホワイトから写真側へ自然に透過するグラデーションを重ねる設計になっている。

## 3. テキストは変更禁止

メインコピーはHTMLで完全に確定していた。

### 1行目

**縞鋼板の防滑性向上なら**

- x = 190
- y = 180
- 166px
- weight 700
- ブラック

### 2行目

**「塗る」すべり止め材**

- 202px
- weight 900
- 「塗る」のみ青 `#005B96`
- それ以外はブラック

HTMLでは「2つの意味上の行として扱い、必要もないのに細かく分割しない」ことまで指定されている。

サブコピーも固定されている。

**ローラーで簡単施工**

- x = 200
- y = 900
- 126px
- weight 700
- ブラック
- 左側にグレーの短い横罫線

という仕様。

したがって今回の制作では、

- 文言を短縮しない
- 改行を勝手に増やさない
- 「塗る」を「塗る防滑材」などに変更しない
- 「ローラー施工」など別の言い方に変更しない
- 新しいキャッチコピーを追加しない

ことが前提だった。

## 4. 材料テクスチャ画像の扱い

左下には、

`texture_material_yellow.png`

を小さなサブビジュアルとして配置する。

指定は、

- x = 190
- y = 1330
- width = 980
- height = 560
- グレー枠
- キャプションなし

となっている。

画像内では、

- ヘラ
- ヘラから垂れる黄色い材料
- 高粘度感
- 粗い防滑骨材
- 容器開口部

を見せることが主目的。

独立した広告パネルのように強調するのではなく、**「この材料はこういう粘度・質感なのだ」と補助的に伝えるビジュアル**という位置づけになっている。

## 5. HTMLで明示的に禁止されていたもの

設計書では、勝手なアレンジを防ぐために禁止要素も列挙されていた。

- 黄色い見出し文字
- 黄色いUI枠
- 黄色い装飾パネル
- 青い背景パネル
- 青い枠
- バースト・吹き出し系装飾
- 漫画風の吹き出し
- 太い文字アウトライン
- 大きな赤文字
- 商品缶
- ハンマー
- 防滑テープ
- コンクリート補修表現
- ロゴ
- ウォーターマーク
- UI

さらに「DOMに存在する日本語テキストだけを描画し、新しい文章を追加しない」と明示されている。

## 6. 1回目の生成

最初の依頼は、

> 指示書にしたがってサムネイルを作成して

というものだった。

生成結果は、全体的な方向性としては、

- 左側オフホワイト
- 右側黄色施工写真
- 「塗る」を青
- 左下に材料テクスチャ
- ローラー施工
- 工業系の構成

を反映していた。

一方で、**HTMLを厳密に再現せず、生成側でデザインを再解釈してしまった**。

特に、

- 「縞鋼板の防滑性向上なら」を独自に複数行化
- HTMLより文字サイズ・文字組みを大幅に変更
- コピーと写真のバランスを再設計
- 一部文字にHTMLにはない縁取り的な表現
- 元画像をそのまま配置するというより、施工場面自体を再生成・再構成
- テクスチャ画像についても元素材そのものではなく再生成的な表現

となっていた。

つまり、**「HTMLから着想を得たサムネイル」にはなっていたが、「HTML設計書を忠実にレンダリングしたサムネイル」にはなっていなかった。**

## 7. ユーザーからの修正指示

そこでユーザーから明確に、

> 改変などはせず、HTMLの指示書に正しくしたがって、サムネイルを作成してください。

という修正指示が入った。

ここが今回のチャットで最も重要なフィードバック。

要求されたのはデザインの改善ではなく、

**「設計済みの内容を勝手に改善しないこと」**

だった。

したがって優先順位は、

```text
HTMLへの忠実性
  ↓
素材への忠実性
  ↓
指定座標・文字・色・階層の忠実性
  ↓
生成AI側の美的判断
```

でなければならない。

## 8. 2回目の生成

修正後の生成では1回目よりHTMLに近づいた。

改善された点は、

- 「縞鋼板の防滑性向上なら」を1つの行として処理
- 「「塗る」すべり止め材」を次の1行に配置
- 「塗る」のみ青
- 「ローラーで簡単施工」を独立配置
- 左側をオフホワイトの余白として確保
- 右側に施工写真
- 左下に黄色材料のクローズアップ
- グレー系の区切り線と枠
- 余計な商品缶・ロゴ・バッジ等を追加しない

といった点。

構造としてはかなりHTMLに近づいた。

ただし、**「改変なし」「HTML通り」を厳密に評価すると、まだ完全ではない。**

主な理由は、画像生成モデルによって、

- 元写真そのものがピクセル単位で配置されているわけではない
- 作業者・ローラー・縞鋼板・材料の形状が生成的に再解釈されている
- HTMLの指定座標やpx値を厳密にレンダリングしているわけではない
- Noto Sans JPの指定フォント・サイズをブラウザレンダリングと同じように保証できない
- テクスチャ写真についても原画像を単純クロップしたものではなく、見た目が再生成されている

ため。

したがって、2回目は、

**「HTMLにかなり近い画像生成」**

ではあるが、

**「HTML設計書の厳密なレンダリング」**

とは別物である。

## 9. 今回明確になった制作上の重要ポイント

今回のやり取りから、次回以降の制作で守るべき条件はかなり明確になった。

- HTMLは参考資料ではなく**完成レイアウトの設計書**
- AI側でコピー、行分け、色、装飾を最適化してはいけない
- HTMLに指定された日本語をそのまま使用する
- 実素材を可能な限りそのまま使用する
- 黄色の防滑材は主役だが、黄色をグラフィック装飾には展開しない
- 強調色の青は「塗る」だけ
- 左側は独立したボックスではなくオフホワイトから写真へフェード
- メイン施工写真では「施工済み黄色面」と「未施工銀色縞鋼板」の両方を残す
- 材料テクスチャ写真は左下の補助ビジュアル
- ヘラから垂れる高粘度材料と骨材感を見せる
- 余計なアイコン、バッジ、商品、コピーを足さない
- 「見栄えが良くなるから」という理由でHTMLを変更しない

特に今回の要求を一文で表すなら、

> **「AIにデザインさせる」のではなく、「すでに決定されたHTMLデザインをAIに再現させる」**

という制作方式になる。

## 現時点の状態

現状は以下。

|項目|状態|
|---|---|
|サムネイルのテーマ|確定|
|メインコピー|確定|
|サブコピー|確定|
|色設計|確定|
|左右構成|確定|
|メイン施工素材|提供済み|
|材料テクスチャ素材|提供済み|
|HTML設計書|提供済み|
|HTMLへの忠実性という要求|明確化済み|
|1回目生成|改変が多く不採用方向|
|2回目生成|改善したが厳密なHTMLレンダリングではない|
|次に詰めるべき論点|「画像生成」で行くか「HTMLを実レンダリング」するか|

この最後の点は重要で、**本当に「改変なし」を要求するなら、生成AIで再描画させるより、HTMLに実画像を埋め込みブラウザで3840×2160として直接レンダリングする方が目的に合っている**。画像生成はどうしても写真・文字・座標を再解釈するため、HTMLとの完全一致には向いていない。今回のHTMLもそもそも3840×2160の座標系を持っており、その方式を想定した設計になっている。

### 引き継ぎ用要約

- **行ったこと**：黄色い防滑材の施工写真・材料テクスチャ写真・HTML設計書を基に、サムネイルを2回生成。1回目の独自改変に対し「改変せずHTML通り」と修正方針を明確化した。
- **次の具体的アクション**：HTML忠実再現を最優先するなら、画像生成ではなく、指定素材をHTMLの各スロットへ配置して3840×2160で直接レンダリングする。
- **使用ファイル**：`thumbnail_a_yellow_offwhite_revised(1).html` / `main_construction_yellow.png` / `texture_material_yellow.png`
- **主要判断**：HTMLは「参考デザイン」ではなく「完成設計書」として扱い、AI側でのコピー変更・再レイアウト・装飾追加をしない。
- **未解決点**：生成AIによる近似再現を続けるか、HTMLレンダリング方式へ切り替えて設計値通りの画像を作るか。
