# 要約の実践フレーム｜問い・答え・根拠

## 結論

「要点＝問い×答え×根拠」は、要約そのものの普遍的な定義ではなく、主張を含む文章を整理するための実践的なフレームワークである。

特に次の文章と相性がよい。

- 解説文
- 論説文
- 調査報告
- 会議や議論のまとめ
- 質問に答える文章
- 課題と提案を扱う文章

一方、物語、手順書、時系列記録、用語集などは、別の構造で要約した方が分かりやすい場合がある。

## 3つの要素

### 問い

その文章が、何を明らかにしようとしているか。

問いが本文に明記されていない場合は、筆者が答えようとしている問題を一文で言い換える。

### 答え

問いに対する、文章の中心的な結論や主張。

細かな説明を並べるのではなく、「結局、何が言いたいのか」を一文にする。

### 根拠

答えを支える、重要な理由、事実、データ、事例。

すべての根拠を残すのではなく、結論を理解・検証するために必要なものを選ぶ。

## 基本形

> **問い：** 何が問題か、何を知りたいか  
> **答え：** 筆者の結論は何か  
> **根拠：** なぜそう言えるのか

この3点をつなげると、次の形になる。

> 文章は「○○か」という問いを扱い、「△△である」と結論づけている。主な根拠は□□である。

## 要約の手順

1. 文章全体を読み、話題を確認する。
2. 筆者が答えようとしている問いを一文にする。
3. 問いへの答えに当たる文を探す。
4. 答えを支える根拠を1～3点に絞る。
5. 例、言い換え、修辞、重複を取り除く。
6. 元の文章にない評価や推測を加えていないか確認する。
7. 要約だけを読んでも、問いと結論の関係が分かるか確認する。

## 架空の例

以下はフレームワークの説明用に作成した架空の文章であり、実在する調査結果ではない。

### 例文

あるチームは、会議前に議題を共有する方法を20回試した。議題を共有した会議の平均時間は35分、共有しなかった会議は50分だった。また、参加者からは準備しやすくなったという意見が多かった。チームは、会議前に議題を共有することで、会議時間を短縮しやすいと判断した。

### 問い

会議前に議題を共有すると、会議の進行へどのような影響があるか。

### 答え

議題を事前共有すると、会議時間を短縮しやすい。

### 根拠

架空の20回の比較では、事前共有した会議の平均時間が35分、共有しなかった会議が50分であり、参加者からも準備しやすいという意見があった。

### 一文要約

架空の比較では、議題を事前共有した会議の方が平均時間が短く、参加者も準備しやすいと回答したため、事前共有は会議の効率化に役立つと判断された。

## 向いていない場合の代替フレーム

| 文章の種類 | 要約の軸 |
| --- | --- |
| 物語・旅行記 | 出来事、転換点、結末 |
| 手順書 | 目的、前提、手順、注意点 |
| 会議録 | 決定、理由、担当、期限、未決事項 |
| 比較記事 | 比較対象、評価軸、違い、結論 |
| 調査メモ | 調査目的、方法、結果、限界 |
| 用語解説 | 定義、特徴、具体例、関連語 |

## よい要約の確認項目

- 元の文章の中心的な問いを外していない
- 答えを自分の意見へ置き換えていない
- 根拠の重要度を見誤っていない
- 数値や固有名詞を変えていない
- 例を事実や一般則として扱っていない
- 短くするために必要な条件や例外を落としていない
- 原文を読んでいない人にも意味が通じる

## まとめ

「問い・答え・根拠」は、文章の論理的な骨格を抜き出すための道具である。

ただし、すべての文章を同じ形へ押し込むのではなく、文章の目的に応じて「時系列」「比較」「手順」「決定事項」など、別の軸と使い分ける。
