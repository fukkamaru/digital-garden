イベント ID 7がどういったものか教えてください。

イベント ID 7 は、Windows の **「Disk」ソースが記録するストレージ関連エラー**の一つで、典型的には次のようなメッセージです。

> `デバイス \Device\Harddisk0\DR0 に不良ブロックがあります`

意味としては、Windows がそのディスク上のある領域へ読み書きしようとした際に、**正常にアクセスできないブロックを検出した**ということです。

今回のポイントは、「不良ブロック」という言葉です。HDDでは物理的な不良セクタとして理解しやすいですが、SSDでも同様のイベントは発生します。SSDではNANDフラッシュ内部の不良ページ・不良ブロック、コントローラ側のエラー、論理アドレスと物理領域のマッピング異常、あるいは接続・I/O経路の問題などが背景にあり得ます。

つまり、イベント ID 7 は単に「Windowsの設定がおかしい」という種類のイベントではありません。**ストレージI/Oのかなり低い層で、Windowsが正常に読み書きできなかったことを示す警告性の高いイベント**です。

### `Harddisk0\DR0` の意味

ここも誤解しやすいところです。

`Harddisk0` は「HDDである」という意味ではなく、Windows内部での**物理ディスク番号**です。したがって、

- HDD
- SATA SSD
- NVMe SSD

のどれでも `Harddisk0` と表示されます。

`DR0` も同様にデバイス識別子の一部です。

今回のようにPCにSSDしか搭載されていないなら、`\Device\Harddisk0\DR0` は基本的にそのSSDを指していると考えてよいです。

### 1回だけ出た場合と、繰り返す場合は意味が違う

Event ID 7が**1回だけ**出たなら、瞬間的なI/O障害や接続問題なども考慮できます。

しかし、

- 数十回
- 数百回
- 複数日にわたって継続
- 同じDisk 0で繰り返す

となると意味合いが変わります。

この場合は、

**「一時的な偶発エラー」よりも「ストレージ側の継続的異常」**

を強く疑います。

今回のPCは、以前確認した範囲では**8月19日以降に100件を超えるEvent ID 7が出ており、翌日にも継続していた**ので、こちら側に分類した方が適切です。

### ユーザープロファイル破損との関係

今回の流れでは、

1. ユーザープロファイルが正常に読み込めなくなる
2. WindowsがTEMPプロファイルで起動する
3. イベントログを調査
4. DiskのEvent ID 7を大量に発見

という順番でした。

Event ID 7だけから、

**「Event ID 7が直接プロファイルを壊した」**

と断定することはできません。

ただし、ユーザープロファイルは

- `NTUSER.DAT`
- AppData内の各種ファイル
- レジストリハイブ
- ユーザー固有設定

など、多数のファイルを起動時に読み込みます。

そのファイル群の一部が存在する領域でストレージ読み取りエラーが発生すれば、**プロファイルの読み込み失敗やファイル破損につながることは十分あり得ます**。

したがって今回については、

**「プロファイル障害」と「Event ID 7」が完全に無関係だったと考えるより、SSD異常がプロファイル障害の原因または誘因になった可能性を考える方が自然**

です。

### CHKDSKとの違い

Event ID 7は「Windowsが実際のI/O中に異常を検知した記録」です。

一方、`chkdsk` は主にNTFSなどの**ファイルシステム整合性を検査・修復するもの**です。

そのため、

`chkdskで問題なし`

でも

`Event ID 7が出る`

ことはあり得ます。

特にSSDの場合は、Windowsから見える論理ファイルシステムよりさらに下の、

**SSDコントローラ → NANDフラッシュ**

側で問題が起きている可能性があるためです。

そのため今回については、

**「CHKDSKで直れば終了」タイプの問題として扱うべきではありません。**

要するにEvent ID 7は、

> **Windowsがストレージ上のある領域へ正常にアクセスできなかったことを記録するDiskエラー**

です。

そして今回のように**同一SSDで大量かつ継続的に記録されるEvent ID 7は、SSDの健全性を疑う十分な理由になります。**

新しく作った臨時アカウントが現在正常に使えていることと、**SSD自体が正常であることは別問題**、という理解が重要です。
