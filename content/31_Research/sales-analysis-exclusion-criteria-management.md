# 売上分析表から除外する

## このノートの位置付け

このノートは、Power Queryで売上分析の対象を切り替えるための、Excelマスタの設計を整理した資料である。特定の得意先や商品を一律に除く処理だけでなく、分析目的に応じて対象範囲を明示的に管理する方法を扱う。

ここで示すファイル名、シート名、パス、担当者名は設計を説明するためのサンプルであり、現行環境の構成や実在の組織情報を表すものではない。

## 解決したい問題

売上データには、分析目的に応じて対象外にする得意先・商品や、特定の営業担当者・組織に絞る条件が存在する。こうした条件をPower QueryのMコードへ直接書くと、条件変更のたびにコードを直す必要があり、どの条件が使われているかも確認しにくくなる。

そこで、条件はExcelマスタで管理し、Power Queryはそのマスタを読んで処理する。これにより、分析条件をコードから分離し、変更内容を表として確認できるようにする。

## 検討した選択肢

### 対象外フラグだけで管理する案

最初は、得意先ごとに `対象外フラグ` を置き、`1` を除外、`0` を対象とする案を考えた。

| 得意先コード | 得意先名称 | 対象外フラグ |
| --- | --- | ---: |
| 000001 | A社 | 1 |
| 000002 | B社 | 0 |

この案は処理しやすい一方、表だけを見た人が `0` と `1` の意味を判断しにくい。`除外ステータス` に言い換えても、「有効」が分析対象として有効なのか、除外設定が有効なのかが曖昧になる。

### 分析対象を明示する案

採用するのは、否定形の除外ではなく、分析対象かどうかを表示する方法である。

| 得意先コード | 得意先名称 | 分析対象 |
| --- | --- | --- |
| 000001 | A社 | 対象 |
| 000002 | B社 | 対象外 |

`対象` と `対象外` は、Excel上で条件を見直す人にも意味が伝わる。Power Queryでは `分析対象 = "対象"` を使う分析だけを残す、または分析ごとの条件に応じて絞り込む。

## 採用したマスタ構成

分析ごとに別ファイルを作る方法も検討した。たとえば `SalesmanAnalysisMaster.xlsx`、`OrganizationAnalysisMaster.xlsx`、`DirectorAnalysisMaster.xlsx` のように分けると、用途ごとの見通しはよい。

しかし、同じ得意先や商品を複数ファイルで管理すると、更新漏れ、条件の不整合、正本の不明確さが起きやすい。そのため、分析条件は一つの `SalesAnalysisMaster.xlsx` に集約し、用途ごとにExcelテーブルを分ける方針を採用する。

```text
SalesAnalysisMaster.xlsx
├─ MstCustomers         # 得意先ごとの分析対象・区分
├─ MstProducts          # 商品ごとの分析対象・区分
├─ MstSalesRepCustomers # 営業担当者と得意先の対応
├─ MstOrganizations     # 組織別の分析条件
├─ MstDirectors         # 役員向け分析条件
└─ MstAnalysisRules     # 分析ごとの追加条件
```

シートは利用者が見やすくするための区分であり、Power Queryではシート全体ではなく、各シート上のExcelテーブルを読み込む。テーブルにすれば、データ行の追加に合わせて範囲が広がり、ヘッダー昇格も不要になる。

## サンプル：営業担当者に紐づく得意先を読む

`kyouto_yasue` は、担当者別に得意先を絞る構成を説明するための架空のシート名である。

```powerquery
let
    _ソース = Excel.Workbook(
        File.Contents("C:\\Users\\kyoupatty029\\data_files\\master\\SalesAnalysisMaster.xlsx"),
        null,
        true
    ),
    _テーブル選択_営業担当者得意先 =
        _ソース{[Item="MstSalesRepCustomers", Kind="Table"]}[Data],
    _型変換_カラム = Table.TransformColumnTypes(
        _テーブル選択_営業担当者得意先,
        {
            {"得意先コード", type text},
            {"得意先名", type text},
            {"担当者名", type text}
        }
    ),
    _抽出_kyouto_yasue = Table.SelectRows(
        _型変換_カラム,
        each [担当者名] = "kyouto_yasue"
    )
in
    _抽出_kyouto_yasue
```

元の検討では `kyouto_yasue` というシートを直接読む方法も用いていた。現在の設計では、担当者名を値として持つ `MstSalesRepCustomers` テーブルへ寄せ、条件の追加や比較をしやすくする。

## Power Queryのステップ名

ステップ名はPower Queryが自動生成する曖昧な名前ではなく、処理内容と必要に応じて対象を示す。

```text
_ソース
_テーブル選択_営業担当者得意先
_型変換_カラム
_除外_対象外得意先
_除外_対象外商品
_抽出_営業担当者
_ソート_売上金額降順
_並べ替え_カラム
_削除_不要カラム
_追加_分析期間
```

この命名なら、詳細エディターを開いたときに処理の順序と目的を追いやすい。

## 判断基準

- 条件が変わる可能性があるなら、Mコードへ直接書かずマスタで管理する。
- フラグ名は、利用者が表だけで意味を判断できる言葉にする。
- マスタはファイルを増やすより、一つの正本にテーブルとして集約する。
- 分析目的固有の条件は、共通マスタを壊さず追加テーブルまたは分析ルールとして分ける。
- シート名や担当者名などの例は、公開用の架空表記として扱い、実在の情報を混ぜない。
