# 4. organization と org の議論

## 質問

```
organization↓org
```

に略した方が良いか？

---

## 結論

### 個人的には org に統一する方が良い

理由

- フォルダ名が既に org
- Power Queryの変数名も短くなる
- パスが短くなる
- タイプミスが減る

例

```
org_kpk_data.xlsxorg_kpsc_data.xlsxorg_region_monthly_data.xlsxorg_region_cumulative_data.xlsx
```

---

## ただし

organizationでも問題ない。

重要なのは

```
organizationorganizationorganizationorganization
```

または

```
orgorgorgorg
```

のように統一すること。

# 7. データクレンジングファイルの重複問題

あなたから次の例が提示された。

```
organaizaion_kpk_dataorganaizaion_region_cumulative_dataorganaizaion_general_cumulative_data
```

※ organization のスペルは誤記と思われる。

---

## 重要な前提

これらは

```
同じローデータを読み込む
```

とのこと。

---

つまり

```
CSV ↓クレンジング ↓同じクレンジング結果
```

である。

---

# 8. ここで発生する問題

現在の構成だと

```
org_kpk_data.xlsxorg_region_cumulative_data.xlsxorg_general_cumulative_data.xlsx
```

が全て

```
同じデータクレンジング処理
```

を持つことになる。

---

その結果

### 問題①

修正箇所が3箇所になる

例

```
商品名正規化マスタ追加
```

↓

```
org_kpk_dataorg_region_cumulative_dataorg_general_cumulative_data
```

全て修正

---

### 問題②

処理差異が発生する

```
Aだけ修正Bは修正漏れ
```

が起きる

---

### 問題③

Power Query保守コスト増加

同じMコードが複数存在する

---

# 9. 推奨構成

データクレンジングは1本化

---

## クレンジング

```
org_cleaned_data.xlsx
```

または

```
org_sales_cleaned_data.xlsx
```

---

### 内容

```
CSV ↓org_cleaned_data
```

のみ

---

# 10. 分析ファイルは分離

分析ごとにファイルを分ける

```
org_kpk_analysis.xlsxorg_region_cumulative_analysis.xlsxorg_general_cumulative_analysis.xlsx
```

---

構成図

```
CSV ↓org_cleaned_data.xlsx ↓ ├─ org_kpk_analysis.xlsx ├─ org_region_cumulative_analysis.xlsx └─ org_general_cumulative_analysis.xlsx
```


# 最終結論

今回の話で最も重要なのは、

**「同じローデータを読み込み、同じクレンジング処理を行うなら、データクレンジングファイルは1つに統合する」**

という点です。

その上で、

```
org_cleaned_data.xlsx
```

を共通データソースとして、

```
org_kpk_analysis.xlsxorg_region_cumulative_analysis.xlsxorg_general_cumulative_analysis.xlsx
```

などの分析ファイルへ接続する構成が、保守性・再利用性・Power Query管理の観点で最も扱いやすい構成だと思います。
