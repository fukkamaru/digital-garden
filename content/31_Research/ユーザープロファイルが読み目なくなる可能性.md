### 1. セキュリティソフトは十分あり得ます

これは単なる推測ではありません。

Microsoft自身がTEMPプロファイル問題のトラブルシューティングで、

> 複数回再起動しても直らない場合、ウイルス対策ソフトやログイン時にスキャンするアプリを一時的に無効化する

という手順を案内しています。[Microsoft サポート](https://support.microsoft.com/en-us/windows/security/identity-signin/we-can-t-sign-in-to-your-account-error-message)

理由は、ユーザープロファイルには

```
C:\Users\<ユーザー>\NTUSER.DAT
```

などの重要なレジストリハイブがあります。

ログオン時にWindowsの **User Profile Service** がこれを開こうとした瞬間、別プロセスがファイルを掴んでいると、

```
Windows
 ↓
NTUSER.DATを開きたい
 ↓
セキュリティソフト等が使用中
 ↓
開けない
 ↓
本来のプロファイルをロードできない
 ↓
TEMPプロファイルへ
```

ということが起こり得ます。

実際、Microsoftが示しているUser Profile Serviceのエラー例にも、

> The process cannot access the file because it is being used by another process.

という `NTUSER.DAT` のアクセス失敗があります。[Microsoft Learn](https://learn.microsoft.com/en-us/answers/questions/2672768/user-profile-service-event-1508?utm_source=chatgpt.com)

### 2. Windows Updateも候補です

これもあり得ます。ただし、

**「Windows Updateそのものがプロファイルを壊した」**

と直ちに考えるのは早いです。

考えやすいのは、

```
Windows Update
 ↓
再起動・システムファイル更新
 ↓
ログオフ／プロファイルのアンロード
 ↓
何らかの理由で正常終了しない
 ↓
次回ログオン時にプロファイル読み込み失敗
```

という**更新をきっかけとした二次的な問題**です。

MicrosoftもWindowsのアップグレード後に一時プロファイルになり、ファイルが見えなくなるケースを公式サポートで扱っています。[Microsoft サポート](https://support.microsoft.com/en-us/windows/deployment/install-upgrade/find-lost-files-after-upgrading-windows)

したがって、

- Windows Update直後
- 更新後の再起動時
- 更新途中の電源断
- 更新後最初のログオン

などで発生したなら、関連性は調べる価値があります。

今回についても、別チャットで確認していた**8月19日のWindows Updateの直後に現象が出た**という時間関係は重要です。ただし現時点では「Windows Updateが原因」とまでは断定できません。

### 3. 高速スタートアップは少し違います

これは意外と重要な区別です。

高速スタートアップではシャットダウン時に、

```
ユーザーセッション
    → ログオフする

Windowsカーネル／ドライバ
    → 完全終了せず休止状態として保存
```

という動きをします。Microsoftの仕様でも、**ユーザーセッションはいったんログオフされる**ことが明記されています。[Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/fast-startup-causes-system-hibernation-shutdown-fail)

したがって、

> 高速スタートアップが有効だからユーザープロファイルが正常に閉じられない

と単純には言えません。

一方でMicrosoftは、高速スタートアップによって特定条件でシャットダウン／休止処理が失敗する事例も文書化しています。[Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/fast-startup-causes-system-hibernation-shutdown-fail)

なので位置付けとしては、

**直接犯というより、システム状態・ドライバ・シャットダウン問題を残す補助要因になり得る**

くらいです。

なお、**「再起動」には高速スタートアップは適用されません**。再起動はフルブートです。[Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/fast-startup-causes-system-hibernation-shutdown-fail)

これは原因切り分けにも使えます。

## むしろ一番重要なのは `NTUSER.DAT` などです

ユーザープロファイルは単なる

```
C:\Users\ユーザー名
```

というフォルダではありません。

中にある

```
NTUSER.DAT
UsrClass.dat
```

などをWindowsがレジストリとしてロードします。

Microsoftは、これらが

- 読み取り専用になっている
- NTFSアクセス権が正しくない

だけでもプロファイルロードが失敗すると説明しています。[Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-server/user-profiles-and-logon/desktop-location-unavailable)

イメージとしては、

```
アカウント認証
   ↓
成功
   ↓
ProfileListからプロファイル場所を特定
   ↓
C:\Users\本来のユーザー
   ↓
NTUSER.DAT等をロード
   ↓
ここで失敗
   ↓
User Profile Service
   ↓
TEMPプロファイルでログイン
```

です。

つまり今回、

**「パスワードやPINがおかしくなった」問題ではなく、認証後のプロファイル読み込み段階で失敗している可能性が高い**

わけです。

## 今回、原因を推測だけで終わらせる必要はありません

かなり重要なのですが、Windowsにはこのためのログがあります。

Microsoftが案内している正式な調査場所は、

```
イベント ビューアー
  ↓
アプリケーションとサービス ログ
  ↓
Microsoft
  ↓
Windows
  ↓
User Profile Service
  ↓
Operational
```

です。[Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-server/user-profiles-and-logon/troubleshoot-user-profiles-events)

ここには**プロファイル読み込みに失敗した時刻の直前・直後の処理**が残っています。

さらに通常の

```
Windows ログ
 → Application
```

にもUser Profile Service関連エラーが残っている可能性があります。

これは今の修復作業とは違って**読み取りだけなので、レジストリを書き換える前にやっておく価値があります。**

特に今回なら、8月19日の正常だった最後のログオンから、TEMPプロファイルになった最初のログオンまでの **User Profile Serviceイベント**を見れば、

- `NTUSER.DAT` が開けなかった
- Access Denied
- ファイルが使用中だった
- ファイルが存在しなかった
- レジストリ読み込みエラー
- プロファイルパス問題

など、原因をかなり絞れる可能性があります。[Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-server/user-profiles-and-logon/troubleshoot-user-profiles-events)

**修復を続ける前に、このログを一度確認するのはかなり合理的です。** 現在の状態を変更しない調査なので、原因究明をしたいなら私はここを先に見ます。
