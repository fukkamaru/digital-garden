# パワークエリ内部の整理

売上分析の処理を、`raw → clean → ref → report`という段階に分ける場合、`clean`と`std`は同じ意味ではない。判断基準は、変換がデータを扱いやすく整えるだけか、後段が依存する標準ルールを確定するかである。

|段階|役割|主な処理|
|---|---|---|
|`raw`|取得した状態を保持する|入力データの読み込み|
|`clean`|扱える状態へ整える|型変換、空白・不要列の処理、NULL処理、表記ゆれ、明白な誤入力の補正|
|`std`|標準ルールへ寄せる|コード体系統一、カテゴリ辞書適用、単位換算、売上定義・丸めの固定|
|`ref`|参照・結合のために整える|キー付与、ディメンション整備、結合用中間テーブル|
|`report`|分析結果を提示する|集計、可視化、最終レポート|

少数の品名・コード・カテゴリの誤りを直す程度なら`clean`でよい。一方、カテゴリ付けを辞書化する、複数システムのコードを統一する、単位や集計定義を固定するなど、値の意味や後段の基準を変える処理は`std`として分ける。

`raw → clean → ref → report`で足りる運用では、2段目を`clean`とする方が誤解が少ない。標準化まで必要になった場合は、`raw → clean → std → ref → report`へ拡張する。
