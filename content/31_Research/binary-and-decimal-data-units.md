# KB・MB・GBとKiB・MiB・GiBの違い

MiBなどの二進接頭辞は、スマートフォンの普及をきっかけに生まれたものではない。`KB`、`MB`、`GB`が10進・2進のどちらを指すか曖昧だった問題を分けるため、IECが1998年に承認し、1999年に標準化した表記である。

|表記|意味|バイト数|
|---|---|---:|
|KB / MB / GB|10進接頭辞によるkilobyte / megabyte / gigabyte|1,000 / 1,000,000 / 1,000,000,000 B|
|KiB / MiB / GiB|2進接頭辞によるkibibyte / mebibyte / gibibyte|1,024 / 1,048,576 / 1,073,741,824 B|

大文字の`B`はbyte、小文字の`b`はbitを表す。たとえば`MiB`はmebibyte、`Mib`はmebibitであり、同じ意味ではない。

## なぜ分ける必要があるのか

コンピュータでは`2¹⁰ = 1,024`が扱いやすく、従来は`1 KB = 1,024 B`のような慣習的な表現が多かった。一方、SI接頭辞のkilo、mega、gigaは本来10の累乗である。ストレージ機器では10進表示、メモリやOSでは2進計算が使われることがあり、同じ「GB」でも表示上の容量が異なる混乱が生まれた。

二進接頭辞は、10進系と2進系を明確に分けるための表記である。スマートフォンやSSDの普及は、この差を一般利用者が意識しやすくした要因ではあるが、制度化の原因ではない。

## 2010年ごろに見かけた可能性

2010年ごろの大学教育や一般的なIT利用では、1024倍の内容を`MB`や`GB`と書く慣習がなお強く、KiB・MiB・GiBを聞かなかったことは不自然ではない。

Gitの進捗表示やOSSの配布サイトでは、当時も`KiB`や`MiB`を目にする可能性があった。一方、`ls -lh`、`du -sh`、`df -h`などのLinuxコマンドでは、`K`、`M`、`G`という短い表示が多く、Linuxを日常的に使っていても二進接頭辞を意識する頻度は限られる。したがって、Gitや厳密なドキュメントを調べる中で初めて知る経路は自然である。

このノートの歴史的な説明は作成時点の調査に基づく。容量を扱う実務では、表記だけで判断せず、対象ソフトや仕様書が10進・2進のどちらを採用しているかを確認する。
