| 工程 | 何をするか | この工程で決めること / 成果物 |
| --- | --- | --- |
| **1. 訴求整理** | 動画内容をそのまま全部載せるのではなく、「視聴者に最初に何を伝えるか」を整理する。動画の特徴、メリット、施工方法、他方式との違いなどを洗い出し、サムネイルに必要なものだけ残す。 | **主訴求1つ**、視覚的フック1つ、補助訴求0～1つ。動画内では重要でもサムネイルでは不要な情報も明確にする。 |
| **2. アートディレクション** | サムネイル全体の見た目の方向性を決める。施工写真は背景が複雑になりやすいため、文字量・色数・フォント・写真比率・余白・装飾量を先に制限する。 | 「写真主役か文字主役か」「工業Editorial系」などの方向性、使用色、フォント、装飾ルール、最大要素数などの**デザインルール**。 |
| **3. デザイン方向案の比較** | いきなりHTMLを作らず、同じ訴求について2～3種類の構成案を考える。例：左文字／右施工写真、写真全面＋下帯、施工写真＋テクスチャ写真など。 | 採用する**基本構成1案**。必要ならBefore/Afterあり・なしのような派生案も決める。 |
| **4. ワイヤーフレーム設計** | 色や細かな装飾より先に、どこに何を置くかを決める。文字領域、メイン写真、サブ写真、比較素材などの占有面積と視線誘導を整理する。 | 各領域の位置、比率、優先順位。「左38%文字／右62%写真」などのレイアウト骨格。 |
| **5. コピー・タイポグラフィ設計** | メインコピー、補助コピー、強調する単語を確定する。同時にフォント、ウェイト、サイズ差、行数、文字色を決める。 | メインコピー原則2行、補助コピー原則1つ。フォントファミリー、文字サイズ、ウェイト、強調色、行間など。 |
| **6. 配色・余白設計** | 使用色を制限し、写真の情報量と文字が競合しないようにする。施工写真上へ直接文字を載せる場合は、グラデーションなどで「静かな文字領域」を作る。 | 基本3色程度、外周余白、要素間余白、文字領域の背景処理。「空いているから追加する」を禁止する。 |
| **7. 素材選定・準備** | 動画の切り抜きや既存写真から、設計に合う素材を選ぶ。重要なのは画質だけでなく、ローラー、施工面、材料など必要な情報が見え、不要な背景が少ないこと。 | メイン施工写真、テクスチャ写真などの**正式素材セット**。意味が分かる英数字ファイル名に統一する。 |
| **8. 不足素材の補完** | 設計上必要なのに素材が存在しない場合だけ画像生成を使う。完成サムネイルを生成するのではなく、Before、After、質感写真などの**部品だけ**を作る。 | HTML設計書から参照できる不足素材ファイル。既存素材で足りるならこの工程は省略。 |
| **9. HTML設計書化** | 確定した設計を、別の画像生成AIが解釈できるHTMLへ変換する。HTMLは完成サムネイルをブラウザ表示するものではなく、**画像生成AI向けの設計図**として記述する。 | 3840×2160座標、要素サイズ、文字内容、フォント、色、余白、素材ファイル名、用途、クロップ、優先順位、禁止事項などをDOM・CSS・`data-*`属性に記述したHTML。 |
| **10. AIへHTML＋素材を投入** | HTML設計書と、そのHTMLが参照する素材画像を同時に新しいチャットへ渡す。AIには「HTMLを完成Webページとして描画せず、設計図として解釈して画像生成する」と指示する。 | 完成したYouTubeサムネイル画像。 |
| **11. 結果評価** | 出力画像が良い／悪いだけで判断せず、「どの設計情報が正しく再現され、何が崩れたか」を確認する。特に情報量、文字階層、余白、写真の扱い、色数、AI広告感を見る。 | 問題点を「画像生成AIの偶然」ではなく、**HTML設計書側で改善可能か**切り分ける。 |
| **12. HTML設計書の改善** | AIへの追加プロンプトを延々と増やすのではなく、再現性を高めるためにHTML側を修正する。たとえば「写真枠最大2つ」「バースト禁止」「余白15%以上」などを設計条件として強化する。 | 次回以降にも流用できる、より精度の高いHTML設計書。 |
| **13. テンプレート化** | 複数回テストして安定したら、案件固有部分と共通部分を分離する。 | 「訴求」「コピー」「素材」「レイアウト」だけ差し替えれば使える**サムネイル設計書テンプレート**。 |
