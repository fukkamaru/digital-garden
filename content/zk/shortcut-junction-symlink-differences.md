それぞれの違いは
- ショートカット：「あそこにあります」という案内板
- ジャンクション：別のフォルダを「ここにあるフォルダ」として見せる
- シンボリックリンク：別のフォルダ/ファイルを「ここにあるもの」として見せる

より詳しい違いを表にまとめたもの

| 項目                           | ショートカット         | ジャンクション    | シンボリックリンク       |
| ---------------------------- | --------------- | ---------- | --------------- |
| Windowsでの代表的な形式              | `.lnk`          | NTFSのリンク機能 | NTFSのリンク機能      |
| ファイル                         | △ ファイルへのショートカット | ×          | ○               |
| フォルダ                         | ○               | ○          | ○               |
| 普通のファイル/フォルダのように見える          | ×               | ○          | ○               |
| アプリからの[透過性](transparency.md) | 透過的に使える         | 基本×        | ○               |
| 別ドライブへのリンク                   | ○               | ○          | ○               |
| ネットワーク先へのリンク                 | ○               | 基本的に不向き    | ○               |
| エクスプローラーでの利用                 | 非常に簡単           | 普通のフォルダに近い | 普通のファイル/フォルダに近い |
| 用途                           | 人間が開くため         | フォルダ構造の接続  | 汎用的なリンク         |

表を見てもその違いはイマイチ分かり難いが、ショートカットについての理解を深めると、それぞれの違いが何となく分かる。

ショートカットはファイル/フォルダのいずれも`.lnk`という拡張子のファイルである。その実体は「リンク先の情報が書かれたファイル」であり、アプリケーションソフトが解釈を行う。

特にWindows Explorer（というアプリケーションソフト）は`.lnk`の意味を理解しているので、クリックすることで該当のファイルやフォルダにアクセスできるし、その他のアプリケーションソフトでは意味を解釈出来ないため、その先へとアクセスすることは出来ない。
→ [[power queryだとショートカットリンクが使えなかった話]]

そのため、人間にとってはリンク先の操作が可能となっている。

対してい、ジャンクションとシンボリックリンクは**Windowsのファイルシステム側が解釈するリンク** になる。
この2つの違いは、ファイルも扱えるかどうかの違い。


| -              | `.lnk`        | ジャンクション / シンボリックリンク |
| -------------- | ------------- | ------------------- |
| リンクだと判断する主体    | Explorerなど    | Windows側            |
| リンク先を解決する主体    | Explorerなど    | Windows側            |
| アプリがリンクを意識する必要 | ある場合が多い       | 基本的にない              |
| ファイルシステムからの見え方 | `.lnk`というファイル | リンクとして処理される特殊なエントリ  |
