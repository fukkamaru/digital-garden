# サムネイル制作におけるSVGの役割

SVGは、完成PNG/JPEGよりも文字・図形・配置の構成情報を保持し得る受け渡し用の形式である。この制作では、人がFigmaで方向性を変えた後、その変更後の見た目をAIへ示し、元HTML/CSSを再調整するための参照データとして扱う。この方法は検証済みである。

| データ | 主な役割 | 代替できないもの |
| --- | --- | --- |
| `.fig` | 人がFigmaで編集を続ける元データ | SVGやPNG/JPEGでは完全に代替しない |
| SVG | 構成・文字・図形・配置を参照する受け渡し候補 | Figmaの編集履歴や全機能を保証しない |
| HTML/CSS | ローカル画像を読み込んで完成表示する実装 | SVGだけから自動で完全再現できるとは限らない |
| PNG/JPEG | 確認・掲載・配布する完成画像 | 要素単位の再編集には向かない |

## Figmaで方向性を変えた場合

1. `.fig` を人による編集の正本として残す。
2. 変更後の対象フレームをSVGで書き出す。
3. SVGと元HTML/CSSをAIへ渡し、構図や見た目の変更を比較できる状態にする。
4. AIはSVGを手がかりにHTML/CSS側を再調整し、ローカル画像を表示して確認する。

SVGだけで元のHTML/CSSを正確に書き換えることは前提にしない。SVGと元HTML/CSSを併用して変更を比較する。写真、マスク、効果、フォント、Figma固有の情報は必要に応じて表示確認するが、SVGを完成画像の再生成に使うものではない。

実SVGで確認できたことは[HTMLサムネイル制作：SVG観察記録](html-thumbnail-svg-observation.md)に、SVGとPNG/JPEGの一般的な違いは[SVGとPNG/JPEG：構造と再編集性の違い](svg-vs-raster-image-formats.md)に残す。
