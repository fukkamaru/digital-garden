# 今回実現したい構成

基本的には以下の3つの作業を想定しています。

## 1. `_AI Start Here` の更新

既存の `_AI Start Here` に、AI作業ログ運用についての入口だけを追加してください。

ここには詳細なログルールを大量に記述せず、

- AIが意味のある作業を行った場合は作業ログを残すこと
    
- 詳細な判定・記述方法については専用のログルールノートを参照すること
    

が分かる程度にしてください。

`_AI Start Here` はAIが最初に読むブートストラップ／ルーティング用ノートとして、できるだけ簡潔に維持したいです。

---

## 2. AI作業ログ用ノートの作成

現時点での候補ファイル名は、

`AI_Work_Log.md`

です。

ここにはAIが実際に行った意味のある作業を時系列で追記していく想定です。

単なる詳細な操作履歴ではなく、

**「AIが何をクリックしたか」ではなく「AIが何を行い、何が変わったか」**

を残すWork Logとして設計してください。

ログ1件あたりに必要な項目についても検討してください。

現時点では、例えば以下を想定しています。

- 日時
    
- 作業内容
    
- 結果
    
- 作成・変更・移動したファイル
    
- 重要な判断とその理由
    
- 必要に応じて主要な参照元
    
- 次のアクション／未解決事項
    

ただし、項目を増やしすぎてログ記録自体が負担にならないようにしてください。

---

## 3. AI作業ログ記述ルールの作成

現時点での候補ファイル名は、

`_AI_Work_Log_Rules.md`

です。

このノートには、AIが「何をログに残し、何を残さないか」を判断できるルールを記述してください。

### 基本思想

ログに残すかどうかは、次の3つを基本判定とします。

1. 何かの状態を変えたか？
    
2. 再利用可能な成果・結論・判断を生んだか？
    
3. 後日「なぜこうなっているのか」を説明するために必要か？
    

いずれかがYesなら原則としてログ対象とします。

3つともNoなら原則としてログ不要です。

### 原則としてログ対象

例えば以下です。

- ファイルの新規作成
    
- ファイル内容の変更
    
- ファイル名変更
    
- ファイル移動
    
- ファイル削除
    
- フォルダの作成・変更・移動・削除
    
- 設定変更
    
- Gitのcommit / push / merge等
    
- 外部サービスへの書き込み
    
- データ変換・一括処理
    
- スクリプト・自動化を実行し、成果物や状態が変化した場合
    
- エラー対応・修復
    
- 重要な判断や方針変更
    

### 条件付きでログ対象

リサーチ・調査・分析もログ対象にします。

ただし、

「Googleで検索した」  
「○○のページを見た」

といった閲覧行為自体を記録するのではありません。

例えば、

- 技術調査
    
- 製品調査
    
- 市場調査
    
- 原因調査
    
- 複数資料の比較
    
- 検証
    

などを行い、意味のある結論・発見・判断が得られた場合に、

- 何を調べたか
    
- 何が分かったか
    
- その結果どう判断したか
    

を記録します。

証拠や出典が重要な調査では、結論を支えた主要な参照元だけを記録します。

### 原則としてログ不要

以下のような単純な参照行為は原則として記録不要です。

- ファイルを開いた
    
- PDFを読んだ
    
- Webページを見た
    
- フォルダ一覧を確認した
    
- ファイル名を確認した
    
- 作業のために一時的に資料を参照した
    
- 検索しただけで、特に成果・判断・変更につながらなかった
    

ただし、それらの参照によって重要な発見・判断・変更が生じた場合はログ対象にしてください。

つまり、

**参照しただけ → ログ不要**

**参照 → 発見・判断・変更につながった → ログ対象**

という考え方です。

# 設計上の注意

ログを「AIの全操作履歴」にはしないでください。

後から、

- 何をしたのか
    
- なぜそうしたのか
    
- 何が変わったのか
    
- どの成果が得られたのか
    
- 次に何をすればよいのか
    

を追跡できることを目的とします。

また、同じセッション内で細かな操作を何十件も個別ログにせず、意味のある一つの作業単位としてまとめる方向で検討してください。

既存の `_AI Start Here` やその他のコンテキストルールに、すでに同種のログ・記録・引き継ぎルールがある場合は、重複するルールを新たに作らず、既存ルールとの役割分担を提案してください。

ファイル名についても、

- `AI_Work_Log.md`
    
- `_AI_Work_Log_Rules.md`
    

を第一候補としますが、既存Vaultの命名規則と合わない場合は、変更案とその理由を実装計画書の段階で提示してください。

## 重要

既存ファイルの変更・上書きや新規ファイル作成を行う前に、必ず実装計画を提示して一度止まってください。

私が承認した後に実装してください。
