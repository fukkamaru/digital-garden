# URLで日本語がエンコードされる理由

エンコードは、あるデータを決められた形式で表現し直すこと、デコードはその表現を解釈して元のデータへ戻すことである。URLでは、文字列の一部がパス・検索条件・区切り記号のどれなのかをネットワーク上で曖昧にしないために、パーセントエンコーディングが使われる。

## URLは文字列だけではない

次のURLでは、各記号に役割がある。

```text
https://example.com/articles/pc?q=冷却&sort=new
│       │           │       │ │      └─ 検索条件を区切る
│       │           │       │ └──────── 検索条件の値
│       │           │       └────────── 検索条件の名前
│       │           └────────────────── パス
└────────────────────────────────────── 通信方式とホスト名
```

空白、日本語、`&`、`=`のような文字をデータとして使うと、受信側がURLの構造とデータを混同する場合がある。そこで、URLの中で特別な意味を持ち得る文字を`%XX`形式へ置き換える。

## 「文字化け」とは限らない

日本語のURLが`%E6%97%A5...`のように見えるとき、多くはUTF-8を使ったパーセントエンコーディングであり、元の文字列を復元できる。この表示だけでは障害とは判断しない。

確認する順序は次のとおりである。

```text
1. URL全体か、検索語などの一部分かを確認する
2. すでに %XX の並びになっていないか確認する
3. 必要な部分だけを1回デコードして元の文字列を確認する
4. URLを組み立てるときは、動的な値だけをエンコードする
```

URL全体を再エンコードしたり、`%`を含む値を繰り返し処理したりすると、二重エンコードになる。ブラウザーで開けない場合も、まず元のURL・コピー元・どのアプリで変化したかを残し、見た目だけで文字コードの問題と断定しない。

具体的な変換例とJavaScriptでの使い分けは[URLエンコードとデコードの具体例](url-encoding-decoding-examples.md)を参照する。[URL Standard](https://url.spec.whatwg.org/)
