# 「聞き手の思考プロセス」と「作業フェーズ」に合わせた業務理解

業務を理解・説明するときは、目的を一文で置き、聞き手が最初に知る必要がある情報から並べる。7W4Hを常に同じ順番で使うのではなく、合意形成、詳細設計、工程検討、予算判断のどれが中心かで入口を変えるための仮説である。[7W4Hのグループ分け](seven-w-four-h-grouping.md)と併用して考える。

| 入口 | 向く場面 | 考える順番 |
| --- | --- | --- |
| Why先頭型 | アイデア・ビジョンを共有し、目的への納得をつくる。 | why → what → who → whom → which → when → where → how → how many → how long → how much |
| Who先頭型 | 関係者、対象、前提を確定して詳細設計やWBSの手戻りを減らす。 | who → whom → which → what → when → where → why → how → how many → how long → how much |
| How先頭型 | 工程、手順、必要工数を先に固める。 | who → how → how long → where → what → how many → when → how much → whom → why → which |
| Cost先頭型 | 予算や投資対効果を短時間で判断する。 | how much → how many → what → why → who → whom → when → where → how → how long → which |

この並び順は、内容の重要度を固定するものではない。例えば、品質・安全・法令が最初に確認すべき案件では、WhyやCostより先に制約条件を置く必要がある。聞き手が今どの判断をするのか、次の工程で何が不足すると手戻りになるのかを見て、必要な順番を選ぶ。

自分自身を聞き手として使う場合も、目的、対象、手段、数量、期限、費用のうち不透明なものを見つけ、その時点で質問する。これは、業務理解の不足を早い段階で表に出し、ミスややり直しを減らすための使い方である。
