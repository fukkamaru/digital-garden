# 1. マージ用の「key_カラム名」は片側だけか両側か

## 例

売上データ

|商品コード|商品名|
|---|---|
|001|AAA|
|002|BBB|

商品マスタ

|商品コード|分類|
|---|---|
|001|A|
|002|B|

マージ時に

- `商品コード`
- `商品名`
- `得意先コード_得意先名`

などをキーに使うことがあります。

---

## 推奨

### 加工側だけではなくマスタ側も作る

売上

|商品コード|key_商品コード|
|---|---|
|001|001|

マスタ

|商品コード|key_商品コード|
|---|---|
|001|001|

として

```
key_商品コード↓key_商品コード
```

で結合する。

---

## 理由

### ① 前処理を統一できる

例えば

- Trim
- 全角→半角
- 大文字小文字統一

を行う場合

両方に同じ処理を適用できる。

---

### ② 元データを壊さない

```
商品コード
```

はそのまま残る。

結合専用列だけ加工する。

---

### ③ 保守性が高い

後から見ても

```
key_商品コード
```

は

「結合用」

と一目でわかる。

---

## 例外

マスタが

- 完全固定
- 変更されない
- 正規化済み

なら片側だけでも動く。

しかし運用としては両側が推奨。

## 選択肢

### パターンA

```
商品コード商品名分類カテゴリー
```

---

### パターンB

Excelマスタはシステム名称

```
コード名称1分類2分類1
```

Power Queryで変更

---

## 推奨

### パターンB

つまり

```
マスタ原本=システム名称
```

にする。

---

## 理由

### 原本が何か明確

システムと同じになる。

---

### 将来の保守が楽

システム変更時に対応しやすい。

---

### 他用途に流用しやすい

別レポート

別分析

別部署

でも利用可能。

---

### ステップ2

---

### ステップ3

key列を削除。

---

### ステップ4

後で再びマージが必要になった。

---

## この時どうする？

結論

### ケースによる

---

# ケース①

同じ粒度で再結合

例

商品別集計

|商品コード|売上|
|---|---|
|001|100|
|002|200|

再び商品マスタ結合。

---

### 推奨

グループ化時に残す。

---

つまり

```
key_商品コード
```

を消さない。

---

## 理由

再生成不要。

---

# ケース②

粒度が変わった

例

月別集計

|月|売上|
|---|---|
|2026-06|1000|

この場合

```
key_商品コード
```

は意味を失う。

---

### 推奨

新しいキーを作る。

例えば

```
key_年月
```

や

```
key_得意先_年月
```

など。

---

## 考え方

重要なのは

```
元のkeyを残す
```

ではない。

---

重要なのは

```
現在のテーブル粒度で何と結合するのか
```

である。

# 4. 実務でおすすめの設計

あなたのPower Queryの作り方を踏まえると、

## 基本ルール

### Raw層

```
システムデータ
```

---

### Standard層

ここで

```

```

へ統一。

---

### マージ用


最終的に

```

```

↓

↓
