# トークン消費量を抑えるための基礎的なスレッド管理

通常Chatで完結する相談は通常Chatで扱うと、Work／Codex側の利用量を抑えやすい。知識質問、考えの整理、文章のたたき台、軽い比較や調査は通常Chatで足りることが多い。一方、Obsidianの確認・編集、ファイル作成、資料制作、コード、複数工程の実作業はWork／Codexに向く。

Work環境では、プロジェクト指示、`AGENTS.md`、必要な背景資料を繰り返し読み、必要に応じてファイルとツールも確認する。その準備は、単純な質問には余分な利用量になることがある。ただし、最終的にWorkで制作・編集することが決まっている案件は、最初からWorkで相談した方が、後から文脈を移し直すより効率的な場合もある。

ChatからWorkへ移す場合は、会話全文を渡すのではなく、次の情報を圧縮した引き継ぎプロンプトを使う。

- 目的と背景
- 決定事項と成功条件
- 対象ファイル・参照資料
- 制約、変更禁止範囲、未決事項
- Workに実行してほしい作業と、実装前に確認してほしいこと

スレッドを分ける基準は、機械的に細分化することではない。無関係な目的・成果物・対象ファイルが混ざると、過去の文脈やツール情報が積み重なり、利用量と判断の負担が増えやすい。しかし、同じ成果物に関係する複数のノートや工程は、共通する文脈を活かせる範囲で一つのスレッドにまとめてよい。

| 状況 | 基本方針 |
| --- | --- |
| 同じ成果物への追加質問・修正 | 同じスレッドを継続する |
| 目的や対象ファイルが変わる | 新しいスレッドを検討する |
| 複数ノートを一つの判断単位として比較する | 文脈を共有して一括で扱う |
| 一問一答の細かい相談 | 通常Chatを優先する |
| ファイル作成・調査・編集が必要 | Work／Codexを使う |
